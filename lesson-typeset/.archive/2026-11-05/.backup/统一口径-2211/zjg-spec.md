# 逐字稿版式规范（课件对照版）

逐字稿不是给人「读」的文章，是站着讲课、对照投屏念的工作稿。所有版式只服务一个目的：
**抬眼就能确认「现在讲的是课件第几页、这一句该怎么说」。**

---

## 1. 页面

| 项 | 值 |
|---|---|
| 纸张 | A4，21 × 29.7cm |
| 页边距 | 上 2.5 / 下 2.5 / 左 2.8 / 右 2.8cm |
| 页眉距 | 1.5cm |
| 页脚距 | 1.75cm |
| 页眉 | 五号宋体居中，写「课题 · 第 X 课时 逐字稿」 |
| 页脚 | **留空，不排页码** |

**为什么不排页码**：逐字稿的页面位置由课件截图承担。老师翻纸时的锚点是「这一块是第 5 页的图」，
而不是「这是第 3 张纸」。数字页码在投屏对稿时没有意义，反而占掉一行视觉。

---

## 2. 块结构

**一页课件 = 一段对照**。段是内容的单位，不是表格的单位——**整份文档只有一张表**，
段按顺序往同一张表里追加行，段与段之间只隔一条 `insideH` 分隔线。

一段占 2 行还是 3 行，取决于排列方式，**每次排版前问用户选一种**：

| | 左右排列 `side` | 上下排列 `stack` |
|---|---|---|
| 每段行数 | 2 | 3 |
| 截图 | 5.4cm，靠左 | 11.0cm，居中 |
| 稿子 | 8.0cm 列，1.38 倍行距 | 满宽 14.4cm |
| 15 页课件实测 | 9 页 A4 | 11 页 A4 |

### 2.1 左右排列（默认）

```
┌──────────────────────────────────────────────────┐
│ 第 3 页 · 承接任务：开启下篇探秘      3:30—4:00  │ ← 表头行（跨列）
├────────────────┬─────────────────────────────────┤
│                │ 〔操作〕翻到第 3 页。            │
│   [课件截图]    │ 师：上节课，我们领略了……        │
│   5.4cm 宽      │ 师：同样是俑，为什么每一张脸…    │
├────────────────┴─────────────────────────────────┤ ← insideH 0.5pt 灰
│ 第 4 页 · 大秦兵团档案卡（一）        4:00—8:00  │
├────────────────┬─────────────────────────────────┤
│   [课件截图]    │ 师：先看两位"主角"……            │
└────────────────┴─────────────────────────────────┘
```

### 2.2 上下排列

```
┌──────────────────────────────────────────────────┐
│ 第 3 页 · 承接任务：开启下篇探秘      3:30—4:00  │ ← 表头行
├──────────────────────────────────────────────────┤
│            [课件截图 11cm 居中]                   │ ← 图行（三列合并）
├──────────────────────────────────────────────────┤ ← insideH 0.5pt 灰
│ 〔操作〕翻到第 3 页。                             │ ← 文行（三列合并，满宽）
│ 师：上节课，我们领略了……                         │
└──────────────────────────────────────────────────┘
```

**为什么上下排列的图放大到 11cm 而不是占满 14.4cm**：实测同份 15 页课件，
12cm 排 12 页、11cm 排 11 页、10.5cm 排 11 页但末页更空。11cm 是页数与画面尺寸的平衡点，
再宽就因图片行不可拆而频繁把整段挤到下一页。

**为什么不能一段建一个表**：每段一个表时，Word 强制在两表之间插段落，段间就出现空隙 +
两条并排的框线，整页看着"断成好几截"。合成一张表后，段间只剩一条线，表格左右边框贯通到底页。

整表**不能设 `tblHeader`**：它只对表格开头几行生效，会把第一段的表头重复到后面每一页。
跨页续排时靠「下一段的表头行」本身来定位页码即可。

列网格两种排列通用，取 **6.4 / 4.0 / 4.0 cm**（合计 14.4cm，左右各缩进 0.5cm）：

- 表头行：前两列合并（10.4cm）放「第 N 页 · 环节名」，第三列（4.0cm）放时间并右对齐
- 左右排列的主体行：第一列（6.4cm）放截图，后两列合并（8.0cm）放稿子
- 上下排列的图行／文行：三列全合并（14.4cm）

表头行与主体行合并位置不同，但总宽一致，所以时间能精确贴到表格右边界。

> **不要用制表位把时间推到右边。** 制表位在合并单元格里的基准各渲染器算法不一致，
> LibreOffice 实测偏约 1cm，Word 打开又是另一个位置。用列宽解决，跨平台稳定。

### 框线怎么画

外框（上／下／左／右，0.5pt 灰 `808080`）和**块间分隔线**（`insideH`，0.5pt 灰）都写在
**表格级** `tblBorders` 上，`insideV` 设 `none`；单元格只补两条自己独有的线：

| 位置 | 线 |
|---|---|
| 表头行两个格子 | 只加 `bottom`，0.75pt 纯黑（表头分隔线） |
| 左右排列的截图格 | 只加 `right`，0.5pt 浅灰 `C8C8C8`（图文分隔线） |
| 上下排列的图行 | 不加任何线，图下那条由 `insideH` 与文行隔开 |

**其余三边一律不要写 `val="none"`。** 单元格边框优先级高于表格边框，写一个 `none`
就把外框那条线挖掉——文档导入腾讯文档 / Word 后表现为「表格下半截没有框、看着没封口」，
LibreOffice 里却可能正常，很容易漏检。代码里统一用 `_set_cell_borders()`，它只生成
传入的边。

## 3. 字号与字体

| 元素 | 字体字号 | 颜色 |
|---|---|---|
| 表头「第 N 页 · 环节名」 | 五号黑体 | 纯黑 |
| 时间区间 | 小五宋体 | 60% 灰 `595959` |
| 〔操作〕提示 | 五号楷体**加粗** | 65% 灰 `595959` |
| 〔学生可能说〕 | 五号楷体 | 40% 灰 `909090` |
| 师： | 五号宋体 | 纯黑 |
| 生（齐）： | 五号宋体**加粗** | 纯黑 |
| 使用说明、正文段落 | 五号宋体，1.5 倍行距，首行缩进 2 字符 | 纯黑 |
| 课时大标题 | 小四黑体加粗，居中 | 纯黑 |
| 文档标题 | 小三黑体加粗，居中 | 纯黑 |
| 副标题（年级·课时·时长） | 小五宋体，居中 | 25% 灰 `404040` |

块内行距 **1.38 倍**。行距是逐字稿最敏感的参数：1.5 倍会让每块多出半行，
15 页课件要多出一到两页纸；1.25 倍以下则念的时候容易串行。

**为什么「师：」和「生：」要用不同字体**：站在讲台上低头扫一眼，靠字体形状比靠读字快。
师语是宋体（正文感，可以顺口念），行动提示是楷体加粗（余光就能扫到），
预判是浅灰楷体（明确告诉眼睛「这不是必须说的话，别照念」）。

## 4. 图片

| 项 | 值 |
|---|---|
| 来源 | 课件 pptx 逐页渲染，`ppt2png.py` |
| 格式 | JPG，质量 88（PNG 会让整份文档到 60MB+） |
| 分辨率 | 110 dpi 渲染 ≈ 1900px 宽，插入 5.4cm 后仍有 900 dpi |
| 显示宽度 | 左右排列 5.4cm（高 3.04cm）；上下排列 11.0cm（高 6.19cm） |
| 水平位置 | 左右排列靠左；上下排列居中，左右留白相等 |
| 边框 | 不加单独边框，靠块外框收边 |
| 垂直对齐 | 与文字顶端对齐（左右排列对齐右列文字，上下排列图在前） |

渲染一次即可反复使用，命名 `p01.jpg … p15.jpg`，放在该课的 `assets/` 下。

## 5. 分页策略

整表允许跨页断行，**主体行一律不设 `cantSplit`**。

实测：块块不拆时，15 页课件排到 13 页 A4——一个 12cm 的块遇到只剩 5cm 的页尾就整块下移，
一页浪费近半。允许断行后回到 9 页。

规则：

- **表头行 `cantSplit`**，且表头格的段落设 `keepNext`，绝不单独落在页末。
- **文字允许续排**：左右排列的主体行、上下排列的文行都不设 `cantSplit`，
  文字自然续排到下一页，截图留在起始页。
- 上下排列的**图行设 `cantSplit`**（图片本身不能拆），代价是页尾剩余高度不足 7cm 时整段下移，
  页尾会留白——这是上下排列比左右排列多 2 页的主因，属正常。
- 跨页后不重复表头（整表设 `tblHeader` 会重复第一段的表头），读者靠下一段的表头行定位。

词表里不再有 `SPLIT_ABOVE_CM` 这类阈值——分页完全交给排版器。

## 6. 保留原样的东西

- **`〔〕` 提示符是标签，不是列表符号**。不要改成 `·`、`□`，也不要改成阿拉伯数字序号。
  它标记的是「这一行是做什么的」，和「第几条」无关。
- 稿子里的「一、二、三」属于使用说明的条目，保持原样，不转成 `1. 2. 3.`。
- 方括号里老师自己写的备注（如「或课前把录音插入该页」）一字不改。

除以上，正文其他位置**只允许阿拉伯数字序号**，出现 `- ` 或 `·` 一律转成 `1.`。

## 7. 检查清单

```bash
# 1. 页数、有无页码
python3 -c "
import pymupdf; d=pymupdf.open('out.pdf')
print('页数', d.page_count)
print('末页有数字页码?', d[-1].get_text().strip().endswith(tuple('0123456789')))
"

# 2. 结构完整性（整表应为 1 张，行数 = 课件页数 × 2 或 × 3）
python3 -c "
import zipfile
z = zipfile.ZipFile('out.docx')
x = z.read('word/document.xml').decode()
# 页码字段在 footer 部件里，document.xml 里永远是 0，别查错地方
f = sum(z.read(n).decode().count('PAGE') for n in z.namelist() if 'footer' in n)
print('表格数', x.count('<w:tbl>'), '| 行数', x.count('<w:tr>'),
      '| 图', x.count('<pic:pic>'), '| 页码字段', f,
      '| 底纹', x.count('<w:shd'))
"
```

- [ ] **表格数 = 1**（中途有课时标题等段落才会 > 1）
- [ ] 行数 = 课件页数 × 2（左右排列）或 × 3（上下排列）
- [ ] 段与段之间只有一条分隔线，没有空隙和并排双线
- [ ] 页脚无页码，文档里搜不到 `PAGE` 字段
- [ ] 表头时间贴右边界，不是浮在中间
- [ ] 表格左右边框从首页贯通到末页
- [ ] 上下排列的截图水平居中，左右留白相等
- [ ] 所有表格无底纹填充
- [ ] 稿子段落零丢失（与源文逐段比对）

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 表头单独在页末、内容在下一页 | 表头段落的 `keepNext` 丢了。合并单元格不影响，但要给表头格内段落显式加 |
| 时间没贴到右边 | 用了制表位。改用 6.4/4.0/4.0 三列网格，让时间独占末列右对齐 |
| 续页只有文字、左边空一大片 | 左右排列的正常现象。图只出现在段的第一页，左列续排留白正好可以写批注 |
| 文档 60MB 打不开 | 图用了 PNG。改 JPG 质量 88，体积降到 1/10 |
| 一页只放得下一个段 | 行距是否被改回 1.5；上下排列则看 `IMG_W_STACK_CM` 是否被调到 12 以上 |
| 图片显示不全或被裁 | 左右排列列宽 6.4cm 装 5.4cm 图，若改成 6.0cm 以上会顶到右边界 |
| 上下排列页尾大片留白 | 图行 `cantSplit` 导致整段下移。缩图宽能改善，别去允许图片行拆分 |
| 换了排列方式后页数变化 | 正常，左右约 9 页、上下约 11 页（15 页课件）。回复里要把页数说清楚 |
