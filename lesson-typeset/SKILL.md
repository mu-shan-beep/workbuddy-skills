# 课件文档统一排版（lesson-typeset）

**一份规范、一支入口命令、一套命名规则。** 版式细节只写在规范里，本文件只保留路由与不可丢的口径。

## 执行纪律（与教案包主流程同一套，不得另立）

排版同样按全任务口径执行，属状态机适用范围内（不论任务大小），按 `teaching-ppt-workflow/SKILL.md`「全任务执行状态机与硬门禁」执行，禁止跳级（状态定义只有一个归属，此处不复制全文）：
`LOCK → AUDIT → EXECUTE → VERIFY → DONE`

排版侧的硬含义，缺一项即不算完成：

| 状态 | 排版侧的必做动作 |
| :-- | :-- |
| LOCK | 锁定唯一的源稿与素材范围，声明本次不动的文件 |
| AUDIT | 先跑素材预检（§1.0）并报状态；声明要改哪些文件 |
| EXECUTE | 只排已审内容；**不顺手改源稿文字**、不扩范围 |
| VERIFY | 解包断言实测：0 残渣／0 `tblHeader`／图数＝页数／字符多重集与源稿一致 |
| DONE | 验收输出贴出后才可报「已完成」；**不得用「已自检」代替实测物证** |

规则改动前后必跑体检：`python3 ~/.workbuddy/skills/teaching-ppt-workflow/scripts/rule_audit.py`（FAIL 先修）；治理细则、单点定义表与权限边界见 `teaching-ppt-workflow/references/self-maintenance.md`，本技能不另立治理流程。

| 唯一权威 | 路径 |
|---|---|
| 规范（唯一） | `references/unified-spec.md` |
| 入口（有源稿） | `scripts/typeset.py` |
| 入口（无源稿·就地改 Word） | `scripts/retrofit_docx.py` |
| **开工前素材预检（硬性第一步）** | `scripts/check_assets.py` |
| 内部渲染模块 | `scripts/renderers/`（禁止直接调用） |
| 课件导出工具 | `scripts/ppt2png.py`（历史工具，**不得作为交付链路素材来源**） |
| 历史版本 | git 提交历史（技能目录不保留旧版副本） |

## 1. 开工前（第 0 步为硬性门禁，禁止跳过）

### 0. 【素材齐备预检与主动提醒｜2026-11-13 用户硬性要求，最高优先级】

**用户会忘记提供素材，助手必须主动提醒，不能等用户想起来，也不能等排版报错才说。**

任何排版／交付整理委托的**第一个动作**，早于读规范、早于跑 `typeset.py`，必须先执行：

```bash
python3 ~/.workbuddy/skills/lesson-typeset/scripts/check_assets.py --root "<课题目录>"
```

- 脚本只读，输出齐备状态表与缺失清单；退出码 `0`＝齐备，`3`＝有缺失。
- **必须在聊天中主动把结果报给用户**：齐备也要报「已齐备」，缺失则逐项列明并**明确请求用户提供**、明确说明「已暂停排版、未生成也未覆盖任何成品」。
- 退出码 3 时**立即停止**，不排版、不 commit、不自行渲染／绘制素材顶替；等用户提供文件后重新跑预检，齐备再继续。
- 即使用户没提素材、即使只排其中一份文档，也必须跑这一次预检并提醒 —— 这是**助手的主动义务，不是用户的要求**。
- 进入下游资料阶段（写逐字稿、制作笔记、学习清单、整理交付文件）时同样顺带提醒一次素材清单，别等到最后一步才说。
- 判定逻辑单点在 `typeset.py::asset_status()`；`check_assets.py` 与 `preflight_assets()` 共用，禁止另写第二份口径。缺素材时 `typeset.py` 亦会以退出码 2 兜底阻断（`⛔ 排版已暂停`），双保险。

1. 读 `references/unified-spec.md`：第 1 章常量、第 2.4 节表格判据、第 2.5／2.5.1 节素材来源硬门禁、第 3 章参数档、第 4 章命名（含 4.5 无源稿就地改造）、第 5 章校验。版式数字不从别处找，也不拿另一类文档的数字套用。
2. 三条硬约束：基础层四类共用；构件按需启用；只调格式不改文字（成品字符多重集与源稿一致，自动表头除外）。
3. 改**版式参数**仍走「先出效果 → 用户确认 → 再写进技能」。此条只约束参数；交付落地按第 2 节直接执行。

## 2. 入口命令（按有无源稿分流）

```bash
T=~/.workbuddy/skills/lesson-typeset/scripts/typeset.py
ROOT="<课题目录绝对路径>"

python3 "$T" --root "$ROOT" \
  --input "牛和鹅-教学设计-源.md" \
  --header "20 牛和鹅" --mode commit
```

| 参数 | 行为 |
|---|---|
| `--root` / `--input` | 课题根目录／源稿路径（相对 root 或绝对路径） |
| `--profile` / `--header` | 均可省略，分别由源稿名、课文标题推导 |
| `--mode` | `commit`＝交付（落课题根目录下 `交付文件/`、原子覆盖、旧版进废纸篓）；`preview`＝引擎缺省，只写 `/tmp` 自校验，**不是交付状态** |
| `--images` / `--no-images` | 显式指定截图目录／明确跳过配图 |
| `--courseware-pdf` | 用户提供的课件 PDF（逐字稿预览图唯一合法来源；缺失即暂停排版） |
| `--dry-run` | 只打印命名推导与配图探测 |

- **交付必须显式 `--mode commit`**：本轮结束前正式成品须已在 `交付文件/`；不停在 `/tmp` 预览、不等「确认落地」再补一步。预览产物用完即删。
- **不接受 `--output`**，成品名由源稿名推导并自动校验；交付目录由引擎 `output_folder()` 统一决定，不手填。
- 要调整就地改课题根目录 `<课文>-<类型>-源.md` 再重排覆盖，不建副本、不建预览版、不来回征询；只有判断不了风险的覆盖／删除／大改才先问用户。

### 2.2 无源稿课题：直接在原来的 Word 上改（规范 4.5）

用户口径：「缺少源稿的全部在 word 文档上改」。`交付文件/` 已有成品、课题根目录没有对应 `-源.md` 时，**不要求用户补 md、不反向抽源稿**，以既有 docx 为唯一载体就地改造。
**素材齐备预检同样适用于本路径**：动手前仍须跑 §1.0 的 `check_assets.py` 并主动提醒用户；若该路径会补逐字稿配图，缺课件 PDF 一样暂停、等提供后再落地。

```bash
T=~/.workbuddy/skills/lesson-typeset/scripts/retrofit_docx.py
python3 "$T" --root "<课题目录>" --header "19 秦兵马俑" --all --check  # 先自校验
python3 "$T" --root "<课题目录>" --header "19 秦兵马俑" --all          # 直接落地
python3 "$T" --root "<课题目录>" --header "17 长城" --file "长城-教学设计.docx"
```

- `--all` 只挑**无规范源稿**的 docx；有源稿但旧版式、重排会丢板书图的，用 `--file` 单独指定。
- 只调格式、不改文字：落地前全文逐字比对，不一致即放弃；页眉页脚／字号／页边距／字族全部复用引擎，不另写第二份常量。
- 逐字稿按页补 `pNN.jpg`，找不到素材必须告警；已有配图不重复插（幂等）。落地复用 `typeset.commit()`，旧版进废纸篓、原子覆盖原路径。
- 两条路径不混用；有源稿的课题仍走上一节。

## 3. 不可丢的口径

1. **命名**：`<课文标题>[-<课时段>]-<内容类型>.<扩展名>`；标题不带课文编号数字，课时段用中文数字；禁止状态词、版本号、空格、下划线、竖线。从可画／PPT 导出的课件收进包时按同一骨架改名（`mv` 改名、不复制），改完核一遍 pptx 页数＝同名 pdf 页数；只改本地名，不动云端作品名。完整词表与防副本规则见规范第 4 章。
2. **表格**：只解决对齐，不负责装饰。仅四类可建表（二维列对齐／作答格子／页眉分区／板书图版），其余一律段落；图版与插图的区分见规范 2.4。
3. **配图**：唯一口径见本文件 **§1.0 开工前素材齐备预检**（执行入口）与规范 2.5／2.5.1（技术口径）；此处不复制。
4. **防副本**：同课题同类型只有一个成品，覆盖前旧版进系统废纸篓；不建 `versions/`、日期目录、备份包。
5. **交付形态**：只交 Word，不转 PDF、不出总览图。
6. **交付文件包与副本清理（2026-11-09 立，2026-11-10 用户加严）**：排版好的文件统一放进项目目录下新建的 **`交付文件/`** 文件夹——**所有类型都进包，含制作笔记**；`交付文件/` 是唯一成品出处。收包之后**包外副本必须清掉**：根目录残留的旧落位成品，一律用 `/usr/bin/trash` 移入系统废纸篓（可恢复），根目录只留 `交付文件/`、`<课文>-<类型>-源.md`、教材 PDF 与 `assets/`。同时清理**未排版版本**（旧命名稿、未排版的原始文档）：先列清单再清。`.workbuddy/` 仅存记忆、日志与审计记录，**不放大源稿或副本**；源稿已落课题根目录。引擎 `output_folder()` 统一指向 `交付文件/`，commit 后由 `sweep_copies()` 自动清理包外同名副本。**整理只限当前课题**：其他课题命名不合规也只列清单、不擅自动手（2026-11-10 用户明确）。
7. **无源稿以 Word 为准（2026-11-10 用户口径）**：缺规范源稿的课题不补 md、不要求用户交源稿，直接在既有 Word 上就地改造（第 2.2 节）；后续补写内容同样直接在 Word 上进行。**用户明确要求「全部／整库」时按整库执行**，本条优先于第 6 条的「只限当前课题」限制。

## 4. 排版后

按规范第 5 章逐项校验（文字零增减、命名、常量与参数档、表格用途、分页、逐字稿内嵌图片数与同类台词样式唯一）。直接打开 docx 目视版式再比对页数，用 `present_files` 打开 **`交付文件/` 里这一次排的正式成品**；回复只讲这一份：页数、版式、做过的判断、文字核验结果。不要顺手排同课其他文档。

最后列一次未排版版本清单并清理（第 3 节第 6 条），在回复里说明清了什么、保留了什么。

## 5. 排障速查

| 现象 | 处理 |
|---|---|
| 单行字段被排成带框线表格 | 判据漏判，查 `table_v32.py::needs_table()` |
| 板书图像独立插图、与上方表格不对齐 | 标为图版回表格，标题去下边线避免双线 |
| 表格比标题色块左突约 3mm | 表缺 `tblInd=170` |
| Usage notes | 结构仅限「基本信息、设计思路、课前准备、分页说明」四部分，严禁擅自增设非标章节 |
| 关键图片素材缺失 | **暂停排版**，列明缺失项并询问用户，等提供后再排；见规范 2.5／2.5.1 |
| 逐字稿缺图／某页台词样式不一致 | 缺图先查用户是否提供课件 PDF（未提供即暂停，不自行渲染）；样式不一致改 `style_of()` 正则，不加白名单，也不改源稿 |
| `row.cells` 误判四列比例 | python-docx 按 `tblGrid` 展开，要数实际 `w:tc` 的 `gridSpan` |
| 成品仍落在课题根目录 | 引擎 `output_folder()` 未指向 `交付文件/`；commit 应自动把根目录同名旧成品移入废纸篓 |

## 6. 文件索引

- `references/unified-spec.md` — 唯一规范
