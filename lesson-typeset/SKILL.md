# 课件文档排版与交付包整理（lesson-typeset）

**一份规范、一支入口命令、一套命名规则。** 版式细节只写在规范里，本文件只保留路由与不可丢的口径。**交付包整理与网盘落位是第二个主功能，唯一定义在 §3.5。**

本技能处理两类任务：**排版**（明确要求 Word／DOCX 时）与**交付包整理＋网盘落位**（§3.5）。普通 Markdown 撰写与内容检查不激活本技能的排版素材预检。

## 排版核对

先确认源稿和素材范围，按 §1.0 跑素材预检并报告缺项。**排版前按 §3.10 逐段分辨内容取舍（可排／需删／拿不准须询问），禁止原样全排源稿**。按审定稿排版，源稿文字调整按本次授权处理。排版后用实际 Word 成品核对隐藏残渣、重复标题行、图片张数以及正文与源稿的字符多重集（一致性比对含 §3.10 例外，口径见规范第 5 章，不在此另立）。完成结论依据实际检查结果。

规则改动前后必跑体检：`python3 ~/.workbuddy/skills/teaching-ppt-workflow/scripts/rule_audit.py`（FAIL 先修）；治理细则、单点定义表与权限边界见 `teaching-ppt-workflow/references/self-maintenance.md`，本技能不另立治理流程。

| 唯一权威 | 路径 |
|---|---|
| 规范（唯一） | `references/unified-spec.md` |
| 入口（有源稿） | `scripts/typeset.py` |
| 入口（无源稿·就地改 Word） | `scripts/retrofit_docx.py` |
| **开工前素材预检（硬性第一步）** | `scripts/check_assets.py` |
| 内部渲染模块 | `scripts/renderers/`（禁止直接调用） |
| 课件导出工具 | `scripts/ppt2png.py`（历史工具，**不得作为交付链路素材来源**） |
| 历史版本 | git 提交历史（技能目录不保留旧版副本） |

## 1. 开工前（第 0 步为硬性门禁，禁止跳过）

### 0. 【素材齐备预检与主动提醒｜2026-11-13 用户硬性要求，最高优先级】

**用户会忘记提供素材，助手必须主动提醒，不能等用户想起来，也不能等排版报错才说。**

仅明确委托 **Word 排版**时的**第一个动作**，早于读规范、早于跑 `typeset.py`，必须先执行（**纯交付包整理不跑本预检**：整理只核五类是否到齐，见 §3.5，不索要板书图或课件 PDF）：

```bash
python3 ~/.workbuddy/skills/lesson-typeset/scripts/check_assets.py --root "<课题目录>"
```

- 脚本只读，输出齐备状态表与缺失清单；退出码 `0`＝齐备，`3`＝有缺失。
- **必须在聊天中主动把结果报给用户**：齐备也要报「已齐备」，缺失则逐项列明并**明确请求用户提供**、明确说明「已暂停排版、未生成也未覆盖任何成品」。
- 退出码 3 时**立即停止**，不排版、不 commit、不自行渲染／绘制素材顶替；等用户提供文件后重新跑预检，齐备再继续。
- 即使用户没提素材、即使只排其中一份文档，也必须跑这一次预检并提醒 —— 这是**助手的主动义务，不是用户的要求**。
- 进入交付包整理阶段时同样顺带提醒一次素材清单（逐字稿配图缺课件 PDF 会影响成品完整性），别等到打包最后一步才说。
- 判定逻辑单点在 `typeset.py::asset_status()`；`check_assets.py` 与 `preflight_assets()` 共用，禁止另写第二份口径。缺素材时 `typeset.py` 亦会以退出码 2 兜底阻断（`⛔ 排版已暂停`），双保险。

1. 读 `references/unified-spec.md`：第 1 章常量、第 2.4 节表格判据、第 2.5／2.5.1 节素材来源硬门禁、第 3 章参数档、第 4 章命名（含 4.5 无源稿就地改造）、第 5 章校验。版式数字不从别处找，也不拿另一类文档的数字套用。
2. 三条硬约束：基础层三类共用；构件按需启用；只调格式不改文字。**一致性口径**：成品字符多重集与源稿一致、自动表头除外；**例外——按 §3.10 判定为「需删」的非交付内容（制作痕迹／AI 味／自检说明等）不排入成品，此类删除合法、不计入一致性比对**（例外的唯一定义见 `references/unified-spec.md` 第 5 章，本条只引用不重写，与 §3.10 不冲突）。
3. 改**版式参数**仍走「先出效果 → 用户确认 → 再写进技能」。此条只约束参数；交付落地按第 2 节直接执行。

## 2. 入口命令（按有无源稿分流）

```bash
T=~/.workbuddy/skills/lesson-typeset/scripts/typeset.py
ROOT="<课题目录绝对路径>"

python3 "$T" --root "$ROOT" \
  --input "源稿/牛和鹅-教学设计-源.md" \
  --header "20 牛和鹅" --mode commit
```

| 参数 | 行为 |
|---|---|
| `--root` / `--input` | 课题根目录／源稿路径（相对 root 或绝对路径） |
| `--profile` / `--header` | 均可省略，分别由源稿名、课文标题推导 |
| `--mode` | `commit`＝交付（落课题根目录下 `交付文件/`、原子覆盖、旧版进废纸篓）；`preview`＝引擎缺省，只写 `/tmp` 自校验，**不是交付状态** |
| `--images` / `--no-images` | 显式指定截图目录／明确跳过配图 |
| `--courseware-pdf` | 用户提供的课件 PDF（逐字稿预览图唯一合法来源；缺失即暂停排版） |
| `--dry-run` | 只打印命名推导与配图探测 |

- **交付必须显式 `--mode commit`**：本轮结束前正式成品须已在 `交付文件/`；不停在 `/tmp` 预览、不等「确认落地」再补一步。预览产物用完即删。
- **不接受 `--output`**，成品名由源稿名推导并自动校验；交付目录由引擎 `output_folder()` 统一决定，不手填。
- 要调整就地改 `源稿/<课文>-<类型>-源.md`（旧课题仍在根目录时照常识别）再重排覆盖，不建副本、不建预览版、不来回征询；只有判断不了风险的覆盖／删除／大改才先问用户。

### 2.2 无源稿课题：直接在原来的 Word 上改（规范 4.5）

用户口径：「缺少源稿的全部在 word 文档上改」。`交付文件/` 已有成品、`源稿/` 与课题根目录均无对应 `-源.md` 时，**不要求用户补 md、不反向抽源稿**，以既有 docx 为唯一载体就地改造。
**素材齐备预检同样适用于本路径**：动手前仍须跑 §1.0 的 `check_assets.py` 并主动提醒用户；若该路径会补逐字稿配图，缺课件 PDF 一样暂停、等提供后再落地。

```bash
T=~/.workbuddy/skills/lesson-typeset/scripts/retrofit_docx.py
python3 "$T" --root "<课题目录>" --header "19 秦兵马俑" --all --check  # 先自校验
python3 "$T" --root "<课题目录>" --header "19 秦兵马俑" --all          # 直接落地
python3 "$T" --root "<课题目录>" --header "17 长城" --file "长城-教学设计.docx"
```

- `--all` 只挑**无规范源稿**的 docx；有源稿但旧版式、重排会丢板书图的，用 `--file` 单独指定。
- 只调格式、不改文字：落地前全文逐字比对，不一致即放弃；页眉页脚／字号／页边距／字族全部复用引擎，不另写第二份常量。
- 逐字稿按页补 `pNN.jpg`，找不到素材必须告警；已有配图不重复插（幂等）。落地复用 `typeset.commit()`，旧版进废纸篓、原子覆盖原路径。
- 两条路径不混用；有源稿的课题仍走上一节。

## 3. 不可丢的口径

1. **命名**：`<课文标题>[-<课时段>]-<内容类型>.<扩展名>`；标题不带课文编号数字，课时段用中文数字；禁止状态词、版本号、空格、下划线、竖线。从可画／PPT 导出的课件收进包时按同一骨架改名（`mv` 改名、不复制），改完核一遍 pptx 页数＝同名 pdf 页数；只改本地名，不动云端作品名。完整词表与防副本规则见规范第 4 章。
2. **表格**：只解决对齐，不负责装饰。仅四类可建表（二维列对齐／作答格子／页眉分区／板书图版），其余一律段落；图版与插图的区分见规范 2.4。
3. **配图**：唯一口径见本文件 **§1.0 开工前素材齐备预检**（执行入口）与规范 2.5／2.5.1（技术口径）；此处不复制。
4. **逐字稿「使用说明」源稿留、成品删（2026-11-19 用户裁定）**：源稿 md 的 `## 使用说明` 四段照常写、照常留（撰写契约与机检依据）；排版成品 docx **一律不输出该段**——`zjg_typeset.py::parse` 自动跳过标题及正文。成品出现「使用说明」字样或空标题即缺陷，须重排。技术口径见规范 2.4.1。
5. **防副本**：同课题同类型只有一个成品，覆盖前旧版进系统废纸篓；不建 `versions/`、日期目录、备份包。
6. **交付形态**：只交 Word，不转 PDF、不出总览图。
7. **交付落位归本技能（2026-11-09 立，2026-11-24 用户裁定重划）**：分两层，都在本技能内完成，不外包给制作技能。**单份层**——本次排版的这一份 docx 由引擎 `output_folder()` 直接落进课题根目录的 **`交付文件/`**，commit 后 `sweep_copies()` 清理该份的包外同名副本，旧版用 `/usr/bin/trash` 移入系统废纸篓（可恢复），对应源稿归 `源稿/`（见第 9 条）。**整包层**——五类齐全核对、`交付文件/` 目录口径、跨类别旧稿整理、网盘落位，见 §3.5（唯一定义）。`交付文件/` 是唯一成品出处，所有类型平铺进去，不再套子目录。**整理只限当前课题**：其他课题命名不合规也只列清单、不擅自动手（2026-11-10 用户明确）。
8. **无源稿以 Word 为准（2026-11-10 用户口径）**：缺规范源稿的课题不补 md、不要求用户交源稿，直接在既有 Word 上就地改造（第 2.2 节）；后续补写内容同样直接在 Word 上进行。**用户明确要求「全部／整库」时按整库执行**，本条优先于第 7 条的「整理只限当前课题」限制。
9. **源稿收纳归位（2026-11-24 用户明确指令，最高；与 2026-11-16 源稿入 `源稿/` 新规一致）**：每次排版并整理交付文件后，必须把本次对应的源文件收纳到课题根目录的 **`源稿/`** 文件夹，命名 `<课文标题>[-<课时段>]-<内容类型>-源.md`（同 4.1 骨架加 `-源` 后缀，同类型只一份）。**严禁散落**：根目录、`.workbuddy/`、`assets/`、`交付文件/` 均不得留 `-源.md` 或其他源稿 md；发现散落用 `mv` 归位（不复制），旧稿／大纲／textClipping 等非交付中间产物用 `/usr/bin/trash` 移入系统废纸篓。排版前若源稿散落，先归位再排（引擎 `asset_status()` 只认 `源稿/` 或根目录下合规命名的 `-教学设计-源.md`，命名不合规会阻断预检）。收口前逐条核验：`源稿/` 清单齐全、命名合规、根目录与 `.workbuddy/` 无散落源稿、板书图与课件 PDF 在 `assets/`、成品全在 `交付文件/`，做到整整齐齐。**整理只限当前课题**（第 7 条同样约束本条）。
10. **排版前内容取舍分辨（2026-11-24 用户明确指令，最高）：排版绝不能原样把源稿整份排进去**。动笔排版前必须逐段分辨源稿，分三类处理：① **可排**——面向客户的纯净交付正文（教案模块、学生任务、台词、清单条目等）；② **需删**——制作痕迹、给 AI 的评分／说明／自检／表态性内容、编写意图、批注、过程稿标记、AI 味残渣（“什么属于制作痕迹”的唯一口径见 `teaching-ppt-workflow/references/lesson-pack.md`「全包源稿纯净化与去 AI 味铁律」，本条只引用不重写；逐字稿「使用说明」源稿留成品删见第 4 条）；③ **拿不准**——**列出具体段落原文向用户询问，得到明确答复再处理，禁止擅自决定排或删**。分辨结论须落在成品校验（规范第 5 章第 10 项）：成品只含第①类，无第②类残留，第③类已问清。**本条只授权“删非交付内容”，不授权改交付正文**——改动交付正文的文字仍须用户明确授权；改版式参数仍走第 1 节第 3 条。

### 3.5 交付包整理与网盘落位（2026-11-24 用户裁定，唯一定义）

用户说「整理交付包」「交付」「上传网盘」「发货」时执行本节；排版完成但整包未整理时同样执行。**本节是交付包整理与网盘落位的唯一定义点**，其他技能只准引用，不另立口径。

**一、五类齐全核对**

1. 按 `teaching-ppt-workflow/references/lesson-pack.md`「交付物清单（五类）」逐类点名核对：① 教学设计 ② 课件（采用形态：可画链接或 pptx）③ 逐字稿 ④ 学习清单 ⑤ 板贴 png（多课时按课时各一份）。清单内容以该处为产品定义，本节只做核对动作，不重写清单。
2. **缺项不阻断整理**：照常完成已到位类别的落位与核对，收尾时逐项列出缺失类别并请用户补充；不默认略过、不把缺项当作已交、不以其他类别顶替、不建占位文件。缺项补齐后重核一次。
3. **类别齐≠内容合规**：必须同时核格式——教学设计／逐字稿／学习清单只认 `.docx`（源稿 md 不进 `交付文件/`），严禁 `.pdf`；`.pdf`、`-源.md`、样稿、大纲、`.DS_Store` 等临时文件出现在 `交付文件/` 即判不合格。**课件形态只认「可画设计链接」或「可编辑 `.pptx`」**；目录内出现其他本地形态（如 `.html`）时，先核商品是否明确承诺该形态，未承诺即判违规并交用户裁定，不得默认保留。曾出现 PDF 被当交付件计数、数量对得上但口径错，该情形不得再判通过。

**二、本地落位**

- `交付文件/` 是唯一成品出处，五类成品**平铺**其中，不再套子目录；命名按第 3 节第 1 条骨架。
- 跨类别旧稿、旧命名版本、旧落位成品，按授权用 `/usr/bin/trash` 移入系统废纸篓（可恢复），严禁 `rm`。采用的 md 是文本成品，不得按「未排版源稿」清走；源稿一律归 `源稿/`。
- 链接类成果（可画设计）保留真实入口，不为落位另做副本。

**三、网盘落位**

- **目录结构**：根 `/小红书原创课件/{科目}/` → `{年级}上册/` → `NNN-课名/`（三位数字 + 半角短横线，如 `001-文言文二则/`）。科目按当次业务确定，当前为「语文」，以后可为数学、英语等，**科目名不固化**；科目层只出现一次。文件直接平铺在课题目录内，不再套子目录。目标目录不存在时自行新建，不必逐次询问。
- **历史不回溯**：已存在的目录一律不改名、不重排、不补改名；现存两位编号、无编号、三位编号并存属既定事实，不作为待修项。
- **只按清单上传**：只传该课已确认的五类交付物；PDF、源稿 md、中间文件、样稿一律不进暂存区与网盘。本地暂存区（`网盘暂存/{科目}/{年级}上册/NNN-课名/`）是上传唯一来源，暂存区里带 PDF 就等于上传带 PDF，传前必须先清。
- **双向核验**：上传前按交付清单核对暂存区，上传后列目录核对文件名与数量，两件事都通过才算完成。只做事后数量核对不算验收。
- **失败即停**：目录层级不对、文件数不符或有违规格式时，停止后续上传并列出问题清单，不边传边改。
- **边界**：建分享、回填发货底稿、改自动发货配置**不在本节**——属 `xhs-lesson-notes/references/fulfillment.md` 的履约段，需另行授权；本节只负责「文件已在网盘正确位置」这一事实。
- **不输出可画链接**：整理、落位、上传与收口报告均不贴可画链接，只写形态类别（可画设计／可编辑 pptx）与到位状态；可画链接仅课件组装阶段可输出，死规唯一定义见 `teaching-ppt-workflow/SKILL.md`。

**四、收口报告**

回复里报三件事：五类逐项状态（到位／缺项）、`交付文件/` 实际清单与清理了什么、网盘落点全路径与文件数核验结果。缺项与未验证项单列，不并入「已完成」。课件为可画设计时，只报形态类别与到位状态，**不贴可画链接**。

## 5. 排障速查

| 现象 | 处理 |
|---|---|
| 单行字段被排成带框线表格 | 判据漏判，查 `table_v32.py::needs_table()` |
| 板书图像独立插图、与上方表格不对齐 | 标为图版回表格，标题去下边线避免双线 |
| 表格比标题色块左突约 3mm | 表缺 `tblInd=170` |
| 辅助对照块(group·bd=thin)数据行边框比表头右突 3mm | `table_v32.py::render_free` 的 `tab`/`text` 段 framed 时 left 须与 `sub` 段齐平（均 0、用 firstLine 补偿）；勿只改源稿列数 |
| Usage notes | 结构仅限「基本信息、设计思路、课前准备、分页说明」四部分，严禁擅自增设非标章节 |
| 关键图片素材缺失 | **暂停排版**，列明缺失项并询问用户，等提供后再排；见规范 2.5／2.5.1 |
| 逐字稿缺图／某页台词样式不一致 | 缺图先查用户是否提供课件 PDF（未提供即暂停，不自行渲染）；样式不一致改 `style_of()` 正则，不加白名单，也不改源稿 |
| `row.cells` 误判四列比例 | python-docx 按 `tblGrid` 展开，要数实际 `w:tc` 的 `gridSpan` |
| 成品仍落在课题根目录 | 引擎 `output_folder()` 未指向 `交付文件/`；commit 应自动把根目录同名旧成品移入废纸篓 |
