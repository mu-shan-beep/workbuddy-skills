# 问题记录与技能优化闭环

每次课件制作都主动记录问题并复盘，用实际经验持续改进技能。用户已明确授权：记录和进化由智能体判断是否需要用户决定，不是每项都确认。课件产物仍逐步确认；常规维护不以此为由反复打断用户。

## 1. 记录与复盘

在当前课件工作目录建立或沿用 `issues.md`，随问题发现更新，记录：

- 编号、日期、课件/模型、阶段、相关工具和版本。
- 现象、触发条件、最小复现、预期与实际，证据文件或用户反馈回合。
- 根因及置信状态：已验证或仍是假设；失败尝试与结果。
- 修复、涉及文件、复查方式、实测结果和未测范围。
- 当前状态、适用条件、可复用防范及其对应技能位置。

知识误差、造型不符、状态同步、操作、设备、离线、性能及确认流程问题均可记录。仅真实发生或用户直接指出的问题才记作已发生；设计猜测标为风险。

发现问题先查项目记录和相关经验，避免重复无效尝试。记录和当前阶段内部修复自主完成；影响已确认的课件结果时，按课件阶段规则重新展示确认。

每次制作结束均复盘。暂停或取消时保存未解决项，不冒称完成。用户明确暂停后不继续制作或维护，遵守暂停范围。已验证的常规改进可以在制作过程中沉淀，不必等到整节课完成。

## 2. 自行处理还是先问用户

| 自行记录、验证并更新 | 先展示具体方案，再等用户决定 |
|---|---|
| 记录现象、失败尝试、证据和用户明确要求 | 改变用户未授权变更的教学目标、范围或最终产物 |
| 合并重复经验、修正失效路径和明显表述错误 | 改变制作阶段、预览要求、确认方式或降低质量门槛 |
| 增加有证据且适用范围明确的防范项和检查入口 | 改变用户已选技术路线、引入显著额外成本或外部服务 |
| 修复与既定意图不符的执行说明，忠实写入用户最新指令 | 修改其他技能、全局设置，或需要额外授权的操作 |
| 为重复确定性操作改进小型辅助脚本，并实际验证 | 证据不足且多个方案会显著改变课件行为的重要选择 |

不因改动行数多就一律询问，也不因只改一行就认定无影响；判断依据是用户意图、影响范围、验证依据和可恢复性。用户已明确给出新要求时可以直接落实，不再次请求批准同一要求。

## 3. 最小有效改进

判断是个案、环境/版本限制还是可复用问题。已有规则未执行时改善入口与检查时机，不再加重复段落。选择最小有效的规则、模板、示例或脚本改动，保留适用条件，避免把一次失败变成普遍禁令。

经验沉淀到 [问题与防范](known-pitfalls.md)，核心流程在入口或对应引用修正；长日志、原图和个案代码留在项目，只保留必要追溯。待验证想法先留在项目记录，不冒充已验证经验。

新增脚本实际运行验证；模型或教学检查用代表性案例验证适用范围。结构校验仅证明文件规范，不证明实际课件效果。没有可复用改进时如实记录，不为更新而更新。

## 4. 应用与恢复

对自行处理的维护：

1. 检查正式技能当前内容与准备修改的依据，避免覆盖并行或无关改动。
2. 在项目工作目录保存可恢复旧版本和改动摘要，实施最小修改。
3. 运行技能结构、内部引用以及涉及脚本或行为的必要检查，核对实际安装内容。
4. 更新失败时保留或恢复原可用版本，不声称成功。完成后简述有意义的变化和未解决项，不逐条索要确认。

需要用户决定的事项：先完成具体修改稿、解释证据与影响，展示后等待确认，再应用用户选定版本。常规问题记录仍可继续，但不执行依赖未获决定的变更。

默认维护范围仅为 `interactive-courseware` 自身。其他技能的问题可以记录并提出修复建议，未经授权不修改它们，也不规避其质量门槛。

## 5. 后续复用

下次开工读取经验库索引，按主题、阶段、建模路线、工具和环境匹配相关条目。环境变化使旧经验失效时验证并修订或归档。保留来源、实际效果和限制，不把一次修好承诺为永不出错。
