# 交互式课件制作（单文件离线版）

交付物永远是**一个 HTML 文件**：双击即开、不联网、不装软件、拷进 U 盘能上课。
内容由学科决定，**引擎结构固定不变**——图层开关、关卡进度、分层提示、提交检测这四件事每次都一样，不要重新设计。

## 一、先过闸门：什么时候不做

动手前书面回答两条，**两条同时为是**才继续：

1. 学生是不是**想不明白它长什么样**？
2. 课上是不是**没法做对照**（静图之间那一段动作是断的）？

任一条为否，直接告诉用户不做，并说明理由。常见误判：

| 误判 | 为什么不做 |
|---|---|
| 「这个知识点很重要」 | 重要不等于抽象，讲得清的不用做 |
| 「做成动画好看」 | 好看是副产品，不是立项理由 |
| 「可以放很多知识点」 | 塞得多说明没想清楚核心难点 |
| 「师生都觉得难」 | 难在记忆量而非空间关系的，做课件无效 |

人物传记、议论文、语法课通常过不了闸门——它们没有「长什么样」的对象。这类需求只迁移**任务链与分层提示**机制（见 `references/subject-matrix.md`），不做 3D。

## 二、七阶段

| 阶段 | 动作 | 卡点（不通过就退回） |
|---|---|---|
| 0 选题闸门 | 回答上面两条 | 任一条为否 → 不做 |
| 1 定形态 | 定「长什么样」：球体／剖面／流程箭头／场线／多视角 | 说不出形态 → 退回 0 |
| 2 出提示词 | 喂教材截图，让模型先写制作提示词，**不碰代码** | 缺页码·方向·数量约束 → 重写 |
| 3 生成 v1 | 参照＋清单＋要求三件套一次给齐 | 知识点与教材不符 → 退回 2 |
| 4 返工·真 | 结构级修正，不是调参数 | 只在正面成立 → 继续改 |
| 5 返工·用 | 任务链＋分层提示，关卡顺序＝板书顺序 | 学生只需一路「下一关」→ 重做 |
| 6 交付校验 | 单文件、无外链、体积、首屏耗时 | 存在 CDN 或外链 → 阻断交付 |

**第 4 步必须早于第 5 步。** 形态错了还加交互，等于在错误地基上盖楼。最典型的失败是 v1 用平面圆环冒充立体，正面好看、侧面是几条线，却先做了五关任务。

整个流程跑 **2—3 轮**，每一轮都是「先定形态，再做交互」。教师每提一次新需求，两步重跑。

## 三、阶段细则

### 阶段 2：让模型写提示词，不是自己写

把**教材截图**（不是文字转述）交给模型，要求它产出制作提示词。跳过这步直接写代码，最容易漏掉学科约束（页码、方向、精度、专有名词）。

### 阶段 3：三件套

| 要素 | 作用 | 写法 |
|---|---|---|
| 参照 | 防 AI 乱生成知识点 | 教材图片原图 |
| 清单 | 这一课到底讲什么 | **精确到数量**：几支环流、几个带、几个风向、移动多少度 |
| 要求 | 怎么实现 | 3D／图层可开关／可拖拽／要配音／单文件 HTML |

硬约束必须写进提示词：方向与数值严格符合教材原图、禁止杂乱装饰、优先保证学科科学性、输出可直接运行的 HTML 单文件并自带注释。

模板见 `references/prompt-patterns.md`。

### 阶段 4：修「真不真」

判断标准只有一条：**转到任意角度都成立**。

- 平面圆环套在球上 → 正面成立、侧面崩 → 判定为假
- 改法是**结构级替换**：把平面换成绕轴一整圈的分区结构（案例：22 条径向气柱 ＋ 12 支气团锥，赤道与 60° 朝外张、30° 与极地朝内收）
- 顺带解决标签遮挡：做自动避让，重叠数要降到 1 处以内

不要在错误结构上叠动画、叠特效、叠交互。

### 阶段 5：从「演示动画」升级为「课堂工具」

两者逻辑不同，不要混：

| | 演示动画 | 课堂工具 |
|---|---|---|
| 逻辑 | 我做给你看，看懂就懂了 | 我留一个空，你来填，填错再说 |
| 目的 | 展示 | 让老师知道学生卡在哪一步 |

**关卡顺序＝板书顺序**，不另造一套学习路径。这是 AI 课件最常见的失败点：把知识点重新组织一遍，界面做得漂亮，但与课堂节奏对不上。

**提示必须分三层**：点一次给一句思路 → 再点一层更深 → 连错两次才放答案。

**看答案不等于过关**：答案摆出来后，仍要再点一次「提交检测」才算通过。

**至少一关用「动手」而非选项**：排序、图上点选、连线。选项能蒙，动手不能。

## 四、三张检查清单

### 真实性

- [ ] 任意角度／任意视图都成立
- [ ] 方向、数值与教材原图一致
- [ ] 循环类运动是绕整圈而非单点
- [ ] 标签互不遮挡（重叠 ≤ 1 处）
- [ ] 没有教材之外的杜撰名词

### 工具化

- [ ] 关卡顺序＝板书顺序
- [ ] 至少一关为动手操作（排序／点选／连线）
- [ ] 干扰项编得合理，不是明显凑数
- [ ] 提示分三层，看答案后仍需重新提交
- [ ] 困难／简单两种模式都能走通
- [ ] 卡关的学生有「再想想」可点，而不是只能看答案

### 交付

- [ ] 无 `http://` `https://` 外链，无 CDN、无外部字体
- [ ] 图片、音频、视频全部内联（data URI 或 base64）
- [ ] 配音预合成后嵌入，不现场合成
- [ ] 报出两个数字：文件体积、首屏可操作耗时
- [ ] 目标机（教室电脑）双击可开

用 `scripts/check_offline.py <file.html>` 做确定性校验，不要靠肉眼。

## 五、反面清单

不要做这些：

- 把「能转」当成交付标准——能转只是 v1
- 用平面元素冒充立体
- 为动效加动效，装饰性粒子、光晕、背景动画
- 关卡之间没有解锁逻辑，一路「下一关」
- 提示只有「看答案」一档
- 把知识点的组织方式重写一遍，与教材和板书脱节
- 依赖联网加载模型、字体、贴图

## 七、交付口径

- 单文件 HTML，双击即开，离线可用
- 首屏 2—3 秒可接受，超过 5 秒要压缩贴图或降低网格精度
- 交付时一并说明：学科依据（教材页码）、可关掉的变量、建议课堂用法（哪一关留给学生动手）
- 明确告知局限：AI 不知课标边界，深度分寸由授课教师最终确认；课件补的是「看不见的那部分」，不替代板图与纸笔练习
