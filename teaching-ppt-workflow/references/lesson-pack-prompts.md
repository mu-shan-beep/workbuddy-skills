# 教学课件工作流｜人工调用提示词

**本文件不是本机执行依据**，仅供用户人工复制到其他模型使用；本机执行一律以 `SKILL.md`「规则权威层级」第2—4级文件为准。本文件与规则冲突时以最新版规则为准，不反向兼容。各段末尾重复出现的「做两轮实际检查…展示成果待确认」是**单段复制自足所需**，属刻意保留，不得抽取为公共约定。

按环节复制对应代码块，随任务提供当前课的教材、已确认成果或待检查文件。制作到已确认进度后接续。板书绘图、宣传预览和录制脚本按单项调用。

## 整套制作与接续

```Plain Text
请按当前课题、教材、年级、课时和已有成果制作或接续完整教案包。先核对本课当前采用的材料、已确认成果和当前步骤。已经确认的内容直接沿用。仅在缺失会影响教学正确性或继续制作时指出具体缺项。

【最高信条（主动自动匹配对应专业规程，严禁等待用户指定）】
后续执行任何任务时，第一步必须由AI自主主动分析意图并自动匹配调用相关专业能力与规程（如文案自动匹配文案规范、教案自动匹配教案规范、课件大纲自动匹配大纲规范、逐字稿自动匹配逐字稿规范），严禁等待用户指定，也不看系统配置是否自动触发——一律由AI自主主动匹配、第一步先加载对应专业规程，不得等用户提醒或指定！

【提交前强制反转输出死规（剥夺直接交差权，严禁跳过自检）】
大模型天生具有交付冲动与惰性，为彻底杜绝“口头声称已自检实则未执行”的欺骗行为，本工作流全流程执行【输出顺序反转指令】：
严禁直接输出阶段成果！任何阶段提交时，你的回复必须严格先在顶部输出该阶段的【提交前强制核验表】（列出物理取证数据，严禁打勾表演）；只有核验完全通过，才允许在下方输出成果正文！若核验未通过，立即停止输出正文，直接报告驳回原因并就地修正！

【纯净源文件绝缘隔离铁律（客户交付级，零制作痕迹）】
上述【提交前强制核验表】与自检取证数据，仅属于向用户汇报时的思考与审核过程；**绝对严禁将任何核验表、自评分数、审查说明、AI客套表态（如“精心考量/为您生成/已自检”）写入交付的  或正文代码块中！** 交付的源文件代码块内必须 100% 仅包含可直接交付给客户看的纯净正文，严禁留有任何制作痕迹与 AI 腔！

【全任务执行状态机与硬门禁（全流程强制执行，禁止跳级）】
适用范围：一切任务，无大小之分（含单文件改动、一次核查、一次记忆写入、一次排障问答），不得以「这次很简单／只是顺手改一下」豁免。必须按以下状态执行，禁止跳级，且须在回复中显式报出当前状态与证据：
LOCK → AUDIT → EXECUTE → VERIFY → DONE
- LOCK：锁定当前唯一任务、输入、范围和禁止事项。
- AUDIT：审核实际准备执行的内容，并提供可核验证据。
- EXECUTE：只能执行已审核通过的内容，禁止临时改写、扩展、合并。
- VERIFY：检查实际结果；失败必须返回 AUDIT 修复。
- DONE：只有 VERIFY 通过后才能进入下一任务。
六大硬门禁：
1. 没有审核证据，不得执行。
2. 实际执行内容与审核内容不一致，立即判失败。
3. 实际结果未验收，不得进入下一任务。
4. 同一错误连续出现两次，停止重复尝试，先查根因。
5. 不允许用“已自检”“已隔离”“应该没问题”代替证据。
6. 问题分析、查因、修复、验证由助手负责，不把监督责任转交用户。

【全流程推进铁律】
1. 单向从属禁越界：未获教学设计定稿确认，严禁启动任何下游成果（大纲／样稿／页面／可画／逐字稿／学习清单／制作笔记）；下游不得反向成为教案的取证对象或放行判据。
2. 阶段推进严格把关：按 教案 → 本课时PPT大纲 → PPT样稿 → PPT页面 → 可画课件组装 → 制作笔记、逐字稿、学习清单 → 最终交付 推进。一个课时课件成品确认后才做下一课时PPT。
3. 封面纯净化铁律：课件封面（P01）严禁标注单元信息，只写课题、作者与教材版本，全课件统一，杜绝教材版次修订引发的单元争议。
4. 交付落地契约：最终交付仅五类（教案、课件、逐字稿、清单、笔记）。课件默认交付可画设计链接（明示才交pptx）；其余四项一律只交付 Word（.docx），严禁保留或交付 .pdf；以 --mode commit 直接输出至「交付文件/」文件夹；清理旧稿统一使用 /usr/bin/trash 移入废纸篓。
5. 省略教材页码：交付内容统一用课文段落、材料名称或关键语句定位，省略教材页码。课号、课时和课件自身页序照常使用。

收到反馈后，先核实原问题与证据，按已授权范围修订并定点复查。记录触发场景、实际证据、改进动作和验证状态。本课特例留在项目中。可复用的教训合并到对应制作或检查条款，用本次问题复查是否能更早发现，并保留原有确认点。已确认要求按实际采用版本接续。
```

## 教案

```Plain Text
请根据提供的课题、教材内容、年级、学情及课时要求，制作可直接用于真实课堂的完整教学设计。

要求：
1. 严格依据当前课题和教材版本，写清可观察、可评价的目标、重难点与关键知识。学情中未提供的情况标为合理预设，不编造真实学生表现。
2. 教学内容分析、学情分析各控制在200字以内；整课共用栏目只写一次。教学目标按课标四维列出具体表现，每条课时目标必须明确对应1个具体教学活动和1个可观察的评价证据（建立目标—活动—评价证据对齐）；评价量规各档位中，最低档（如★☆☆）必须覆盖目标的最低必做要求，严禁量规最低档与目标要求脱节。教学重难点明确，教学准备采用「资源状态登记表」（区分已提供／可制作／需查找／待确认／不适用），教学过程不受该字数限制。
3. 以普通班常态课为默认：每课时少量核心学习，按扁平化具体活动环节（4~6个）组织。鼓励大板块任务，但每个大板块下必须包含内部动作时间预算（阅读、书写、讨论/互读、反馈、组织转换五类耗时拆解），防止形式上标6~8分钟、实际动作需9~11分钟导致暗中超时。若整体过载，先删减或合并动作，禁止只在环节间搬移分钟。
4. 教学设计使用Markdown；教学过程并排四列：“教学环节（含用时）、教师活动、学生活动、设计意图”，不拆成标题行、双列活动和表后意图，不自行转Word。
   - 扁平化活动环节贯穿：取消“板块一、板块二”等大词打包，直接以全课 4~6 个递进式具体活动环节展开（如“环节一：情境导入，解题生疑（3分钟）”），每个具体活动环节独立占一行，师生动作严格水平对齐。
   - 控制单元格字数软上限（防 Word 排版挤压）：教师活动≤120字（抓关键指导）、学生活动≤80字（明确实操动作）、设计意图≤40字（紧扣素养目标）。
   - 下游映射标注：学生活动中需上屏的核心问题、例句或任务句，直接标注 `【上屏：xxx】`，供无缝映射 PPT 大纲。
   - 随堂产出即评价：学生的圈画、朗读、书写即评价证据，教师活动末尾以简短巡视点拨闭环，不设多余评价表。
   - 支架与填空回查原句：所有学习单、题干、填空句必须回查教材原句，不得改写原句的主语、逻辑和核心动词；改写必须注明依据，严禁产生句意不通或无词可填的错误。正文不夹带修订历史。
5. 板书、必要练习和评价与教学目标、活动一致；练习及反馈可融入教学过程，不默认新增独立作业模块。明确要求作业时再写，避免增加负担。
6. 多课时分别设计本课时目标、教学过程和板书，保持前后衔接；不重复整套内容分析和学情分析。必要字词读音、批注示范融入对应过程，不另立辅助小节。

默认输出：基本信息、教学内容分析、学情分析、教学目标、教学重难点、教学准备、分课时教学设计、教学反思。每课时只含目标、教学过程、板书，不另列评价依据、字词提示或批注示例模块。单元设计、AI与跨学科、独立作业拓展按需增加，不因参考模板出现就自动补入。具体以lesson-pack.md的“教案默认模块”为准。
尚未授课时，反思栏目写“课后反思要点”或预留填写位置，不编造实际课堂效果。
直接输出完整教学设计，不附PPT策划或额外分析。

交付内容统一用课文段落、材料名称或关键语句定位，省略教材页码。课号、课时和课件自身页序照常使用。

借鉴参考案例时，先根据本课学生的困难、学习顺序和证据重新推导设计，只有适用的思路才借用。AI 活动仅在有实际学习价值且课堂条件允许时采用。

【强制反转输出顺序：剥夺直接输出四列表格权】
严禁直接输出教学设计正文！你的回复必须严格分为两大部分：
第一部分【动笔前基线前置核验表】（必须先计算并打印出物理证据，禁止打勾表演）：
① 教材目录与事实底数：必须先核验教材总目录或单元导语页，写清课次、单元归属、单元语文要素与配套习作题名，严禁新旧版课号与单元/习作混搭；生字严格按教参标准统计（多音字单独列出，写为“认识X个生字，读准多音字Y”，禁止混计总数）；写出可复现正文字数；微观任务指令必须在对应段落有确凿依据；
② 逐环节容量预算（仅作内部取证，不写进教案正文）：逐环节列出「学生动作序列｜逐项耗时区间｜小计」，小计相加得出总时间，标出机动余量；若超载只准删/并动作，禁止只在环节间搬分钟；
③ 目标—活动—评价对齐核查（仅作内部取证，不写成正文矩阵表）：每条课时目标对应承接活动与可见产出证据；独立交付的《学习清单》量规最低档（★☆☆）必须在数学集合上完全覆盖目标的最低必做要求；
④ 支架回查与代入通读：所有学习单填空代入答案通读，严禁改写原句主语或动词逻辑，模板留空不预填答案；
⑤ 教学准备按 `lesson-pack.md`「教案默认模块」第 6 项执行，严禁夹带内部审查说明。

第二部分【教学设计正式正文】：
只有在第一部分五项基线全部闭环且无超时风险时，才允许在下方输出正式教案正文（按教案默认模块规范的法定结构：基本信息、教学内容分析、学情分析、四维总目标、教学重难点、教学准备、分课时教学目标、并排四列教学过程、板书设计、真实授课后的教学反思）。严禁夹带「目标—活动—评价证据对应矩阵」「逐环节内部时间预算表」「文末学习单附件与量规」「突发情况应急建议」等非法定模块；源稿必须纯净可直排，禁止 AI 自嗨括注、Markdown 水平线／代码围栏／HTML 标签与未经核验的单元编号。若第一部分任一项未过，直接报告驳回原因，就地修正基线，严禁强行输出正文！
交付前执行三道阻断闸门复核终稿是否守住基线；日常制作展示闸门结论与问题清零摘要；**仅明确要求完整审查报告时**才进行五轮六维评分（满分100，终稿≥90且关键问题清零）。记录证据和问题处理，教案正文保持纯净，展示整课教案待我确认。
```

## 教案检查（完整审查报告模式／日常只读模式，二选一）

```Plain Text
【角色设定】
你是一名严格挑剔的教研员与教学设计审查员，按教材和实际课堂组织条件核对教案。

【全任务执行状态机与硬门禁（全流程强制执行，禁止跳级）】
适用范围：一切任务，无大小之分（含单文件改动、一次核查、一次记忆写入、一次排障问答），不得以「这次很简单／只是顺手改一下」豁免。必须按以下状态执行，禁止跳级，且须在回复中显式报出当前状态与证据：
LOCK → AUDIT → EXECUTE → VERIFY → DONE
- LOCK：锁定当前唯一任务、输入、范围和禁止事项。
- AUDIT：审核实际准备执行的内容，并提供可核验证据。
- EXECUTE：只能执行已审核通过的内容，禁止临时改写、扩展、合并。
- VERIFY：检查实际结果；失败必须返回 AUDIT 修复。
- DONE：只有 VERIFY 通过后才能进入下一任务。
六大硬门禁：
1. 没有审核证据，不得执行。
2. 实际执行内容与审核内容不一致，立即判失败。
3. 实际结果未验收，不得进入下一任务。
4. 同一错误连续出现两次，停止重复尝试，先查根因。
5. 不允许用“已自检”“已隔离”“应该没问题”代替证据。
6. 问题分析、查因、修复、验证由助手负责，不把监督责任转交用户。

【检查要求】
1. 只读检查提供的教案。对照教材、单元导语、学情和课时，核对知识事实、重难点、目标与活动是否对齐，检查任务支架、材料可用性及学生能否在常态课条件下完成。
2. 逐课时容量与时间审计（五类时间估算表）：按环节列出「阅读、书写、讨论/互读、反馈、组织转换」具体耗时估算表，指出明显偏紧或超时环节（估算上限>标称时间），列出可删减或合并的具体动作建议。严格执行死规：总负荷超载时只准删/并动作，禁止只改分钟不删动作。
3. 目标—活动—评价一致性核查：核对四列教学过程中教师活动指导、学生活动即时产出与设计意图是否闭环，核对独立《学习清单》量规最低档（★☆☆）是否覆盖目标最低必做要求（教案正文严禁另设矩阵表）。
4. 支架回查与原句核验：检查学习单题干、填空句是否严格回查教材原句，严禁改写原句主语或动词逻辑导致句意不通。
5. 资源按已提供、可制作、需查找、待确认、不适用五态核对。
6. 【模式选择】：
   - 日常模式：只按三道阻断闸门（教材事实无硬伤、常态课容量无超时虚构、上屏信息自足与四列规范齐备）核验并输出取证清单，不输出分数、不展开五轮。
   - 完整审查报告模式（仅用户明确要求时开启）：至少五轮（事实、目标、任务、演练、综合），每轮按教材25、目标20、逻辑20、任务15、容量10、规范10评分，满分100，总分≥90且关键问题清零方可通过。
7. 【输出要求】：只指出实际存在的问题，标明具体位置、问题原因、课堂影响及可直接替换的最小修改文字，给出能否通过的明确结论。先检查，严禁擅自修改原稿，待用户授权后再修改。
```

## 板书

```Plain Text
请将当前教学设计中已经确认的板书绘制成高清图片。

内容严格沿用确认方案，保留文字、知识层次、箭头和逻辑关系，只优化视觉排版，不重新设计教学内容。
采用真实课堂深绿色黑板与粉笔手绘风，白色粉笔为主，少量彩色粉笔强调重点；线描简洁，装饰不挤占知识区。

每个课时单独提交一次绘图任务，每次只生成该课时的一张完整16:9板书图，按使用用途保证文字和关系清楚可读；独立板书按自身用途保证清楚可读，不套用固定像素门槛。
多个课时依次完成，不在一次绘图调用中合并，不制作多格拼图。
核对文字、关系、画幅和实际尺寸，纠正错字、漏字或裁切后交付独立PNG；仅提高像素尺寸不等于增加原生细节。
直接输出图片，不重新分析或改写板书。

交付内容统一用课文段落、材料名称或关键语句定位，省略教材页码。课号、课时和课件自身页序照常使用。

仅在我单独委托板书图时执行此提示词。完整教案包的板书方案写入教学设计。做两轮实际检查，先对照依据和内容，再检查实际成果的呈现、可用性和问题处理。检查摘要另在聊天列出范围、发现、处理和未核实事项。展示当前阶段的实际成果，待我明确确认后再推进。
```

## PPT大纲

```Plain Text

要求：
```

## PPT大纲检查

```Plain Text
【角色设定】

LOCK → AUDIT → EXECUTE → VERIFY → DONE
- LOCK：锁定当前唯一任务、输入、范围和禁止事项。
- AUDIT：审核实际准备执行的内容，并提供可核验证据。
- EXECUTE：只能执行已审核通过的内容，禁止临时改写、扩展、合并。
- VERIFY：检查实际结果；失败必须返回 AUDIT 修复。
- DONE：只有 VERIFY 通过后才能进入下一任务。
六大硬门禁：
1. 没有审核证据，不得执行。
2. 实际执行内容与审核内容不一致，立即判失败。
3. 实际结果未验收，不得进入下一任务。
4. 同一错误连续出现两次，停止重复尝试，先查根因。
5. 不允许用“已自检”“已隔离”“应该没问题”代替证据。
6. 问题分析、查因、修复、验证由助手负责，不把监督责任转交用户。

【检查要求】
1. 对照提供的教材原件、定稿教案和待检查PPT大纲，逐页核对知识事实、活动顺序与实际文案。

4. 文本准确性与防脑补铁律：
   - 核对课文原句动词填空是否原词呈现（严禁概括词代入，如必须填课文原词“冲”，严禁填“冲撞”）；
   - 核对胜因探究与哲理感悟是否严格立足课文确切原句（必须保留课文修辞，严禁基于常识进行课外物理力学因果脑补）。
5. 显隐三态时钟核查：
   - 检查核心答案、填空订正是否标【交流后出示】，严禁提前泄露；
   - 检查示范支架是否首个前置呈现（提供方法样例），其余两看是否留作交流点拨，严禁全屏提前剧透；
   - 检查自评量规是否在学生同桌互读互说交流后出示自评，严禁在交流前抢跑出示；检查量规上方是否带有语境过渡引导语句。

   - 检查关键操作页（如心情曲线图）是否在屏幕上亮出“只填心情词，不写原因；原因在同桌互读时讲”等防超时护栏；
```
