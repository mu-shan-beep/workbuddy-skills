# 规则自我修复、优化与梳理机制

本文件是**全部自建技能**的**常驻治理细则**：教案包三件套（`teaching-ppt-workflow`、`lesson-transcript`、`lesson-typeset`）＋ `xhs-lesson-notes`、`ppt-visual-style`、`interactive-courseware`（共 6 个）。**第三方安装技能不在治理范围**（含带 `_skillhub_meta.json` 的 `baidu-pan-ops`、`quark-drive`、`totorosir-workbuddy-checkin`，以及 ppt-master、pdfkit-py、teachable-figures、teardown、ima-skills、wps-office-suite 共 9 个），对其只报不改。目的：让规则在每次修订、每次自检、每新课试跑时自动收敛，而不是越改越乱、越改越长、越改越自我矛盾。

`SKILL.md`「规则权威层级」与「更新规程」是裁决与执行入口；本文件是其落地工具箱。两者冲突时以 `SKILL.md` 为准，并当次回写本文件。

## 1. 触发条件（何时必须跑本机制）

| 触发 | 动作 |
|---|---|
| 改任何含「轮次／评分／闸门／板块／页数／交付格式／模式标签／行号引用／触发条件／权威归属」的规则 | 先全库检索该术语，再改；改后跑第 4 节自检 |

| 自检／试跑发现新盲区 | 当次回写第 3 级或第 4 级文件并留案例；盲区落在清单／闸门之外时，当次修补判定式 |

## 3. 防臃肿规则

1. **单点定义、全库对齐**：同一规则只在唯一归属处定义；他处只引用，不复制。改前先全库检索命中总数作分母。
2. **新增须伴删除**：新增一条规则／章节／附件，须同时删除等量的同源旧表述；只追加不删的更新一律拒绝（见 SKILL.md 更新规程 2）。
3. **不重复造词**：已有术语（闸门、取证清单、单向从属、确认凭据）不再换名复述；新增术语须写入本表第 2 节。
4. **不预设下游已存在**：凡涉及「大纲／页面／讲稿」的规则，必须显式标注其启动前提为「上游已定稿确认」，不得行文暗示下游已生成（这是 2026-11-12 越界根因）。
5. **阈值只定义一次**：字数软上限、环节数、课时长等数字只在 `lesson-pack.md`「教案默认模块」定义，他处引用，不得另写一套。

## 4. 改后自检协议（每次规则修订必跑）

**步骤 0 — 机器项一次跑完（先跑它，再做人工读盘与试跑）**
```bash
python3 ~/.workbuddy/skills/teaching-ppt-workflow/scripts/rule_audit.py
```
断言：①三入口是否都绑定状态机；②`lesson-pack-prompts.md` 的 11 份复制件是否逐字一致；③跨文件锚点是否死链；④已删模块是否被下位文件正向要求（矛盾）；⑤Markdown 表格列数是否一致；⑥单点定义表登记项是否齐全。
**脚本 PASS 不等于优化完成**——人工读盘与新课试跑仍必须做；脚本 FAIL 一律先修再谈其他。

**步骤 1 — 术语检索分母**
```bash
cd ~/.workbuddy/skills/teaching-ppt-workflow
grep -rn "待检索术语" . --include=*.md
```
报出**命中总数（分母）**与命中处；分母缺失不得宣称「零残留」。自选词表报「0 命中」不构成零残留证据。

**步骤 2 — 净变更核算**
```bash
cd ~/.workbuddy/skills
git diff --numstat -- teaching-ppt-workflow/
```
报「新增行数／删除行数／净变化」；净增须能对应「新增伴删除」。

**步骤 3 — 读盘痕迹**
重新打开被改文件，核对改动点确已生效；报「改动文件／行数／末行原句」。

**步骤 4 — 冲突与分叉扫描**
- 对单点定义表每个概念，确认只有归属处有定义，引用方无分叉。
- 检索「独立调用／对称一致／二选一输入／持续委托」类措辞，确认都带了「不解除上游生效条件」或「≠成果确认」的限制。
- **层级、时序错配与死链**：判定式若只存在于第 7 级人工提示词或领域参考、未挂到日常执行入口（lesson-pack.md 取证清单／闸门），或**只在成稿后闸门生效、撰写入口没有动笔前准入**，均视为「规则未生效」；当次提升或以链接引用，不复制副本（本次复发根因）。同时核对所有指向 `lesson-review.md`／`lesson-pack.md` 的锚点与真实标题逐字符一致，标点差异导致的死链当次修标题或修链接，不得留空链。
- **覆盖率声明与生成期覆盖**：报出本次「已查维度／未查维度」，确认最难自动化、风险最高的一维已被真实取证覆盖；并报出四类基线（教材底数／容量预算／目标评价对齐／句级代入）各自在动笔前是否已产出可复看取证物，未产出即判「准入未执行」。只有可自证指标（字数、合计、关键词命中）全绿不构成通过，也不得事后补报基线。
- **全流程同类全扫与全案连锁核验**：任一阶段发现缺陷进行修订时，必须回溯该阶段及关联阶段同类全部对象并实际代入验证（改教案填空全扫所有填空，改大纲一页全扫连续页，改样稿全扫风格拆解），严禁点状修补；核心口径（生字数量、达标要求、环节微观任务）变动时，必须连锁核查资源表、学情分析和时间预算表说明栏，严禁局部残留旧口径；大纲修订时严格执行【跨页涟漪核验】（改动生字反查前序多音字、改动赛事卡反查后序心情图横轴、改动示范反查后序任务指令护栏、改动攻防描写反查对比表与胜因原句）。
- **缺陷状态台账**：全流程所有阶段的问题清单逐项标「成立／已关闭／已驳回（附证据）」，已驳回项不得在下一轮以「待核实」继承；跨轮继承必须带状态，不整份复制。

**步骤 5 — 试跑（验收门槛）**
新口径须在一个**新课题或新产物**上试跑一次才算优化完成；同一课题同一成果的重复检查不计为「下一次真实任务」。试跑或自检发现的新盲区当次回写第 3—4 级文件并留案例。

## 5. 漂移检测节奏（周期性梳理）

- **每新课读盘**：开启新课时，全库逐文件读盘一次，与第 2 节单点定义表对账，输出「规则健康」备注（矛盾点／清晰度／未验证项）；并确认新课教学设计及后续各阶段在启动前均已产出生成前准入凭据，而不是成稿后才补。
- **季度级收敛**：检查生效条目是否膨胀、是否有重复口径、是否有死链；按第 3 节防臃肿规则合并。
- **镜像单向覆盖**：本机最新版为唯一权威，飞书提示词与云端技能按最新版覆盖，不反向兼容、不为旧版保留双轨。

## 6. 冲突裁决阶梯

1. 用户当前明确指令 ＞ SKILL.md ＞ lesson-pack.md ＞ lesson-review.md ＞ task-modes/workflow 等 ＞ 领域参考 ＞ 人工提示词（lesson-pack-prompts.md 仅人工复制用，非本机执行依据）。
2. 同一条规则只在一个层级定义，其余只引用。
3. 出现分叉时，**以唯一归属处为准**，删除分叉表述；不靠节首一句声明覆盖散落条款。
4. 关联技能（lesson-transcript、lesson-typeset）与本技能冲突时：维度裁决表优先——逐字稿维度以课件为唯一依据（lesson-transcript §0 有效），内容维度以教学设计为权威；跨技能路径契约以全局 MEMORY「md 源稿落课题根目录」为准。

## 7. 失效产物自修复触发

检测到以下任一情形，立即按 lesson-pack.md「失效产物登记与处置」标「未生效／待重校」，不将其当作有效依据，不悄悄复用，不删文件：
- 上游（教学设计）未经定稿确认即生成了下游（大纲／页面／讲稿／清单／笔记）；
- 上游闸门未过或已确认成果后续被判不放行时，据此生成的下游；
- 跨对话接续时，发现上一轮成果的状态标注未清除。

自修复＝标状态 → 等上游修订并重新定稿确认 → 下游单向重做 → 清除状态。

## 8. 只读例外

用户明确限定「只检查／只读」时：
- 不落盘改规则，新盲区只记为**待回写项**随结论报出；
- 取得修改授权后当次回写并留案例；
- 自检发现的矛盾点如实报告，不擅自修。
