# 【本机】教案包制作

## 全任务执行状态机与硬门禁（全流程强制执行，禁止跳级）

**适用范围（2026-11-13 用户纠偏，最高优先）：一切任务，无大小之分。** 含本技能全流程、单文件改动、一次核查、一次记忆写入、一次排障问答、一次规则修订，一律适用；禁止以「这次很简单／只是顺手改一下」为由豁免，也禁止理解为「只在某个技能内部才生效」。

必须按以下状态执行，禁止跳级：
`LOCK → AUDIT → EXECUTE → VERIFY → DONE`

- **LOCK**：锁定当前唯一任务、输入、范围和禁止事项。
- **AUDIT**：审核实际准备执行的内容，并提供可核验证据。
- **EXECUTE**：只能执行已审核通过的内容，禁止临时改写、扩展、合并。
- **VERIFY**：检查实际结果；失败必须返回 AUDIT 修复。
- **DONE**：只有 VERIFY 通过后才能进入下一任务。

**六大硬门禁**：
1. 没有审核证据，不得执行。
2. 实际执行内容与审核内容不一致，立即判失败。
3. 实际结果未验收，不得进入下一任务。
4. 同一错误连续出现两次，停止重复尝试，先查根因。
5. 不允许用“已自检”“已隔离”“应该没问题”代替证据。
6. 问题分析、查因、修复、验证由助手负责，不把监督责任转交用户。

**状态必须显式化（2026-11-13 用户追问「状态机丢了吗、怎么没看到你用」后加固）**：状态机不是心里默默走的流程，必须让用户看得见。
- 每个任务至少报两处（不论大小）：**开工报「LOCK：任务／输入／范围／禁止事项」**，**收口报「VERIFY：实测物证 → DONE」**；中途转状态用一行标注。单文件／单命令的小改可把 LOCK＋AUDIT 压成一行、VERIFY 压成一行回读证据——**压短合法，省略状态与跳过 VERIFY 不合法**。
- 报「已完成／已修复／已是 0 残留」前必须先跑出 VERIFY 的实测输出；**只有结论没有输出＝未验收**（硬门禁 5）。
- 排版、逐字稿、交付整理等**下游单项委托同样适用**，不因「这次只排一份文档」而降级——三套技能入口（本技能、`lesson-typeset`、`lesson-transcript`）均已绑定本状态机。
- 机器可查部分由 `scripts/rule_audit.py` 断言（三入口是否绑定、复制件是否走样、锚点是否死链）。

## 规则权威层级（冲突时的唯一裁决点）

**同一条规则只在一个层级定义，其他文件只准引用，不准复制改写。** 冲突时按下列顺序裁决，一律以最新确认的版本为准，不为兼容旧口径保留两套表述。

| 级 | 文件 | 唯一职责 |
| :-- | :--- | :--- |
| 1 | 用户当前明确指令 | 覆盖一切 |
| 2 | `SKILL.md` | 总路由与死规：五项交付、禁教材页码、可画路线、阶段确认点 |
| 3 | `references/lesson-pack.md` | 阶段与交付契约：阶段表、教案模块、四列字数、上屏标记、质检口径 |
| 4 | `references/lesson-review.md` | 教案质检方法论与放行条件 |
| 5 | `task-modes.md` / `teaching-resources.md` | 单项任务边界；**不得规定质检轮次或评分** |
| 6 | `classroom-design.md`、`visual-*`、`capability-*`、`workflow.md` | 领域参考与衔接；**不得规定流程或自评口径** |
| 7 | `lesson-pack-prompts.md` | **仅供人工复制到其他模型，不是本机执行依据** |

**更新规程（三条，防复发）**：
1. **单点定义 + 全库对齐**：改任何含「轮次／评分／闸门／板块／页数／交付格式／模式标签／行号引用／触发条件」的规则前，先全库检索该术语的**所有出现处**，检索词表须由该术语的全库命中反推并报出**命中总数作分母**，一次性对齐；禁止只改主文件、只改命中句而留下同句后半段、同块其他条款或下位文件的旧口径，自选词表的「0 命中」不构成零残留证据。同一节内不得出现「总则豁免 + 分则无条件」；评分条款须**隔离到带模式标签的独立子节**，不靠节首一句文本声明覆盖。
2. **净变更核算**：每次更新报「新增行数／删除行数／净变化」，新增须伴随删除同源旧表述，只追加不删的更新一律拒绝。
3. **试跑读盘 + 结果回流 + 镜像单向覆盖**：改后重新打开被改文件核对改动点确已生效，并在**新课题或新产物**上试跑一次新口径（同一课题同一成果的重复检查不计为「下一次真实任务」），未试跑不计为优化完成。试跑或自检中新发现的规则盲区须当次回写第 3—4 级文件并在 [feedback-regression.md](references/feedback-regression.md) 留案例；若新盲区落在清单／闸门之外，即判该清单覆盖不全，**须当次修补判定式**，仅留案例不改清单不计为优化完成。只记录不回写同样不算完成（自检发现与用户反馈同样触发；**用户明确限定「只检查／只读」时例外**：盲区记为待回写项随结论报出，不落盘改规则，取得修改授权后当次回写）。本机最新版为唯一权威，飞书提示词与云端技能按最新版覆盖，不反向兼容、不为旧版保留双轨。

**规程自身的取证物**：每次更新规则须在聊天中报出「检索词**及全库命中总数（分母）**与命中处／新增·删除·净变化行数／改后读盘痕迹（行数、末行原句）／试跑发现与回写位置」；缺任一项视为本次更新未完成，分母缺失时不得宣称「零残留」。

**规则修订权限边界（不得越界、不得乱改，2026-11-13 用户立规）**——防止「以优化为名擅自改规矩」：

| 类别 | 助手可否自主做 | 例子 |
| :-- | :-- | :-- |
| **可自主修订**（属修 bug，不改规矩） | ✅ 直接改并报备 | 表述歧义、死链／失效锚点、同义重复口径合并、与用户最新裁定冲突的旧表述、可复现的代码级缺陷 |
| **须用户明确指令**（属改规矩） | ⛔ 无指令不得动 | 交付物增减、阶段顺序与确认点、闸门数量与评分口径、版式参数与命名规范、素材来源规则、术语更名、模块增删 |
| **一律禁止** | ❌ | 以「优化」名义扩大改动范围；在委托范围外的文件落改动；把只读委托做成改规则（只读例外见 self-maintenance §8）；只追加同义口号不删旧表述；改规则后不跑自检 |

- 每次改动须报「改了哪一条／依据哪条用户指令或哪次自检发现／新增·删除行数」；**给不出依据的改动一律回退**。
- 只读委托下发现规则缺陷，只记为**待回写项**随结论报出，取得授权后当次回写（self-maintenance §8）。

本机制的常驻细则、单点定义表与自检脚本口径见 [self-maintenance.md](references/self-maintenance.md)；每次规则修订或用户要求自检时依此执行，不另行发明流程。**自省三问（每次任务 DONE 前必答，无问题也要报「无」）**：① 本次有没有本该在生成期就规避的缺陷？② 根因是规则缺口、代码缺口还是执行走样？③ 已回写到哪条规则／哪行代码／哪个断言？

## 先选对入口

- 做完整教案包、课堂 PPT 或其中一个环节，从本技能开始。整套顺序为教学设计 → PPT 大纲 → 三页样稿 → 正式单页 → 可画组装 → 制作笔记、逐字稿、学习清单 → 交付。接续时从已确认的阶段继续。**单向从属：教学设计是内容与决策的唯一权威，大纲是它的上屏表达方案、为教学设计服务；每一阶段只在上一阶段成果经用户明确确认后启动，下游成果不得反向成为教学设计的质检取证对象或放行判据，也不得为对齐大纲而修改教学设计。上游变更后由下游单向跟随重做。**
- 只做色彩、笔触、排版风格选择或风格拆解时，读取 `ppt-visual-style`。它提供视觉依据，整套阶段、交付路线和确认点仍由本技能负责。
- 最终成果是可操作的 2D 或 3D 交互课件时，使用 `interactive-courseware`。
- 本机 Codex 以这个本机入口执行。ChatGPT 的同名云端个人技能单独识别，版本按各自实际加载的来源核对。

以普通班的常态课堂为默认用途，不预设学生已熟练互评、教师能高频切换并逐人即时诊断。先为少量核心学习安排连续读、想、写、说的时间，再设计必要反馈；目标可评价不等于每个目标都要当场单设检测。**教学设计动笔前先过 [动笔前基线准入](references/lesson-pack.md#教学设计动笔前基线生成期准入)（教材底数／容量预算／目标评价对齐／句级代入四项），四项不齐或容量预算超载不得展开四列表；缺陷在生成期规避，不靠成稿后闸门补救。** 制作前按 [常态课负荷约束](references/lesson-review.md#先按常态课选择任务再细化) 判断整体负担，不在高负荷骨架上用精密计时反复打补丁。 教学设计在初稿展开前和交付前均按[常态课堂可执行性](references/lesson-review.md#常态课堂可执行性初稿与交付双重检查)核对真实组织条件；若教师仍需大幅重设计才能上课，不因时间合计或评分达标而放行。课件帮助学生看懂材料与任务，教案、课件、讲稿各自承担职责；没有特别要求时不按展示课或说课组织。

本技能负责判断任务、明确依据和质量标准，具体文件、图片及应用编辑交给相应执行技能或插件。不复制执行工具手册，也不为每次任务建立一套项目管理文件。

学习优秀案例或推导新课设计时，按需读 [设计思路的提炼与迁移](references/design-reasoning.md)。本用户明确要求学习设计思路：提炼“为什么这样设计、什么条件下成立、如何根据本课重新推导”，不将参考案例的具体活动、环节顺序或版式变成通用做法；分别落实到教案审查与页面设计，不新增确认阶段、评分维度或交付栏目。

## 用户教案包流程

**固定规则：客户交付级源文件与去 AI 味铁律（2026-11-13 用户明确立规，最高；唯一归属见 [lesson-pack.md](references/lesson-pack.md#全包源稿纯净化与去-ai-味铁律)）。**
交付给用户的所有 Markdown 源文件（`<课题根>/<课文>-<类型>-源.md`）和 Word 成品，**必须是可以直接交付给客户看的，绝对不留任何制作痕迹与 AI 痕迹**。
1. **生成期源头掐灭（严禁入稿）**：给 AI 的评分、自检报告、说明性文字、表态性内容（如“本设计精心设计…”、“符合新课标核心素养…”、“好的，为您生成…”、“已对照放映时序核验…”等），**直接在生成源文件时全部去除，严禁写入 `-源.md`，更不要导入排版**。源文件正文必须纯净、专业，立足一线常态教学；
2. **后期排版期双重过滤**：下游排版技能（`lesson-typeset`）在排版时作为第二道硬闸门，自动润色切除任何可能残留的 AI 味、表态性内容与代码标记残渣（`---`、代码围栏、`<br>`、单星斜体等），绝不排入 `.docx`。

**固定规则：教案包最终交付仅五项。** 教学设计、PPT课件、制作笔记、逐字稿、学习清单。各项仅交当前采用版本和选定格式，PPT按可画路线交付。板书方案融入教学设计；独立板书图、宣传海报、展示拼图、检查报告、额外格式、副本及ZIP均不纳入整包制作和交付。仅在制作确需时使用大纲、样稿、教材与源文件，复用已有工作区，和交付目录分开。另有明确的单项委托时按单项处理。

**固定规则：后续所有产出物不出现教材页码。** 课件、大纲、教学设计、学习或作业清单、讲稿、板书、使用笔记、宣传等交付的正文、表格、图片和备注均适用；用“课文开头”“排练部分”“结尾”“课后表格”或关键语句定位。教材页码仅供内部核对，不写入交付内容。从已有成果提取新材料时也应去除教材页码；之前已采用的成果不回溯修改。课号、课时、课件自身页序及交付文件自身页码不受此限制。

**课件默认交付可画设计链接；仅当用户明确要求「可编辑 pptx」或「交付 pptx 文件」时才制作并交付 `.pptx`，「制作PPT」、模板、动画或可编辑需求不自动转为原生 PPTX 制作。** 仅含原始整页图片的临时PPTX可作为导入中转，不作为课件成品交付。明确委托处理本机已有的拆图稿时，按 [本机单项指令](references/lesson-pack-prompts.md#本机单项拆图后校字清理残留与添加动画) 在本地完成校字、图层清理或原生动画。

本用户已确定的课件交付路线：先绘制完整课时页面，再按已确认PPT大纲页序全部导入可画（Canva），每页放一张原图，保留比例与内容，最终交可画设计链接。不得把“继续制作PPT”自动改成本地PPTX交付，也不重新生成设计或自动拆层；只有用户明确改变路线时才调整。必要的本地打包文件仅作导入中转，不替代可画成果。继续前先核对已有页码，已齐页则进入可画组装，不重复绘制。

用户说“按照流程帮我制作教案包”“制作完整教案包”时，默认是整套成果的持续委托，不能仅交一份教案即结束，也不能每到下一阶段再索要一次制作委托。范围按流程中的完整交付清单执行；阶段确认是推进条件，收到确认后继续已授权的下一阶段。只有明确限定“只做教案”“只检查”等时才缩小到单项。**持续委托授权的是阶段推进顺序与已授权的下一阶段，不等于任一阶段成果的定稿确认；每阶段成果仍须用户明确确认才生效（确认凭据见 lesson-pack.md「明确确认点」）。**

本用户的教案与原创课件按 [lesson-pack.md](references/lesson-pack.md) 执行：教案**撰写前先产出动笔前基线，成稿后**日常以三道阻断闸门（教材事实／常态课负荷／上屏信息自足与四列规范）复核基线并输出取证清单，不输出分数；仅用户明确要求完整审查报告时执行5轮评分且≥90分；其他成果至少2轮检查。每阶段展示实际最终成果，等待用户确认后才推进；内部自检不能代替确认。PPT每次完整完成并确认一个课时，再开始下一课时。

教学设计正文默认采用用户确认的精简表格结构，见 [教案默认模块](references/lesson-pack.md#教案默认模块)：整课共用分析只写一次，栏目用“学情分析”“教学目标”；语文目标按文化自信、语言运用、思维能力、审美创造四维简写，目标后不附评价依据，“教学重难点”“教学准备”分列。教学设计默认以Markdown交付；教学过程采用扁平化具体活动环节贯穿（4~6个环节，取消大板块打包，每环节占一行），按“教学环节（含用时）、教师活动、学生活动、设计意图”并排四列，不自行转为Word。执行四列单元格字数软上限（教师活动≤120字、学生活动≤80字、意图≤40字）防Word排版挤压；学生活动中需上屏核心材料标注 `【上屏：xxx】` 供下游大纲无缝提取。各课时只展开目标、四列教学过程和板书，必要字词及批注提示融入过程，末尾保留教学反思。单元设计、AI与跨学科、独立作业拓展按需增加。内部审查不扩写成操作附录；此规则不缩小整套教案包的其他委托范围。

具体格式按 [lesson-pack-prompts.md](references/lesson-pack-prompts.md) 对应标题定位读取，只加载当前环节。整套委托逐阶段推进，明确限定的单项只做该项；新流程规定的确认点优先于下文通用的自动衔接建议，已有明确确认不重复索要。制作任务已授权的内部修订可继续；单独只读检查仍不改原稿。

## 用户反馈后的自动改进与自主进化闭环

**核心信条（自省与自动进化，2026-11-13 用户立规）**：
Skill 可以有问题，但**绝对不应该不会自动优化！遇到问题必须自主深度思考根因、主动吸取教训、自主发起规则演进与代码级硬约束，不断自我优化，绝不能每次都等用户来指出！** 把监督和查错责任转交用户，即是助手的彻底失职。

先按 [反馈回归案例](references/feedback-regression.md) 定位当前产物相关条款，将规则传到实际提示词、工具操作和验收。无论是用户指出问题，还是自检／试跑发现新盲区：
1. **主动归因，不推卸责任**：立即深度自省“为什么在生成期没有提前规避”，严禁找借口；
2. **拒绝口号，代码级物理闭环**：严禁仅追加同义自然语言提示词（“请认真检查”），必须将预防动作转化为**前置工具调用、物理数据提取（如课件 XML 解包、教材原件正则 Grep）与机器断言**；
3. **连锁回写与案例固化**：当次原位修订对应第 3—4 级规程文件（`lesson-pack.md`、`task-modes.md`、`lesson-pack-prompts.md`），并在 `feedback-regression.md` 留下真实闭环案例；
4. **全案连锁涟漪排查**：依据 `self-maintenance.md` 步骤 4，只要改动一处底层标准，必须连锁排查关联产物（改动大纲反查教案与清单、改动课件反查笔记与讲稿），不留死角。
遵循已有确认点、只读边界与生成图局部字形的标注规则；**只读委托下新盲区只记录为待回写项随结论报出，不修改规则**，取得授权后当次回写。

本课特例留在已有项目记录。可复用的教训合并到本技能负责的制作或检查条款，记录触发、证据、动作、适用边界和验证状态。用本次问题复查能否提前发现，兼查原有合理做法、课堂负担和已确认内容。局部修订按实际范围检查。交付时简述成果修复与规则改进，复用已覆盖问题的条款。

## 课堂表达与视觉判断

整套教案包以给学生实际授课为用途。课件、学习及作业清单采用符合年级的学生语言，指令具体、清楚；教案、讲稿和使用笔记采用自然、准确的教师语言，便于直接组织课堂。所有用词先核对阅读对象和教学情境，内部制作、审查、委托沟通及宣传措辞不混入课堂材料；自然表达不等于用词随意，专业表达也不等于堆术语。具体写作与检查见下列课堂表达参考。

制作页面文案、预览图、PPT、美化或视觉修复前，读 [classroom-design.md](references/classroom-design.md)。依据本页学生要观察、比较、讨论、操作或归纳的内容选择布局，优先保证知识准确、阅读顺序和课堂投影清晰。

按 [visual-reference.md](references/visual-reference.md) 衔接三个任务：大纲阶段给参考搜索关键词；没有制作委托的独立风格来图请求默认只做拆解；已要求绘制或已授权整套制作时，必要拆解属于制作内部步骤，复用已有结果后继续绘图，无需另要一次拆解授权。新风格缺少参考时仍遵守用户先收参考的流程；已有批准风格、指定模板或本课页面可直接沿用。导出审核图与局部修复不重新收参考。

“减少AI味”落实为具体修改：用真实问题和材料代替空泛口号，按内容关系安排版式，减少无功能装饰和机械重复，教师语言自然可说。不要将“所有页面都极简”“一律三张卡片”或某种配色变成新的固定模板。
