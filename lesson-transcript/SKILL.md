# 课堂逐字稿：编写与审核（lesson-transcript）

一句话：**教学设计决定教什么，课件决定放什么，逐字稿只负责把它变成课堂上说得出口的话。**

| 文件 | 作用 |
|---|---|
| `references/script-spec.md` | 唯一编写与审核标准（用户定稿 V1.0，二十三章）。判断“该不该这样写”只看它 |
| `references/audit-playbook.md` | 对读与时间核算的操作规程：抽课件文字、建环节—页映射、跑校验、报问题口径 |
| `scripts/pptx_text.py` | 逐页抽取课件文字（可选备注），作为对读底稿 |
| `scripts/audit_script.py` | 校验时间轴连续／总长／页归属活动／自述时长／配图张数 |

排版不归本技能：写好的源稿交给 `lesson-typeset`，它会自动按 `pNN.jpg` 配课件截图。

---

## 0. 四条不许，一条必须

1. **不改教学设计**——环节、活动、分钟数、板书、作业都是已确认的。
2. **不改课件**——页序、问句、词表、图都不动；发现错字只报告。
3. **不跳页不添页**——课件多少页，稿就多少页，顺序一致。
4. **不留备份副本**——重写就地在 `.workbuddy/<课文>-<课时段>-逐字稿-源.md` 上改，不另存 `-旧版`、不建 `备份-<日期>/`、不打 zip。要回退靠系统废纸篓与 git（用户 2026-11-06 裁定；逐字稿源稿是唯一真身）。
5. **必须把冲突列出来**：位置 ＋ 现象 ＋ 依据 ＋ 建议，四样齐全，不用新环节绕过去。
   （依据 `script-spec.md` 2.3、二十、二十三）

允许的补充只有：课堂常规语言、自然过渡、即时反馈、组织秩序的提示（4.2）。

---

## 1. 开工前先拿到三样事实

| 要拿到的 | 怎么拿 | 用途 |
|---|---|---|
| 环节与活动的分钟数 | 读教学设计，抄成「环节→活动（分钟）」两列，先自查加法＝课时总长 | 时间的唯一基准 |
| 每页屏幕内容 | `python3 ~/.workbuddy/skills/lesson-transcript/scripts/pptx_text.py <课件.pptx> [--notes]` | 页标题、问句清单、词表／写字表／作业项 |
| 课文原句 | 教材 PDF 或用户给的原文 | 引文、多音字、动词串只能照教材 |

缺哪一样就说明哪一样缺失，不凭印象补（2.1、13.2）。

---

## 2. 四段工作流（对应 spec 第 23 章九步）

### 第一段 对读（第一步～第三步）

1. 抄活动分钟表，检查“环节内活动之和 ＝ 环节分钟”。
2. 抽课件文字，逐页记：**页标题 / 问句（含编号）/ 固定清单条数**。
3. 建对应表：`环节 → 活动(分钟) → 课件页 → 稿页起止`，一行一页，六列（见 playbook 第 3 节）。
4. 页数与页序对上之后才算可以动笔；对不上先报告，不写。

### 第二段 写稿（第四步～第五步）

按页写，每页四件套：〔操作〕→ 师（任务与提问）→ 生／〔学生可能说〕→ 师（反馈、追问、点拨）→〔板书〕。
要点：

- 页面问句就是稿子的问句，编号也要对得上；课件四问就写四问，不合并、不换问。
- 不念屏幕全文（5.5）；图片页先让学生看画面再说话（5.3）。
- 学生预设一律 `〔学生可能说〕`，写成可能而非事实（8.1）；四年级的回答要说四年级的话（8.2）。
- 评价落到具体表现：“你找到了关键句子”“你不仅说想法，还找了依据”（9.1）。
- 一次一问，不把“找句子＋解词＋说感受＋讲道理”堆在一句里（7.2）。
- 过渡从上一个答案里长出来，不喊“进入下一个环节”（12.1）。
- 涉及动物、器材、实验按设计写安全提醒（13.5）。

### 第三段 自检（第六步～第七步）

跑机器校验，再人工过 `script-spec.md` 十九 A–G 七类清单：

```bash
python3 ~/.workbuddy/skills/lesson-transcript/scripts/audit_script.py \
  <源稿.md> --acts acts.json --total 40 --images assets/ppt-第一课时
```

ERROR 全清零才算完成；WARN 逐条判断（playbook 第 4 节）。

### 第四段 交付（第八步～第九步）

- 只交正式稿，不附教学理念、不附设计复述、不附 PPT 建议（十七 输出限制）。
- 未解决的材料冲突单列一段，说明属于设计问题、课件问题还是材料缺失（2.3）。
- 交付话术：页数、总时长、每环节时间、发现的问题、做了什么改动，用表说清。

## 3. 源稿契约（必须长成这样，排版引擎才认）

路径与命名：`.workbuddy/<课文>-<课时段>-逐字稿-源.md`（如 `.workbuddy/牛和鹅-第二课时-逐字稿-源.md`）。
排版成品名由 `lesson-typeset` 自动推导为 `<课文>-<课时段>-逐字稿.docx`，不带课文编号数字。

```
# 20 牛和鹅 · 第二课时 逐字稿          ← 主标题
小学语文 · 四年级上册 · 第二课时（40 分钟）  ← 副标题行
## 使用说明                            ← 固定四段：按课件顺序／行首标记／时间依据／页数对应
### 第二课时　理解认识变化…              ← 课时主题
## 第 1 页 · 封面：理解认识变化｜0:00—0:20   ← 页标题：页码 · 课件页标题｜起—止
〔操作〕出示第 1 页…
师：…
生（齐）：…
〔学生可能说〕…
〔板书〕…
```

| 行首标记 | 渲染 |
|---|---|
| `师：` | 教师台词（最重） |
| `生（齐）：` | 全班齐答／齐读 |
| `生：` | 个别学生 |
| `〔操作〕` | 课堂操作／翻页／巡视 |
| `〔学生可能说〕` | 预设回答，弱化显示 |
| `〔板书〕` | 板书记录 |
| `〔停顿〕` | 等待、思考提示 |

时间写法固定 `0:00—0:20`（半角冒号、全角破折号），不写“约 1 分钟”充当区间。

---

## 4. 时间怎么算（唯一算法）

1. 总长 ＝ 教学设计课时（40 分钟）；先按环节分，再按活动分，最后落到页。
2. 单页时长 ≈ 台词字数 ÷ 4.5 字/秒 ＋ 学生活动时间（默读、圈画、书写、同桌交流都要真给时间）。
3. 页区间首尾相接：上页止 ＝ 下页起；首页 `0:00`，末页止 ＝ 课时长。
4. **正文里自述的“约 N 分钟”必须与页区间一致**——这是最常出现的自相矛盾
   （例：页给 3.5 分钟，正文却写“不要求大家在这五分钟里”）。
5. 一页可以跨同一环节的两个相邻小活动，不许跨两个环节。
6. 时间不够时先砍重复的教师语言和空评价，不砍学生实践，不虚构成“极快节奏”（11.5）。

---

## 5. 只审不改（用户拿已有稿来查时）

1. 先出对读表与问题表，不改文件。
2. 每条问题带位置、现象、依据、建议（playbook 第 7 节）。
3. 用户说“改”再动手；改动只限语言与页内结构，不改变环节、活动、页序与目标。
4. 改完重跑校验，报出页数、总时长、图数三项前后对比。

---

## 6. 交付前最后一屏

- [ ] 页数 ＝ 课件页数，页标题逐页一致，页序无误
- [ ] 时间轴连续、总长＝课时、每页落在设计的活动里
- [ ] 课件每一问都有正面回答；页面清单条数（作业／写字表／自查条）不少
- [ ] 板书条数 ＝ 板书设计图条数
- [ ] 学生预设都带 `〔学生可能说〕`，无“全班都已掌握”式虚判
- [ ] 课文引文与教材逐字一致
- [ ] 交付说明里写清未解决的材料冲突

任何一条不满足，都不算“可直接上课”的稿（`script-spec.md` 二十一、二十二）。
