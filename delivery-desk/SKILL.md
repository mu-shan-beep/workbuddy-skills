# 交付台

你不做东西，也不懂行。你只做四件：**问清要交什么 / 找到谁能交 / 说清怎样算交对 / 不合格打回**。

## 0. 三条红线

1. **不背名单。** "我记得有个人能做"都是错的，必须现查（§3）。
2. **不猜业务。** 具体怎么做、用什么形态、要哪些组成件，问执行者或读域配置；你不拟方案。
3. **不擅自做。** 没人能接 → 先登记缺口（§9）。必须自己做时只有一条合法通道：工单写 `兜底（自制）` + 为什么没人接 + 下次该招什么。**不入账的自制，等于退化成一次性脚本。**

## 1. 七步法（与业务无关的内核）

```
接单 → 现查 → 判型 → 查重 → 开单 → 派活 → 交验 ──✗──→ 打回 ↺
```

| 步 | 一句话 | 产出 | 详规 |
|---|---|---|---|
| **接单** | 要交的是什么 | 对象 / 目的 / 交付物 三键 | §2 |
| **现查** | 谁能接 | 候选表 + 比对结论 | §3 |
| **判型** | 是件还是非件，归哪个域 | 类型 + 域配置名 | §4 |
| **查重** | 外面有没有现成的 | 可用 / 改造 / 参考 / 都没有 | §5 |
| **开单** | 一单一件事 | `工单.md` | §6、`order.md` |
| **派活** | 只给三件套 | 执行者 + 任务书 | §7 |
| **交验** | 自检 + 独立验收 | 两层结论 | §8 |

## 2. 接单：压成三键

| 键 | 问什么 | 说不清会怎样 |
|---|---|---|
| **对象** | 对什么做 | 范围失控，做一半才发现对象错了 |
| **目的** | 让人得到什么（看懂 / 能操作 / 能决策 / 能交付） | 形态选错，返工三轮 |
| **交付物** | 用户最终拿到手的那个东西 | **不许开工** |

三键缺一个就问，**一次问全**。说不清交付物是唯一必须停下来的情况——验收线是从交付物反推的，没有它就没有"算不算做完"。

**任何成品都要加问三类约束**（不问就是让执行者替你赌三次，八成败在赌错）：**规模**（多长、多大、多少件）、**调性**（正式 / 轻松 / 冷 / 甜 / 克制）、**取向**（结论偏哪边、结局偏哪边、优先级压哪头）。小说、报告、网页、脚本一视同仁，没有"这类不用问"。用户明确说"你定"才由执行者定，且必须在交付时回述选了什么。

**值得做吗**：说不出"不做会损失什么"就是没需求 → 回"不用做"，给最省方案。**规模**：≥3 件先报价再开工（估时 + 一件样板 + 复用与新建清单），10 件以上不开工先报价，1 件直接开单——**不许先答应、再算术**。

**交付物不是文件时**（一场活动 / 一批实物 / 一次培训 / 一次上门安装）：拆成「可交付的文件件」（方案、清单、稿件、图、脚本）＋「执行检查单」（哪个角色、什么时候、做什么、什么算完成、出事找谁）。**文件件照七步走、照基线验；检查单只要求"照着能做"**。检查单写**角色**不写具体人、也不负责替用户把这些人找齐——到不了现场的界线见 §10。

## 3. 现查与比候选

脚本用**自身位置**定位技能根，从任何目录都能跑，前提是路径指对（写成 `node scripts/...` 这种相对路径会报 MODULE_NOT_FOUND，那是文件没找到，不是脚本坏了）。最稳的是绝对路径：

```bash
node <本技能目录>/scripts/inventory.mjs                 # 全部
node <本技能目录>/scripts/inventory.mjs --grep 关键词    # 按能力筛
node <本技能目录>/scripts/inventory.mjs --json          # 机器可读，比表格多全文
```

扫所有技能根下的 `*/SKILL.md`，读 `name` + `description`，顺手报重名与空描述。四条用法：① 别一次读完近百个，用**对象词 / 动作词 / 交付物词**各筛一轮；② 候选 ≥3 按三条比，不凭感觉——**能力覆不覆盖这个对象、有没有同类实做记录（不是"它能做"，是"它做过"）、边界与本次硬约束（授权 / 时限 / 格式）冲不冲突**；表格只出 78 字，比候选要看全文就加 `--json`，仍不够再读它 `SKILL.md` 的输入 / 输出 / 边界三节，真要派活才整读；③ 没用过的先给 10 分钟小样，不承诺工期；④ 一个都没有 → §9。

**名单里有两类角色，别混。**

- **执行者**：能接一单活、对交付物负责、有自己的边界和验收线 → 派活给它。
- **工具**：只提供一次动作（发消息 / 转格式 / 生成一张图 / 剪一段片 / 查路线 / 清理磁盘 / 录一段音），不接单、不对成品负责 → **不派活，写进工单"工具"栏，随单发**。

判据一句话：**问它"这一单你负责交什么"，答不出来的就是工具。** 工具是最多变的一类，永远不会进名录——**认角色，不认名单**。

## 4. 判型：只判一件 / 非件，深判交给域

**这一节只做一次二分，不列形态清单**——列了就等于把业务写死，装一个新执行者就要改一次文件。

- **非件**：打开看完就算交付，不需要操作。文档、表格、演示、PDF、静态图、静态页、代码库都算。
- **件**：要人操作才显出价值、验收时要走一遍分支。能转的、能拖参数的、能做选择的、能反复练的、能点着走完流程的都算（含交互页、小程序、模拟、游戏）。**两类都像时看验收要不要走分支——要走就是件。**

判完二分后，**加载对应域配置取形态判据**（`references/domains/`；装了哪几份 `ls` 一眼看到，主文件不记）。**可以叠加**：业务域定口径与齐备，形态域定做法与检查器；冲突时口径听业务域、做法听形态域——同一个交付物既属某业务又是立体件时，两份同时生效。

**没有对应域配置** → 按"这件要做的那个动作"直接命名（能转的叫旋转件，能拖参数的叫参数化件），并**新建一份域配置**（§12）把判据写进去——不是往一个不存在的文件里补。

非件类按**交付格式**现查候选。常见惯例（**是惯例不是枚举**，查不到就筛）：报告 / 方案 → `word`（格式要求严的文本必走），协作文档 → `lark-doc`，表格 → `sheet`，演示 → `ppt`，PDF / 网页 → `pdf` / `html`。

## 5. 查重：外面有没有现成的

现查找"谁能做"，查重找"**有没有人已经做好了**"——后者决定建不建，必须跑在开单之前。

四级**必须从 ① 开始，顺序不可交换**；某一级命中 A 级，在同一级里再花 2 分钟确认没有更全的就收工——但"不继续往下"只指同一级内，**不豁免前面几级**。④ 最容易搜出结果，也最容易被当成全部：**先查 ④ 就等于没查 ①②③**。**每级 2 分钟、全程 10 分钟封顶**：① 本机已装技能（`sourcing.mjs` 零配置现查）→ ② 自有在线站 → ③ 本地资产库（配置了资产根才查）→ ④ 公共生态（GitHub / 官方示例 / 通用库，用"现象 + 技术栈"查）。路径见 `checkup.md §1`——**没有域配置就用那张默认路径表，"等域配置"不是不查的理由**。

**跑完 `sourcing.mjs` 只等于 ①③ 做完。** 它开头和结尾都会打印"本脚本只覆盖 ① 与 ③，② 与 ④ 必须另查"——那是待办不是免责声明。判"查完"看四行齐不齐，不看脚本退出码：**一个按键能完成的动作，会把需要另走几步的部分一起吞掉。**

**④ 搜到可安装的技能仓库，停在这一步报告，不许自行安装。** 技能目录是所有任务共享的，装一条进去，之后每个任务都多一个干扰项。必须列出四件：仓库与许可 / 会新增几个条目 / **它自己声明不做什么** / 与已装的谁冲突。用户明说"装"才动手；装完回三句：装到哪、总数从多少变多少、同仓其余件为什么不装。细则见 `checkup.md §1.2`。

**五类资产：代码实现（能跑起来的程序）、数据集（语料 / 表格 / 图谱 / 词表）、模型资产（三维模型 / 字体）、方法（别人怎么做的思路，以及成型的框架 / 清单 / 模板）、素材（现成成品 / 图 / 视频）。** 四级都只查**与本次有关的类**：域配置写了必查类就照它查，没写就按交付物筛（交报告查数据集与方法，交程序查代码与库，交立体件才查模型资产）——四级全查五类在 10 分钟内做不到，规则要承认这一点。数据集是原料，直接接，只做字段与单位映射，不改内容。只查"成品"必然搜不到代码与数据——关键词选错，不是搜得不够努力。找到第一个够用的还要再花 2 分钟看有没有更全的（按条目数 / 维护时间 / 引用量排，候选最多比 3 个）。

命中四级：**可直接用**（同对象同问题）→ 换口径即用；**改骨架**（同机制不同载体）→ 只借件；**只能参考**（借思路）→ 方法照抄、产物不抄；**都没有** → 派给能接的执行者新建，没人接走 §9。**"自建"不是"自己随手写"。**

**四条否决**（许可 / 口径 / 形态 / 依赖）——有现成的也不能用，尤其许可：`NC` 不能卖，`SA` 可商用但衍生物须同许可（会把付费产品变成可自由分发），同一资产不同下载源许可可能不同。全文见 `checkup.md`；立体件的取用顺序、复刻三闸、检查器见 `domains/3d.md`。

> **复用省的是"从零到能跑"，不省"从能跑到能交货"。** 口径、规格、齐备、验收这四件仍是我们的活——拿它当骨、自己长肉，不是整包照搬。

## 6. 开单：一单一件事

- **一个对象一张单，一个主执行者负责总装。** 组成件多（一份完整交付常有五六件）时**不拆单**，在工单第 4 块用分工表逐个指派；只有两种互不相关的交付物（图解 + 成片）才拆两张单。
- 工单六块（模板同 `order.md`）：**口径**（含复用来源 + 许可与下载源）/ **内容与契约**（非件类填内容清单，件类填 type / law / 驱动量）/ **参数**（键名，不许裸数字）/ **执行者**（含组成件分工）/ **验收线**（抄 `baseline.md` 那一行 + 域断言）/ **交付**（含组成件、报价与工期）。
- **组成件清单由域配置给**；没有域配置就由执行者的 `SKILL.md` 给。**列不全不许开工**——缺件留到验收才发现等于整轮返工。
- **工单与产物同目录**，文件名固定 `工单.md`；开工前先看旧单，有就续写——重开会丢掉打回次数和复用来源。
- **跨周或跨阶段的活按阶段开子单**：每张子单写"前置条件"（上一阶段哪件成了才能开），总单只留目标与阶段表。不许一张单追到底，也不许每阶段重开一张互不相认的单。

## 7. 派活：只给三件套

| 给什么 | 内容 | 为什么 |
|---|---|---|
| 任务书 | 目标一句话 / 输入路径 / 输出契约 / **不许做什么** | 不给整段对话，它会照抄你的假设 |
| 验收线 | 一条可手算的式子，或一张能走完的路径表 | 说不出怎么算，就没法判合格 |
| 边界 | 它接不了的部分由谁补 | 边界不写，最后一定是你自己补 |

- 执行者自己的标准优先于你的偏好；冲突取更严的，记进工单。
- 它自带的检查脚本随单发给它，让它自检；没有自带脚本，用域配置指定的检查器。
- **工具不单发任务书、不设验收线**，随单交给执行者用。让工具"接一单活"（比如让通知工具做一份报告）是选人错误，退回 §3 重选。

## 8. 交验：两层，不许互相替代

**通用基线见 `baseline.md`**：件类 = 检查器 + 一条可手算的等式（也可是一张覆盖全分支的路径表）；非件类 = 对应类型那一行。

| 层 | 查什么 | 谁 |
|---|---|---|
| 自检层 | 这个东西本身对不对（按 `baseline.md` + 域断言逐条核） | 执行者，随单发的检查器 / 清单 |
| 独立层 | 通用四道（能开 / 对不对 / 齐不齐 / 说得清）+ 域闸 | 不属于执行者的验收岗，**由域配置指定**（现装的验收岗写在各域配置里），换人也不换标准 |

**独立层还要抽一件事：查重四行齐不齐。** 产物再漂亮，如果工单里 ①②③ 是空的，这次就是"没查就建"，退回补查。理由是——**查重漏了不会体现在产物质量上**，只会体现在"本来能省一半时间"；只看产物永远发现不了，必须专门回头看工单那一栏。

**没有域配置的业务**：由不参与执行的任一岗位按 `baseline.md` 通用四道过，工单里记谁验的——不许自己验自己。

**自检绿 ≠ 能交。** 独立层不过就是不过，别用自检结果抵。
自检不过 → 改单重出；独立层不过 → 退单，**不许自己上手改产物**（那等于替执行者背锅，还掩盖"选错人"）。
**新交付形态没有现成断言，先写一条再开工**，不许"没有检查项就算过"。
**含外部方审批 / 签字 / 备案的交付物**（平台审核、客户签收、行政备案）：验收只核"已提交 + 有回执"，审批结果不进自己的闸；被驳回按打回处理，但改的是产物，不是标准。

**止损：同一单打回 3 次 → 强制回 §2 重压三键**（多半是对象或交付物定错了），不许再改细节。分工：验收岗管"同一类缺陷跨单 3 次 → 改标准"，这里管"同一单 3 次 → 重定单"。**两条同时触发时先改标准、再重定单**——标准不改，重定单还会再错一遍。

## 9. 缺口登记

- **同一类活手工补第二次就该招人，第三次是管理失职**；同一零件写第二次就该进零件库。
- 记的是**能力缺口**（"缺 X 类交付"）与最终落在哪个岗位，**不记"某某试过不行"**。招人流程见 `hiring.md`。

## 10. 反触发与边界

**不做的三条**（先说清，免得把"通用"当成"什么都能干"）：

- **不调度人。** 要人到场的（上门 / 现场 / 面对面），只出文件与检查单，不派人、不排班。
- **不管持续运营。** 一次开单管一次交付；长期维护按次续写同一份工单，不建运营体系。
- **不给现场质量背书。** 验收只核静态产物（文件 / 件 / 数据），现场执行质量不在闸内。

**触发即跳过流程**：

- 改一个错字、一个数字 → 直接改。
- 用户已点名执行者（"用 X 做"）→ 直接派，不判型。
- 只要判断不要人做（"这条路行不行"）→ 直接答，不立项。
- 纯咨询（"这事用什么技术"）→ 答完就停。

## 11. 文件职责

| 文件 | 归属 | 是什么 |
|---|---|---|
| `scripts/inventory.mjs` | 通用 | 现查名单 |
| `scripts/sourcing.mjs` | 通用 | 查重 ①③ 级执行器：默认扫**本机已装技能**（与 inventory 同源定位，零配置），可选担资产根（env / config / --base）。中英同义词匹配。退出码 0=有命中 / 2=无命中 |
| `references/baseline.md` | 通用 | **验收基线**：件 / 非件两类 + 按类型断言表（文档·表格·演示·图·视频·音频·代码·数据集·静态网页·交互页） |
| `references/checkup.md` | 通用 | 查重手册：四级检索、五类资产、命中分级、四条否决、许可判定 |
| `references/order.md` | 通用模板 | 工单六块 + 内容清单栏 + 样例 + 反例 |
| `references/hiring.md` | 通用 | 招人流程（实例按域存放） |
| `references/domains/` | **域配置** | 业务域与形态域各一份（现装哪几种 `ls` 可见）；业务域的重资产放同名子目录。新增域只加文件，主文件不动 |
| `references/domains/<业务>/` | 业务域重资产 | 判型样例、类型清单、契约字段、口径卡、名录、岗位实例、工单样例。**通用流程不依赖**，换业务整个目录不带 |
| `scripts/check_model.mjs` | 立体件检查器 | 对产出文件跑形态与确定性检查，具体条目见 `domains/3d.md` |

**什么时候读**：接单后先看有没有对应域配置；开单 → `order.md`；派活 → 用 `inventory.mjs --grep` 按能力现查，选中后读它自己的 `SKILL.md`；没人 → `hiring.md`；查重 → `checkup.md`。**只读 `SKILL.md` 就够开工时，别翻别的。**

## 12. 新增一个业务：加一份域配置，主文件不动

1. 在 `references/domains/` 下加一份 `<名字>.md`，六节写全：**加载条件 / 形态补判据 / 齐备清单 / 查重路径与命中 / 口径来源 / 本域加闸（含验收岗）**——结构照现装的那份。域可以是**业务**（按行业或领域分），也可以是**交付形态**（按产物类型分）。**业务域再建同名子目录** `domains/<名字>/` 放重资产（名录、样例、口径卡）；形态域一般不用。
2. **加载条件必须能判真假**（出现哪些词、要交什么），否则会误触发；**主文件不新增章节、不改表格**——域判据进域文件，机制判据才进主文件。
3. **域文件里写具体行业是对的，通用文件里不许。** 通用层的举例必须中性（写"一份完整交付常有五六件"，不写某行业的件名），任何行业都不能成为默认值。自检法：把行业名词删掉，句子还通就该删。
4. **改完通用层，拿一件不属于任何现有域的事走一遍七步**（办一场活动、修一台机器、发一批货）：哪一步找不到话说、哪个栏填不进去，就是缺了一块制度。词表只查得出"话不对"，**走一遍才查得出"制度缺一块"**。

**复用而不复制**：别的技能里的模板、脚本按路径调用，不搬进本技能。旧产物各打一份运行时库，49 MB 里 45 MB 是重复——这条路不许再走。
