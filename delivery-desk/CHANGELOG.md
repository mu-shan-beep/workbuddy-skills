## v25（2026-11-27）

**与机器解绑：资产根不再依赖作者的盘符路径。**

**问题**：`sourcing.mjs` 的兜底资产根硬编码了 `E:/shizb_private/tongjiang` 等作者机器路径；`checkup.md §1`、`domains/teaching.md` 的默认路径表也写死同样路径。装到任何别的机器，兜底永远落空，只能靠 `--base` 每次手敲。

**改法**：资产根解析改为六级顺序，全部与机器无关——

1. `--base` 参数（原有）
2. 环境变量 `DELIVERY_DESK_ASSETS`（新增）
3. 技能目录下 `config.json` 的 `assetsRoot`（新增；模板见 `config.example.json`，config 属机器本地配置，换机器重填即可）
4. 从当前目录向上找（原有）
5. 从技能自身位置向上找（新增——不管 cwd 在哪都能跑）
6. 都找不到 → 退出码 3，报错信息改为给出上述三种指定方法

`catalog` 扫描同步泛化：不再只认 `tongjiang-lab`，自动找根级或任一子目录的 `catalog.json`，库名可由 `config.catalogPath` / `config.sourcesDir` 覆盖。文档三处（`checkup.md §1`、`domains/teaching.md §4`、`teaching/routing.md` 示例 URL）的写死路径全部改为引用解析顺序，`grep` 复查零残留。

**验证**：从无关目录跑（技能位置自寻命中）、隔离环境无资产根（exit 3 + 指引正确）、config.json 指定（命中）、环境变量指定（命中）、无命中（exit 2）、`inventory.mjs` 复查正常——六条路径全过。

## v24（2026-11-27）

**改名：`model-director` → `delivery-desk`（中文：交付台）。**

原名的 `model-` 前缀来自它最早的服务对象（零件库 `model-parts` / `model-electric`）。但它早就不只管模型——文档、网页、剧本、活动都走它。名字留着，每换一个领域都要先解释一遍"这不是只管模型的"，等于每次都在给"通用"打折。

**选名理由**：它做的是"接进来、分出去、验完放行"，这是台面的动作，不是工厂的动作。`desk` 自带"我不生产，我只转办"，正好对上三条红线的第一条。

**同步范围**：目录名、`name` 字段、6 个文件 15 处引用（`qa-inspector` 5、`model-parts` 4、`model-electric` 2、`form-scout` 1、`lesson-architect` 1、`teaching/roster.md` 1），删掉 SKILL.md 顶部"名字沿用 model-director 是历史包袱"那句。

**过程里的坑**：改完 `name` 字段，系统按新名生成了一个目录，旧目录仍在——一时出现两份，文件清单完全一致，只能靠 `name` 字段与内容版本区分。更麻烦的是，**删掉旧目录后它被自动重建了一次**（16:49，20 个文件原样回来），第二次删除才稳定。所以规矩要加一条：**删完不能只看返回码，要隔几秒再查一次 `Test-Path`，两次都为空才算删掉。**

**验证**：`inventory` total=98、problems=0；`model-director` 残留引用 0 处；目录只剩 `delivery-desk`。

## v23（2026-11-27）

**问题**：装一个外部技能会得到两份内容——`_skill-sources` 里的 git 仓库原件，和 `.user_skills` 里的副本。改一处，另一处不同步。v22 就踩到了：给 `academic-paper` 补简体触发词，只改了副本，资产库原件仍是繁体「論文」，当时靠同义词表临时兜住——那是补丁。

**为什么不能直接链过去**：技能根在 C 盘，项目在 E 盘。Windows 的目录 junction 不支持跨卷，symlink 要管理员权限且跨盘不可靠。物理上做不到"一份文件两个位置"。

**改法：技能目录只留入口，正文单份留在资产库。**

- `.user_skills/<name>/SKILL.md` 约 2 KB，只写三块：真源绝对路径 + 安装时 commit、执行时读哪份 / 跑哪个脚本（一律绝对路径）、更新方法
- 不再复制 `references / scripts / shared / templates`
- `novel-script` 的脚本用真源绝对路径调用；`{baseDir}` 指向真源，不指入口——写错这一处，脚本会去入口目录找不存在的 `scripts/`

**效果**：`academic-paper` 2.8 MB → 2 KB；`novel-script` 约 285 KB → 2 KB。真源 `git pull` 后入口自动读到新内容，不存在"同步"这件事。

**验证**：`inventory --grep 论文 剧本` 两个都在；`node <真源>\scripts\novel-script.mjs validate <剧本>` 仍返回 178.3s / 180s 全过。

**代价**：调用多一跳（读入口 → 读真源）；上游若改目录结构，要手工改入口里的路径表。

## v22（2026-11-27）

这一版修两件事：**写了规则却没被执行**，和更隐蔽的**装了却搜不到**。

**触发逻辑换掉了枚举。** description 原来靠罗列任务名（做方案 / 写策划 / 做课件 / 写小说…）。枚举任务名本身就是限制：加十个还漏第十一个（写悼词、写招商函、写产品说明）。改成**一条判据 + 形态作桥**——判据是"用户要的是一个成品，不是一句回答"，形态用它自己的封闭集（文本 / 表格 / 图示 / 页面 / 音视频 / 实物 / 活动 / 系统）。任务名是开放集，形态是封闭集，后者才收得住。

**§2 从"创作类加问三项"改成"任何成品都问三类约束"**：规模、调性、取向。原来那条也是枚举——它对报告、网页、脚本同样成立，不问照样返工。

**查重补上 ④ 的硬约束**（`checkup §1`）：④ 必须真打开搜一次，不许用 ①③ 的脚本结果代替。新增 **§1.1「脚本只扫 ①③，跑完不等于查完」**——判据从"脚本退出码"改成"四行齐不齐"，因为**一个按键能完成的动作，会把需要另走几步的部分一起吞掉**。`§8` 工单加"④ 检索与安装"必填行，没写视为 ④ 没查。

**安装权收回用户**（`checkup §1.2`）：搜到可装的技能仓库，停在报告这一步，必列四件——仓库与许可 / 会新增几个条目 / **它自己声明不做什么** / 与已装的谁冲突。用户说装才装，装完回三句。没有批准就装，等于用一次任务的口头授权去改所有任务的环境。

**`sourcing.mjs` 两处修**：
- **块标量解析 bug**：`description: |` 被正则读成一个竖线，等于这条技能没有描述。`novel-script` 正是这种写法，搜「剧本」0 命中；修后 3 条。这是"装了不代表能被看见"。
- 待办提醒原来**只在 0 命中时打印**，命中时反而不提——最容易被当成查完的时刻恰恰没有提醒。现在开头和结尾都打。`HEAD_LINES` 40→90，避免长 frontmatter 被截。

**`inventory.mjs`**：`--grep` 支持空格分词（OR），与"用几个词各筛一轮"的用法对齐。

**新增技能 `novel-script`**（Apache-2.0，来自 `eternityspring/shuohao-skills`，经用户批准安装）：竖屏短剧剧本，分集 / 场次 / 节拍流 + 10 道确定性校验。同仓其余六件未装。

## v21（2026-11-27）

改的是 **description 的触发力**——它一直是"机制语言"，用户说的是"任务语言"，两者没有交点，所以唤不起来。

**旧**：「调度官（通用，与业务无关）。任何要产出交付物的需求……先跑 inventory.mjs 现查、压成三键、判件/非件、加载域配置、开单、派活、定验收线……」——全是内部术语，还把执行细节顶在最前，占掉最值钱的前 60 字。

**一条必须记住的边界**：description 只能提高"被想起"的概率，保证不了"被读"。这次的策划案就是例子——**我"按流程做了"，但没有真的打开这个文件**。触发与执行是两件事，前者靠描述，后者靠有没有真读。

| # | 原文 | 为什么会跳 |
|---|---|---|
| 1 | "各级的具体路径**由域配置给**"（`checkup.md §1`）、"各级在哪个路径，**域配置里写**"（`SKILL §5`） | 新业务没有域配置 → **没有路径 → ①无从查起 → 直接跳 ④**。硬伤：查重路径挂在一个可能不存在的文件上 |

**这一版真正的教训**：规则写得再对，只要**没有"缺了就报错"的检查点**，它就会被合法地绕过。前十八版一直在改"说什么"，这一版改的是"少了什么会被拦住"。
