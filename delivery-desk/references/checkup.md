# 查重手册：先看外面有没有，再决定建不建

侦察查的是"**谁能做**"，查重查的是"**有没有人已经做好了**"。两件事不能互相替代——后者决定"建不建"，必须在派活之前跑。承包商接到单时已经决定建了，那时的检索只能省力，省不了这笔账。

> 下文例子取自现装的域（不止一个行业）。**规则看条文，例子只看形状**——换业务时例子要换，条文不用改。各域的具体路径见 `domains/<业务>.md`。

---

## 1. 四级检索（必须从 ① 开始；顺序不可交换）

**每级 2 分钟、全流程 10 分钟封顶**；四级都空就记 C，不纠缠——查重是为了省事，不是考证。

| 级 | 查哪儿 | 怎么查 | 没有域配置时的默认路径 |
|---|---|---|---|
| ① 本地自有 | **本机已安装技能**（技能即现成的可复用资产） | `node scripts/sourcing.mjs --grep 关键词` —— 技能根自动定位，零配置；或 `node scripts/inventory.mjs --grep 关键词` 看名录 | 同左，零配置即用 |
| ② 自有在线 | 自己发布过的站点 | 按主题分页找同题 | 没有就记 `N/A + 理由`，不许留空 |
| ③ 本地资产 | 已配置的本地资产库（样课 / 数据集 / 已拆开源库等） | 有资产根才查：`sourcing.mjs --grep` 会一并扫 `DELIVERY_DESK_ASSETS` / `config.json` / `--base` 指定的目录树；**未配置就记 `N/A + 未配置`** |
| ④ 公共生态 | GitHub / 官方示例 / 通用库 | 用"现象 + 技术栈"查，不用行业泛词；**必须真的打开搜一次，不许用 ①③ 的脚本结果代替** | `github.com/search` + 官方文档 |

**不绑定任何技能名或资产库名。** 本机有什么就查什么——换一台电脑，`inventory.mjs` / `sourcing.mjs` 现扫现得，名单永远现算不背书。想额外挂一个本地资产库，三选一：环境变量 `DELIVERY_DESK_ASSETS`、技能目录下 `config.json` 的 `assetsRoot`（模板见 `config.example.json`）、临时 `--base` 参数。

**顺序不可交换。** ④ 最容易搜出结果，也最容易被当成全部——**先查 ④ 就等于没查 ①②③**。任何一级命中，都不豁免前面几级。

**路径优先级**：域配置写了就用域配置的（见 `domains/<业务>.md` 第 4 节）；**没有域配置，直接用上表右列**。**"等域配置"是跳过查重最常见的借口**，遇到就按右列查。

### 1.1 脚本只扫 ①③，跑完不等于查完

`node scripts/sourcing.mjs` 的覆盖面就是 ① 与 ③。它开头和结尾都会打印"本脚本只覆盖 ① 与 ③，② 与 ④ 必须另查"——**那两行不是免责声明，是待办**。

跑完脚本就当查完，是查重漏检最常见的样子：**一个按键能完成的动作，会把需要另走几步的部分一起吞掉。** 脚本给了一个"已完成"的手感，人就默认整件事做完了。

所以判"查完"的标准是四行齐，不是脚本退出码：

- ① 脚本命中数
- ② 有站就查、没站写 `N/A + 理由`
- ③ 脚本命中数
- ④ 检索词 + 实际打开过哪些仓库 + 命中数

### 1.2 找到能装的，不许自己装

检索是"看"，安装是"改状态"。技能目录被所有任务共享，装错一个，之后每个任务都会多一个干扰项，而且用户不会知道它是哪来的。

④ 搜到可安装的技能仓库时，**停在报告这一步**，把四件事摆给用户：

1. **仓库地址与许可**（MIT / Apache-2.0 / 无证 / 仅研究）
2. **会新增几个技能条目**（整包几个，还是只挑其中一件）
3. **覆盖什么、不覆盖什么**——必须写出它自己声明"不做"的事，那往往是关键
4. **与已装的哪个重复或冲突**

**用户明确说"装"才装。** 装完要回三句：装到哪个目录、技能总数从多少变成多少、同仓其余件为什么不装。

没有人批准就装，等于用一次任务的口头授权去改所有任务的环境。

## 2. 深度规则：够用之后再看 2 分钟

**找到第一个"够用"的，在**同一级**里再花 2 分钟看有没有更全的**——更全的就换，没有就用第一个。注意"不继续往下走"**只指同一级内部**，不适用于跨级：③ 里找到够用的，仍然要回头看 ① 查没查过。按三条排：**结构 / 条目数、最近维护时间、被引用量**。候选最多比 3 个，选最全的开工。

要的是"没漏掉明显更好的"，不是穷尽——搜到第三个还有第四个，就叫失控。**"更好"必须能一句话说清好在哪**（结构数 / 维护 / 引用），说不清就不算更好。

> 实测教训（2026-11-27）：只搜到第一个够用的来源就动手，事后发现漏了一个更全的（条目数是前一个的 5 倍，还补上了前一个缺的部分），并因此误判"那类内容没有独立资源"。
> **"够用"是陷阱，更好的往往就在下一页。**

## 3. 五类资产：查什么，不是查哪儿

每一级里都要查五类，不是只查"同题成品"：

| 类 | 是什么 | 例 | 能直接用吗 |
|---|---|---|---|
| **代码实现** | 一个可运行的程序文件 | 公开仓库里的示例项目 | 高：多为 MIT，拷进来改口径与文案 |
| **数据集** | 语料 / 表格 / 图谱 / 地理气象 / 词表 | 公开语料、行政区划、行业词表、统计年鉴 | **最高：它就是原料，直接接** |
| **模型资产** | 可导入的三维文件 / 字体 | 公开模型库、机构开放资源 | 高：能导入就直接用，形状改不了 |
| **方法** | 别人怎么做的思路，以及成型的框架 / 清单 / 模板 | 技术博客、论文、README、成熟的方法库（发布管理、分析框架、议事流程等） | **不只是学**：框架、清单、判决标准可直接套用，改名词即可 |
| **素材** | 现成成品 / 图 / 视频 | 素材站、图库、成品市场 | 看许可，最易被误当自有 |

**"直接用"对数据集的意思是：不改内容，只改接口。** 字段映射、单位换算、编码转换（GBK→UTF-8）、去重补缺——这些是接入，不是改编。只有成品素材才谈"改编"。

**接入前核三件，核的不是"能不能改"：**

1. **许可与用途**：CC0 随意 / CC BY 署名 / NC 不能卖 / "仅限研究"不能进付费产品 / 无许可只能内部验证、不对外分发。
2. **口径与版本**：同名字段不同年份会换定义（行政区划代码、行业词表、统计口径）。用哪一版写进工单。
3. **质量与格式**：条目数、缺失率、编码、主键唯一性、要不要清洗。

这三条是**用前核对**，核完照样直接接——不是"因为有坑所以不用"。

只查"同题成品"是最浅的一层：结构在**代码实现**和**模型资产**里，数据在**数据集**里，做法在**方法**里，这几类都不叫"成品"——用"成品""方案""模板"这类交付词当关键词，必然搜不到。

## 4. 命中分级

判据是**同对象 + 同问题 + 同关键变量**——三者全中才算 A：

| 级 | 命中什么 | 做法 |
|---|---|---|
| **A** | 同对象 + 同问题 + 同关键变量 | 复刻骨架与做法，换本业务口径与文案 |
| **B** | 同机制、不同载体 | 只借件：手法 / 配色 / 结构 / 节奏 |
| **C** | 都对不上 | 记"没有现成可复用的"，走 §9 末的缺口或直接开单新建 |

**"自建"不是"自己随手写"。**

三个词在各业务里怎么落地，由域配置翻译（示范见现装业务域的 §4，它把三个词各写成一句可判断的话）。**通用层不给行业解释，否则换业务就得改这里。**

**非件类（文档 / 表格 / 演示 / 视频）不套这个分级。** 它的查重只有一问：**有没有现成模板或同类范例**（模板库、往届成品、同类案例）。命中改模板，不命中从空白起——别拿"同对象 + 关键变量"去套一张报表。

## 5. 四条否决：有现成的也不能用

### 5.1 许可——不只看"能不能用"，要看"用了之后你的东西变成什么"

- `NC`（CC BY-NC 等）→ **不能卖**，只能非商业用途。
- `SA`（CC BY-SA 等）→ 可以卖，但**改编后必须同许可发布**。把 SA 资产合并进交付物，整个交付物可能被要求 CC BY-SA——付费产品变成可自由分发的。要卖先判"合并还是聚合"（由验收岗或许可审查岗判断，本机没有该岗位就人工判）。
- 无 LICENSE → 只借思路，不搬文件。
- **同一个资产，不同来源页的许可标注可能不同**（仓库页写 BY-SA，发布页写 BY；有的官网标 "Commercial: No"）。**以你实际点下载的那个页面为准**，截图存档。省这一步，后面全是扯皮。

### 5.2 口径
国外标准、旧版规范、别的场景的设定值，不能连数值一起抄。（例：同一常数在不同年代、不同标准里的取值不同，差一档就错。）

### 5.3 形态
要能操作，它只能看；要立体的，它是平面的。

### 5.4 依赖
为一个不起眼的效果引入 200 KB 依赖，不划算。

## 6. 载体专属规则：别当通用规则用

有些规则只对一种载体成立，写进通用层就会在别处误用。它们各自的去处：

| 交付载体 | 去哪儿看 |
|---|---|
| 立体件（能转 / 能剖） | `domains/3d.md`：先代码后模型、复刻三闸、检查器 |
| 视频 / 成片 | 通用底线见 `baseline.md §2`；素材取用规则由业务域给，没有就只过基线 |
| 文档 / 表格 / 演示 | 只有"模板与范例"一条查重，见 §4 末段 |

**通用层只写"什么情况下该去看哪份"，不写具体载体怎么做。**

## 7. 复用的正确姿势

> **复用省的是"从零到能跑"，不省"从能跑到能交付"。**

开源件基本停在"能跑"——口径、可用性、齐备、验收这四件仍然是我们的活。所以正确姿势是**拿它当骨、自己长肉**，不是整包照搬。

对应到许可审查的通用判词：**去掉具体表达之后还剩什么，剩下的就是你能合法学的。** 拆分方式、分组、配色语义、简化策略可以学；具体的模型数据、材质、命名表不能碰。

## 8. 工单怎么记

- **复用来源**：`仓库 @commit` + 许可 + 改了什么。A/B 写清来源，C 写"①②③④ 均无命中"。
- **④ 检索与安装**：检索词 · 实际看过哪些仓库 · 命中几条 · `已装（谁批的）` 或 `仅报告未装`。没写这行的，视为 ④ 没查。
- **许可与下载源**：`<NC / SA / BY / 无证>` · 实际下载页 URL · 抓取日期（SA 类必须写"合并还是聚合"的结论）。
- 没写查重结论的工单，视为没查重；**逐级四行缺一行的，同样视为没查重**——"四级均无命中"五个字不是结论，是省略。
- **现查结果的数字是快照，不是承诺**：技能根会因安装 / 卸载 / 重挂载而增减，同一天跑两次就可能差一两个。拿它判断"该派给谁"，不拿它当固定总数核对——真要核对，先跑两次看是否一致。
