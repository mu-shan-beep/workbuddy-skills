# 验收基线：所有交付物先过这一层

域配置可以加更严的闸，但**不能代替这一层**。基线不过，域断言再漂亮也不算交。

## 1. 先分两类

| 类 | 基线怎么过 |
|---|---|
| **件**（能转 / 能拖 / 能选 / 能练 / 能点着走完） | 一条可手算的等式（可建模的件），或一张覆盖全分支的路径表（流程类件），加一个检查器。检查器由域配置指定；没有就按域断言逐条人工核 |
| **非件**（文档 / 表格 / 演示 / 图 / 视频 / 静态页） | 下面那张表，对应那一行逐条人工核 |

**两层用同一张表，但不做同一件事**：自检层把全表逐条核一遍；独立层**不重做逐条核**——只做两件：抽查 3 条最易错的（版心 / 合计 / 页数这类），再换一个视角看整体能不能交。重复逐条核是同一件事做两遍，还让人误以为有两道保险。

**不碰"件"的业务，只看第 2 节就够。** 等式与检查器是件类的门槛；非件类没有公式，按类型那一行逐条核即可——文档、报表、方案不需要"可手算的等式"这种东西。

## 2. 按类型取断言（选本类型那一行，抄进工单"验收线"；交互类虽属件，没有检查器时也查这里）

| 类型 | 最小断言（可手验） |
|---|---|
| **文档**（报告 / 方案 / 说明书 / 记录） | 版心统一、页码连续、字体族 ≤2、标题层级不乱 |
| **表格**（报表 / 清单 / 登记表） | 表头与单位齐全、合计数能对上、无"未标注的空格"、数字格式一致 |
| **演示**（幻灯片 / 放映文件） | 实际页数 = 大纲页数、母版统一、1366×768 下正文等效 ≥16px |
| **图**（插图 / 信息图 / 示意图） | 导出尺寸对用途、文字无裁切、色值符合指定色板、无低分辨率位图 |
| **视频**（成片 / 解说 / 短片） | 时长与稿相符、字幕与音轨偏差 ≤0.2 s、无静音断档 |
| **音频**（解说 / 录音 / 配音） | 时长与稿相符、无爆音削波、底噪可接受、字幕（若有）与音轨对齐 |
| **代码 / 脚本 / 系统** | 干净环境按 README 能跑、无硬编码路径与密钥、示例输入有预期输出 |
| **数据集**（清洗后的表 / 语料） | 字段说明齐全、主键唯一、缺失率已标注、编码统一（UTF-8）、附来源与许可 |
| **网页（静态）** | 断网能打开（或写清依赖）、无死链、字体与图不丢 |
| **交互页 / 小程序（件）** | 全部分支可走到结局、重置无残留、断网有降级提示、返回不迷路 |

**这是底线，不是上限。** 执行者或域配置有更严标准时，取更严的那条，记进工单。

## 3. 这笔债要认

**这张表目前全是人工断言，没有自动检查器。** 只有立体件有 `scripts/check_model.mjs` 能一键跑。

哪一类做到第三件，就该给它写一个 checker。在那之前，**不许对外说"这类有闸"**——人工核也是核，但要写"已逐条人工核"，不能说"自动通过"。

## 4. 升级规则

| 情况 | 做法 |
|---|---|
| 某类型第一次做 | 用上面那一行，人工核，把核对记录随验收单交 |
| 同一类型做到第三件 | 停下，给它写检查器（脚本或清单），写进域配置 |
| 先写哪个 | 按「已交付件数 × 出错次数」排，不按类型重要程度排——做得多、错得多的先写，那才是漏得最狠的地方 |
| 域配置给了更细的断言 | 直接替换本表对应那一行，不叠加两套 |
| 交付物不属于以上任何一类 | **先定义一条断言再开工**，不许"没有检查项就算过" |
