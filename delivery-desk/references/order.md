# 工单：派活的唯一凭据

没有工单就没有交付。工单的作用不是记录，是**在动手之前把三件事钉死**：做什么、谁来做、做成什么样算合格。

## 一、模板（复制这一份）

```markdown
# 工单 TJ-YYYYMMDD-NN

## 1 口径
- 对象：对什么做（一份报告 / 一套方案 / 一组数据 / 一段素材）
- 目的：让人得到什么（看懂 / 能操作 / 能决策 / 能交付）
- 交付物：用户最终拿到手的那个东西（格式 + 数量 + 用途）
- 受众与场景：谁用、在什么场合用（决定尺寸 / 时长 / 精度 / 字号）
- 截止：什么时候必须交到手上（没有就写"无硬期限"）——估时是工作量，不是交期；有日历日期的活（活动、申报、上线、交付节点）必填
- 复用来源（查重结论，**逐级写，四行缺一行不许开单**）：
  - ① 本地技能：`<贴 sourcing.mjs 技能命中摘要，或写明翻了哪份名录 → 结论>`
  - ② 自有在线：`<查了什么 → 结论>` / `N/A：<理由>`
  - ③ 本地资产：`<贴 sourcing.mjs 资产命中摘要 → 结论>` / `N/A：未配置资产根`
  - ④ 公共生态：`<查了什么 → 结论>`
  - 采用哪一级：可直接用 `<仓库 @commit>` / 改骨架 `<改了什么>` / 只参考 / 四级均无命中
- 许可与下载源：`<NC / SA / BY / MIT / 无证>` · 实际下载页 `<URL>` · 抓取 `<日期>`

## 2 内容与契约
**非"件"类：只填第一行，下面六行整块写 N/A 并说明理由。件类：不填第一行；下面六项按需填，不适用的写 N/A 并说明**——可建模的件必有 law 与驱动量；流程类件（走分支、有状态）通常没有等式，改在 steps 里写清状态与分叉。
- 内容清单（非件类必填）：要包含哪些章节 / 页面 / 段落 / 镜头，各占多少篇幅或时长
- type（域配置给的可选值）：
- kernel（符号/闭式/数值/状态机/统计）+ 精度：
- carrier（域配置给的可选值）+ 一句"用它干什么"：
- law（必守律）+ 怎么验（一条能手算的等式；可建模的件必填）：
- 驱动量（**有且只有一个**；流程类件写"无"）：
- steps：3–8 步，每步 act / expect / concl

## 3 参数（只写口径卡键名 = 值）
| 键 | 值 | 出处 |
|---|---|---|

## 4 执行者
- 主执行者（负责总装与交付）：`<名录里的名字>` / `兜底（自制）`
- 选它的理由（三条比对：能力覆盖 / 同类实做 / 边界不冲突）：
- 交付前必须重读：`<它的 SKILL.md>` + `<相关 references>`
- **工具**（不接单，只提供动作；随单发给执行者用）：发消息 / 生成图 / 转码 / 查路线 / 录音 …，写"名字 + 用来干什么"
- **组成件分工**（组成件 ≥2 时必填，单件可省；主执行者仍只有一个，负责汇总与对客）：
  | 组成件 | 执行者 | 各自验收线 |
  |---|---|---|
  | | | |

## 5 验收线
- 通用基线：抄 `references/baseline.md §2` 对应那一行 → 逐条核，结论写进工单
- 域断言（若有，取更严的那条）：
- 件类另加：域配置指定的检查器全绿（立体件为 `node scripts/check_model.mjs <文件>`）

## 6 交付
- 产物：
- **送达**：用户拿到它要走哪一步（本地文件路径 / 文档链接 / 发到哪个会话 / 存到哪）——**没写就等于没交**
- 源文件（未内联）：
- 校样 / 预览：
- 组成件（齐备清单由域配置给；缺项标 ✗，并写谁补、什么时候补）：
- 报价与工期（≥3 件必填）：估时 / 样板件 / 复用与新建清单
- 工单状态：已开单 / 派活中 / 待验收 / 打回第 n 次 / 通过
```

### 5.1 非"件"类的验收线（保留此锚点，内容已上移）

直接抄 `references/baseline.md §2` 对应那一行，写进工单"域断言"栏。

按类型断言表（文档 / 表格 / 演示 / 图 / 视频 / 音频 / 代码 / 数据集 / 静态网页 / 交互页）**原来写在这里，已上移为通用基线**——它是全流程唯一的验收来源（交互类也在内），留在工单模板里，别的形态就看不到。

**这张表目前是人工断言，没有自动检查器。** 哪一类做到第三件就该给它写一个，在那之前别对外说"这类有闸"。

## 二、填写规则（都是踩过的坑）

1. **驱动量只能有一个。** 写两个就一定会出现"两套数据对不上"。
2. **参数栏不许出现裸数字。** 没有对应键就先去域配置指定的口径卡补键，再引用。
3. **边界必须写进组成件分工。** 主执行者接不了的部分，写清"谁补、什么时候补"——别硬塞给它，也别放任自己最后补。
4. **验收线要能被人复算。** 写成"合计数 = 各分项之和，逐项加完应等于 X"，不是"检查正确性"——给不出一句能代数字进去算的话，就是没验收线。
5. **状态必须更新。** 打回几次写几次，写在工单里而不是记在脑子里——打到第三次就说明选错了执行者，按 `SKILL.md §8` 止损回 §2 重压三键，不许再改细节。
6. **复用来源不许空着。** A/B 写清来源与改了什么；C 写"①②③④ 均无命中"。空着等于没查，而没查就建 = 白做。
7. **组成件列不全不开工。** 缺的项在开单时就写清"谁补、什么时候补"，否则会一路缺到验收。

## 三、真实样例

本域资产：`domains/<业务>/order-example.md`（现装的那份含复盘）。**通用模板不带行业样例，样例一定属于某个域。**

**样例是"填满长什么样"，模板才是要抄的。** 读样例只看每一栏的颗粒度（键名 = 值、law 一句可算的式子、验收线能被人复算），不抄它的对象。

## 四、反例（一眼看出没开单）

| 症状 | 说明 |
|---|---|
| 工单里执行者写"我" | 没查名录，直接自制 |
| 参数栏是 9.8、0.92 这种裸数字 | 没走口径卡，下次换场景必错 |
| 验收线写"检查正确性" | 无法复算，等于没有验收 |
| 驱动量写两个（如同时给了两个自变量） | 一定会出现两套数据打架 |
| 状态栏永远停在"派活中" | 没验收就交付 |
| 非件类工单没有内容清单 | 等于没说要交什么，做到哪算哪 |
