# AI 自主视觉规划

仅在“新建并生成课件”时读取。它是渲染安全契约，不是视觉模板、学科模板或课型模板。

## 核心原则

- 先理解当前课题的对象、关系、情绪、课堂动作和记忆点，再为这一册建立独有视觉概念。
- 不从主题池、版式库、课型骨架或候选构图中选择页面。AI 直接决定每页背景、视觉重心、图层、坐标、留白、字号、颜色和图像裁切。
- 相邻页面要保持同一视觉世界，但不能重复同一轮廓。变化来自内容关系，而不是机械轮换版式。
- 背景属于教学表达。场景、对象、空间关系或情绪能帮助理解时，为本课生成 2–4 张同源主题背景图构成**背景池**，普通页按主题匹配尽量复用池中背景，纯色兜底只是最后手段；不需要图像时才设计有明确色彩逻辑的纯色背景。**所有背景图必须符合本课题主题，全册视觉设计与风格色调一致**——同一视觉世界、同一色彩体系、同一画面质感，任何一张图出现"换了一个课件"的割裂感或违和感都视为不合格。无论背景图是浅色系还是深色系，页面内容（文字、容器、插图）的颜色都必须按「文字对比度」一节先算后写，保证足够对比度。古诗词原生工具页是例外：组件自带完整界面，必须省略 `visualPlan.background`。背景池规划与复用决策见“背景图生成与复用”一节。
- 思维导图工具页默认必须使用背景图，不退化为纯色底：画面延续本课视觉世界（同一场景的另一视角、同一季节或氛围的呼应），组件安全区内保持安静低细节让节点可读；标题、任务引导和结构说明排布在安全区外的文字安全区，详见“思维导图工具页”一节。
- 背景图不得承载必须阅读的文字、答案或数据。所有教学信息仍使用可编辑的希沃文字、图片或原生组件。
- 图片背景必须记录出图后确认的主次主体框和文字安全区；文字、文字容器和 scrim 不得遮挡主主体。
- 不用卡片网格填满页面。优先形成一个主视觉焦点，其他内容围绕它建立层级。
- 文字默认直接排在留白或对比度充分的区域，不得仅因"这是文字"就添加底板。**`fill` 容器垫底是「特定重要内容 / 重要布局需要」的强调手段，不是默认样式，尽可能少用**：只有当某条内容确实需要突出（核心问题、结论、答案、安全提示等特定重要内容），或布局结构本身需要容器承载（对比栏、定义框、分层卡、时间轴节点、分组卡、总结卡等）时才使用。容器选择顺序固定为：直接文字 → 特定重要内容 / 重要布局需要的 `fill` 容器 → 图片对比度不足时的局部 `scrim` 兜底；一页容器数量控制在必要范围，能省则省。
- **标题类文本（`title`/章节大标题/题头）默认直接排布、不垫底**：标题层级靠字号、字重与颜色建立，禁止用独立 `shape` 色块做标题底板，也不默认给标题加 `fill` 容器。仅当图片背景确实无法保证对比度时，才允许标题使用 `fill` 容器或局部 `scrim` 垫底（必要兜底，非默认）。
- 图片背景禁止全页 `overlay`，也不得用全画布 scrim 或 shape 变相恢复。深色局部 scrim 不做全局禁用，但只在图片复杂且对比度确实不足时使用；颜色必须取自本页色彩体系，不能默认套用通用近黑矩形。
- 每页先按 [references/page_structure_guide.md](page_structure_guide.md) 匹配一种结构类型作为**组织逻辑起点**，再自主决定最终几何。结构类型只提供"这类教学角色的页面通常如何组织"，不是候选构图，也不豁免任何本文件校验；相邻页不得使用同一结构类型。

## 页面结构

页面结构的组织逻辑参考 `page_structure_guide.md`：按教学角色（骨架 / 导入 / 讲解 / 互动 / 练习 / 总结 / 作业 / 学科专属）匹配结构类型，每个类型给出画布分区骨架、布局要点与配图倾向。

- 结构类型是内容关系的产物：同一教学角色在不同课题下允许不同结构，同一结构类型在不同页面上必须有不同的坐标、色彩、背景与视觉重心。
- 一页只用一个主结构类型；相邻两页不得使用同一结构类型；成组练习/检测页允许同结构，但轮廓与排版必须明显不同（仍受相邻页相似度 < 82% 与全册至少 4 种版面轮廓校验约束）。
- 结构类型标注的配图倾向只是提示，最终仍按「页面配图」的"去掉配图后教学内容是否完整"逐页判断。
- 结构类型不引入新字段或新元素种类；`elements` 仍只用 `text` / `image` / `shape`，`source` 仍绑定检查脚本列出的内容槽。
- 用户明确给出结构要求时，用户要求优先于结构类型匹配。

## 生成前

1. 从已确认内容提炼一句 `creativeDirection.concept`、一个 `visualMetaphor` 和一条 `backgroundStrategy`。三者必须针对本课，不能写“简洁、现代、清晰”等通用形容词。
2. 运行：

```powershell
python scripts/courseware/design/inspect_visual_blocks.py --spec pages.json
```

它会列出每页必须出现一次的语义内容槽。视觉计划通过 `source` 绑定这些槽，禁止复制、改写或遗漏正文。
3. 按“内容 → 内容角色字号 → 行数估算 → 文本框几何”的顺序规划每个文字槽。先确定最终字号，再按中英文宽度、显式换行、行距和四侧内边距反推文本框；空间不足时扩大文本框、精简文案或拆页，不降低字号。
4. 为需要场景或对象支持的页面先确定图像画幅、主体方向与占比、文字安全区和禁止文字区，再调用 ImageGen。提示词必须包含本课对象、动作、环境、镜头、画面重心、留白方向、16:9、无文字、无水印；内容页背景默认按**中间留白**方向出图（主体置于画面边缘或四角、中心大面积安静留白），侧边留白图仅按「背景图生成与复用」的用途定位少量生成。配图提示词另须声明与本页内容对应的对象或场景、与全册一致的画风与色调。思维导图等工具页同样按此流程出图，提示词需声明画面中下部安静留白以承载组件。
5. 出图后由 AI 查看最终图片，按 `cover` 裁切后的 1280×720 可见画面确认实际主体框和文字安全区，确认实际留白方向并在 `imageLayout.whitespace` 显式声明（`center` / `left` / `right` / `bottom`），再写入 `imageLayout`。实际主体进入预期文字区时，重新生成图片或调整前景几何；不得把生成前的目标位置冒充出图后的识别结果。正式落稿时，图片背景先物理裁切，纯色背景生成无损 1280×720 PNG，再统一由 MCP `set_slide_background_image` 写入页面自身背景；不得在 ENBX 中嵌入全画布图片或色块元素。

## 背景图生成与复用

每份课件先建立由 **2–4 张主题背景图构成的背景池**，普通页从池中按主题匹配复用；只有池中没有任何图能匹配当前页主题时才新生成一张并加入池中。纯色背景是最后手段，仅在用户明确要求无外部图片、或页面确实不需要图像时使用。

**全册一致性是背景池的准入门槛**：池中每一张图都必须服务本课题，与全册同一视觉世界、同一风格与色调；任何一张图与前后页放在一起产生割裂感、违和感或图库感拼贴，都不能进入池中。

### 留白方向分类

每张背景图按画面留白方向分为四类，复用上限与用途各不相同：

| 留白方向 | 画面特征 | 用途定位 | 复用上限 |
|---|---|---|---|
| **中间留白（center）** | 主体置于页面边缘或四角，中心区域安静低细节，可承载前景内容 | **内容页首选，池中大部分（过半）池项应为这类**；支持自由布局，建议多复用 | 最多 **6** 页 |
| 左侧留白（left） | 主体占据右侧、左侧留白 | 尽量少用：单侧主体压缩另一侧可用空间，影响内容最大化展示 | 最多 **2** 页 |
| 右侧留白（right） | 主体占据左侧、右侧留白 | 同上，尽量少用少复用 | 最多 **2** 页 |
| 底部留白（bottom） | 主体集中在上部，下部安静 | 视需要少量使用 | 最多 **4** 页 |

可在 `imageLayout.whitespace` 显式声明留白方向（`center` / `left` / `right` / `bottom`），校验器按上表分档执行；缺省时按 primary 主体几何自动推断（主体完整落在左/右半区且纵向占比大 → 判为对侧留白，其余含顶部/底部/四角主体与无主体画面 → 判为中间留白）。建议出图回读后显式声明，避免推断与实际画面不符。

### 背景池规划（出图前）

- 按教学阶段与情感氛围划分池项：封面/导入、讲解主视觉、对比/总结、活动氛围等——每个池项对应一种氛围，不按单个页面划分。
- 池项之间必须同源：同一视觉世界（同一场景的不同视角、同一季节或氛围的呼应），保持与前后页的色彩连续性，风格、色调与质感一致，避免图库感拼贴。
- **池项构成以中间留白为主**：至少过半池项为主体置边缘、中心安静的中间留白图，供讲解、梳理、对比等内容页反复复用；侧边留白（左/右）背景全池最多 1 张，仅用于确实需要单侧大主体的页面（如情境导入大图）；底部留白可视需要少量。
- 提示词为每张池图声明主体方向、主体占比与文字安全区；中间留白图必须要求"主体置于画面边缘/四角，画面中心大面积安静留白"，防止生成主体居中的图占用内容区。

### 复用决策（逐页）

页面需要背景时按以下顺序判断：

1. **页面类型**：`poem` 与课堂活动（`choice / judge / match / classify`）由组件独占整页，不得声明背景，不参与背景池（活动页规则以 `subject_tool_guide.md` 的「课堂活动页规则」为唯一权威定义）。
2. **mindmap 工具页**：必须使用背景图（不退化为纯色底），从池中选择组件安全区（约 y 234–660）安静低细节的池项。
3. **普通页**：遍历池中已有背景，优先匹配**中间留白**池项且与当前页主题契合（同一场景、同一情感氛围、色彩连续）则复用；侧边留白池项只在该页内容形态确实适配单侧布局（如导入情境大图、单侧浮字大图页）时使用；池中没有可匹配项时才新生成（新图同样优先设计为中间留白）。
4. **新生成的图加入池中**，供后续页面继续复用。

### 复用约束

- 复用上限按留白方向分档：中间留白单张最多 **6** 页、侧边（左/右）留白单张最多 **2** 页、底部留白单张最多 **4** 页。校验器执行：超档报错，接近档位上限时警告。
- **中间留白背景建议多复用**：复用 5 页及以上时，各页前景布局、文字排版与视觉重心必须有明显差异，并优先通过**更换配图**与变化布局制造差异（见「页面配图」的"中间留白页的图文组合"）。
- 相邻 2–4 页可以按需复用同一背景图（中间留白背景尤佳），但相邻页版面轮廓相似度仍须 < 82%，复用多页时各页轮廓与排版必须明显不同，避免单调。
- 复用背景不沿用首次使用的 `imageLayout`：每个复用页仍按自己的文字排布声明 `textSafeRegion` 与 `bgTone`，不得直接照抄首次使用的安全区坐标。

## 页面配图

配图（`kind:"image"` 前景元素）与背景图分工不同：背景图铺满整页表达氛围与场景，配图是页面内的教学插图，承载具体对象、示例、对比、流程或数据可视化，让抽象概念可见。配图可选带一句图注 `caption`，渲染器在配图底部绘制半透明图注条；图注计入页面内容密度。

**配图是按需增强，不是每页标配。** 默认不配图；只有当本页主题确实需要图来说明、描述、介绍或美化时，才为这一页配图。整册课件允许大量页面完全没有配图——纯文字页、强调阅读的文本页、课堂活动页都是合法的无配图状态。配图数量不参与任何达标统计，不配图不扣分。

### 配图决策（按需判断，先判断后配图）

逐页自问：**去掉配图后，本页教学内容是否仍然完整、学生是否仍能理解？**
- 如果文字与背景已能讲清，则不配图；
- 只有配图能补足文字表达不了的内容时才配图。

需要配图的典型场景（配图承担说明、描述、介绍或美化作用）：

- 概念讲解页：示意图说明结构、关系或机制；
- 示例页：实物图、样例图或典型例证；
- 对比页：并置两幅对象的差异；
- 流程页：步骤示意或时间线索；
- 数据页：趋势、占比或数量关系的可视化；
- 主视觉页：封面、章节页可配图提升视觉焦点；
- **中间留白内容页的图文混排**：背景中心安静带面积大，文字与配图组合排布能同时提升信息量与视觉质量（见下节）。

明确不配图的场景：

- 纯文字梳理、要点归纳、强调阅读的文本页；
- 课堂活动页（`activity_page` 由活动组件独占页面）；
- 已有背景图足以表达场景氛围、文字层级已清晰的页面。

有配图需求的页面每页 1–2 张为宜，不堆叠多图。**配图必须结合本页内容合理生成与插入**：提示词取材本页教学内容的真实对象、场景或过程，画面与全册背景同一视觉世界（风格、色调、笔触一致），不得用与本页内容无关的通用图库图、装饰图或背景图冒充配图。

### 中间留白页的图文组合

中间留白背景的内容页是配图的最佳舞台——中心安静带面积大、前景布局自由，应**多结合插图呈现最佳视觉效果**：

- 在满足"去掉配图后教学内容仍完整"的前提下，中间留白页可适当提高配图意愿：用 1–2 张配图填补视觉重心、与文字形成图文呼应，避免大面积留白带来的空旷与单调；
- 布局方式自由多样：图文中轴对称、文字环绕插图、左右图文呼应、插图作视觉锚点文字分层展开等，按本页内容关系选择，同一背景的复用页之间应更换配图与布局制造差异；
- 配图位置避让背景边缘主体与文字安全区，不得实质遮挡背景主主体；
- 复用同一张中间留白背景的多个页面，**优先通过更换配图、变化图文关系来区分版面**，而不是让每页都是"标题 + 纯文字列表"。

### 配图位置与图文混排布局

配图在页面内的**位置与尺寸**是图文混排页视觉质量的常见失分点，按以下契约排布（经验来源：图文混排页配图顶格、右侧下方大面积留白、文本列过窄三类真实返修）：

- **配图不得顶格**：配图顶部 y 不得与标题同高或高于标题——图文混排页的标题通常位于 y≈30–110，配图顶部应留出标题带（建议 `y ≥ 120`，或至少低于标题底部 40px），否则视觉上"插图压过了标题"，阅读顺序颠倒。
- **配图垂直居中、用高度填充所在侧**：单侧配图（如右配图）应在该侧垂直居中并尽量拉高（如 `x=820, y=140, w=420, h=480`，占满 y 140–620），避免"一角有图、其余大面积空白"的失衡；配图高度上限仍受「配图面积 ≤ 画布 80%」约束。
- **文字列宽度最大化**：图文混排时，文字列宽度按「配图起点 x − 安全边距（≥ 60px）」取最大化（如配图 x=820 时文字列 x=280、宽 520），不要让文字挤在中间窄列、两侧大面积空置。
- **跨色调区域拆 textSafeRegions**：文字/容器跨越背景不同色调区域（如上部天空、下部地面）时，把 `textSafeRegions` 拆成多段、每段独立声明实测 `bgTone`（如上部 `#D6C8B0`、下部 `#C0B39A`），不要用单一区域硬套，避免底部文字对比度失真。

### 配图规划步骤

1. 先确定图位与文字排布：配图占位（含底部图注区）、文字安全区、禁止文字区，再出图。
2. 提示词必须包含与本页教学内容对应的对象或场景、动作、环境、风格（与全册视觉世界同源、色调一致）、镜头、画面重心、留白方向、无文字、无水印；配图带图注时提示词要求画面底部留白以承载图注条。
3. 出图后由 AI 回读最终图片，确认主体清晰、与背景同源、底部图注区未被主体占用；主体漂移进入图注区或与文字冲突时重新生成。
4. 写入 `visualPlan.elements` 的 `kind:"image"` 元素：`source`、`box`、`role`，可选 `caption`。

### 配图元素契约

```json
{
  "kind": "image",
  "source": "images/page-03-illustration-1.png",
  "fit": "cover",
  "role": "illustration",
  "caption": "图中展示叶片气孔的显微结构，帮助学生理解蒸腾作用的路径。",
  "box": {"x": 700, "y": 130, "w": 500, "h": 340},
  "z": 10
}
```

- `source` 为本地图片路径（建议 `images/page-NN-illustration-M.png`）或 `page.image` 引用；
- `fit` 当前仅支持 `cover`；
- `role` 可选，取值 `illustration`（默认）/ `photo` / `diagram` / `data`；
- `caption` 可选，10–80 字的一句话图注，说明图中内容与教学作用，不重复正文；渲染器在配图底部自动绘制图注条（半透明深色底 + 22px 白字居中，最多两行）；
- 配图面积不得超过画布的 80%（不得把配图当全画布背景）；带图注时配图宽度 ≥ 200px、高度 ≥ 60px；
- 配图不得实质遮挡背景图的主主体：规则同文字，遮挡 `primary` 停止生成，遮挡 `secondary` 由 AI 复核。

### 配图与内容

- 图注计入页面内容密度，但图注不能替代正文三层信息（`lead`/`body`/`items`/`question`/`answer`/`summary`）；
- 图注是对内容的补充解释，正文仍须完整、可独立成页；图注不重复正文结论。

## 根级契约

```json
{
  "title": "课题名（落稿与导入按此命名课件）",
  "imageStrategy": "generated",
  "visualPlanning": {
    "backgroundImageMinRatio": 0.5,
    "creativeDirection": {
      "concept": "本课独有的视觉概念",
      "visualMetaphor": "贯穿全册但不固定版式的视觉隐喻",
      "backgroundStrategy": "哪些页用场景图、哪些页用纯色以及原因"
    }
  }
}
```

`title` 是落稿文件名与客户端课件名。缺失时 `build_v2.py` 会依次按课题 `topic`、首个有标题页面自动派生，并打印告警；无任何可派生来源时回落「未命名课件」（易撞名，应避免）。导入前同名的旧课件会被自动关闭，但显式写 `title` 仍是最稳妥的做法。

`backgroundImageMinRatio` 默认 `0.5`。课堂活动页和古诗词原生工具页不计入分母。用户明确要求无外部图片时可以降低为 `0`，但普通页面必须重新设计纯色背景与视觉层级，不能保留空图位或占位图。首个可使用背景的非活动页默认必须使用本课生成的背景图；用户明确要求无图时，正式制作应记录该覆盖决定并使用相应兼容参数，而不是伪造图片证据。

### imageStrategy（spec 根级图片方案）

建课流程阶段①确认的图片方案写入 spec 根级 `imageStrategy`，取值三选一：

| 取值 | 含义 | 约束 |
|---|---|---|
| `generated` | AI 生成图片（默认，可省略） | 按「背景图生成与复用」建背景池 |
| `provided` | 图片由用户提供 | 先核对素材内容、清晰度与裁切空间，再进入视觉规划 |
| `none` | 无外部图片方案 | 必须同时声明 `backgroundImageMinRatio: 0`；见下方「无图方案」 |

### 无图方案（imageStrategy=none）

用户明确不要外部图片（或无法生成/提供图片）时采用无图方案，校验器会强制执行：

- `visualPlanning.backgroundImageMinRatio` 必须为 `0`，且所有页面背景一律 `type:"solid"`——**不得声明任何图片背景**（含 `mindmap` 页，思维导图页的背景图要求在无图方案下降级为纯色底 + 完整的前景文字说明）；
- 不得声明任何前景配图（`kind:"image"` 元素）；
- 页面设计以**色彩、留白、字体层级和必要图形**完成：用纯色底色分区分组、用字号字重建立层级、用 `shape` 做结构锚点与分隔线、用文字 `fill` 容器承载特定重要内容，不得保留空图位或占位图；
- 其余校验（内容密度、对比度、相邻页相似度、轮廓多样性）全部照常执行——无图不是降低质量的理由，而是另一种设计路径。

## 逐页契约

普通页和原生工具页使用 `visualPlan`。古诗词原生工具页仍声明 `designRationale` 和空 `elements`，但必须省略 `background`。课堂活动页由希沃组件独占，必须保持空白，不声明 `visualPlan`。

```json
{
  "layout": "authored_canvas",
  "visualPlan": {
    "teachingIntent": "本页的教学作用",
    "designRationale": "为什么本页需要这一视觉重心和背景",
    "background": {
      "type": "image",
      "source": "images/page-01-background.png",
      "fit": "cover",
      "imageLayout": {
        "hasRecognizableSubject": true,
        "subjects": [
          {
            "label": "本页核心观察对象",
            "importance": "primary",
            "box": {"x": 880, "y": 80, "w": 320, "h": 560}
          }
        ],
        "textSafeRegions": [
          {
            "label": "左侧留白",
            "box": {"x": 60, "y": 50, "w": 720, "h": 380},
            "bgTone": "auto"
          }
        ]
      }
    },
    "elements": [
      {
        "kind": "text",
        "source": "title",
        "role": "title",
        "box": {"x": 72, "y": 64, "w": 680, "h": 160},
        "style": {
          "fontSize": 64,
          "color": "#17324D",
          "bold": true,
          "lineSpacing": 1.2
        }
      },
      {
        "kind": "text",
        "source": "lead",
        "role": "lead",
        "box": {"x": 76, "y": 250, "w": 600, "h": 150},
        "style": {
          "fontSize": 34,
          "color": "#315F63",
          "lineSpacing": 1.35
        }
      }
    ]
  }
}
```

这个示例利用出图后确认的左侧安全区直接排文字，不加遮罩或文字底板。背景也可为 `{"type":"solid","color":"#RRGGBB"}`。

所有图片背景都必须声明 `imageLayout`：

- `hasRecognizableSubject` 必须为布尔值。为 `true` 时 `subjects` 非空且至少有一个 `primary`；为 `false` 时 `subjects` 必须显式为空数组。
- `subjects[].label`、`importance` 和 `box` 必填；`importance` 只接受 `primary` 或 `secondary`。
- 可选顶层字段 `whitespace` 声明该背景的留白方向（`center` / `left` / `right` / `bottom`），供背景池复用分档校验；建议出图回读后显式声明，缺省时按 primary 主体几何自动推断。
- `textSafeRegions` 必须是非空数组，每项显式提供 `label` 和 `box`。
- 所有 `box` 均使用最终 `cover` 画面的 1280×720 坐标，不是原始图片像素，也不是生成前预计位置。
- 每个文字框必须完整落入至少一个 `textSafeRegion`。文字的 `allowOverlap` 不能绕过主体保护。
- 与较小区域交叠超过 2% 视为实质遮挡：text 或 scrim 遮挡 `primary` 时停止生成，遮挡 `secondary` 时警告并由 AI 复核。

图片局部复杂且一组文字无法保持对比度时，才在 `background.scrims` 中声明一块服务整个内容组的遮罩：

```json
"scrims": [
  {
    "box": {"x": 64, "y": 72, "w": 620, "h": 360},
    "color": "#315F63",
    "opacity": 72,
    "rounded": true,
    "radius": 0.08
  }
]
```

`scrim.opacity` 必须显式声明且在 `0–100`；`rounded` 必须为布尔值，`radius` 必须在 `(0, 0.5]`。每块 scrim 必须完整承载至少一个文字框；图片页上的 scrim 还必须完整位于某个 `textSafeRegion` 内。遮罩颜色应来自背景物体、环境或本页强调色。不得使用全画布 scrim，不得为每个文字槽重复添加遮罩，不得让同一文字同时使用覆盖它的 `scrim` 和自身 `fill`，也不得用 scrim 覆盖图片主主体。

### 思维导图工具页

是否设置思维导图页由内容结构决定，选型研判见 `subject_tool_guide.md` 的「思维导图自动研判」（知识复习、概念关系复杂、逻辑推理步骤、对比总结、结构化信息才选用）。确认使用后，本页是普通教学页与原生组件的复合体，视觉与内容要求都高于“组件加灰底”，校验器会强制执行：

- **配图必须且和谐**：背景必须是 `type:"image"`，并与全册视觉世界同源——优先取本课场景的延展视角（同一地点的另一种构图、同一季节或氛围的呼应画面），保持与前后页的色彩连续性；不得退化为通用灰底，也不得使用与主题无关的图库感图片。
- **安全区内安静**：组件安全区（约 y 234–660）是脑图生长区域，背景在这一区域保持低对比、低细节（远景雾化、柔和过渡、大面积留白）；主主体放在远离安全区的边角，避免与脑图节点争夺注意力。
- **内容翔实**：除标题外必须提供一句任务引导（`lead`，说明学生要完成的梳理动作与可判断产出），建议再补充 1–3 条结构说明（`items`，解释层级划分依据或关键词的取舍逻辑）；全部文字排布在安全区外的文字安全区并通过校验，说明文字合计建议不少于 60 字。
- **顶部文字纵向排列，不并排**：安全区外顶部（y<234）的文字必须按阅读顺序**纵向依次排布**——标题（左上）→ 任务引导（标题正下方）→ 结构说明（再往下），不得把 `lead` 并排放到标题右侧同一高度（如右上角），否则引导语与标题同高、视觉上"高过标题"，阅读顺序颠倒。顶部空间不足时**精简 `items` 条数或压缩行高（lineSpacing 1.15–1.2）**，而不是横向并排。
- **节点精炼、解释外置**：脑图节点文案保持精炼（不超过 4 字为宜，避免定宽节点挤压），详细解释放进页面文字说明而不是节点；配图不承载任何文字。

### 图层

所有图层使用 1280×720 逻辑坐标和 `{x,y,w,h}`。`z` 越大越靠前。

- 文字：`kind:"text"`，`source` 取检查脚本列出的 `title`、`body`、`lead`、`item.0`、`question`、`answer`、`summary` 等；`style` 至少包含最终输出的 `fontSize` 和 `color`。
- 图片（配图）：`kind:"image"`，`source` 为本地图片路径，或 `page.image` 引用页面主图；当前使用 `fit:"cover"`。可声明 `role` 与 `caption` 图注，契约与规划见「页面配图」一节。
- 装饰与结构形状：`kind:"shape"`，支持 `shape` 取值 `rect`（矩形）/ `rounded`（圆角矩形）/ `oval`（椭圆）/ `line`（线段）/ `arrow`（右箭头）/ `triangle`（三角）/ `callout`（对话气泡）。形状是页面视觉语言的一部分，承担三类角色：
  - **结构分区**：左右分栏的浅色底、上下分层色带、对比栏背景、时间轴轨道、卡片网格底；
  - **视觉锚点**：章节竖条、序号圆点、引导箭头、角标、气泡图形（引用/提示/角色话语，气泡可用元素级 `tailRight` 控制尾巴方向）；
  - **装饰语言**：与全册视觉世界一致的点缀（同一色系的圆点/线条/三角），克制使用。
  - **红线不变**：`shape` 不得作为任何文字（尤其标题）的底板——文字垫底只允许文字自身 `fill` 容器或 `background.scrims`；不得绘制全画布 shape 遮罩；装饰不能承担教学含义，也不能替代真实图片。形状与文字重叠时按 z 层规则判定：形状作背景分区（z 低于文字）允许文字覆盖其上；形状盖住文字（z 高于文字）报错。需要「形状 + 文字」组合的强调内容优先使用文字 `fill` 容器。
  - 数量纪律：每页装饰 shape 建议 1–5 个，硬上限 8 个（校验器执行，超过报错）。形状服务于结构分区与视觉强调，不是填充手段；同页多个形状应形成统一的形状语言（同色系、同圆角、同尺寸节奏），避免拼贴感。

先按内容角色选最终字号，建议范围如下：

- 封面或主视觉标题：`56–72px`。
- 普通页标题：`42–56px`。
- 引导语、问题或结论：`30–40px`。
- 正文或列表：`24–32px`。
- 辅助文字：`22–26px`。
- 大数字：`64–112px`。

标题硬下限仍为 `42px`，其他正文硬下限仍为 `22px`。`fontSize` 是最终输出字号，不是允许自动缩小的起点；正式生成不会自动缩号。

### 扩展内容字段的视觉位置

`question`、`answer`、`summary` 和 `bigNumber` 是内容槽的扩展字段，校验器会统计其字数计入页面密度。它们在 `visualPlan.elements` 中作为 `kind:"text"` 的 `source` 绑定，视觉位置按内容角色灵活设计：

| 字段 | 推荐 role | 推荐字号 | 典型位置 | 视觉处理 |
|---|---|---|---|---|
| `question` | `question` | 28–36px | 页面中上部，标题下方 | 默认直接排布；仅当它是页面核心问题等特定重要内容时才用 `fill` 容器强调，配 `accentColor` 标记关键词 |
| `answer` | `answer` | 22–28px | 紧随 `question` 下方 | 用较浅色或缩进与问题区分；仅在问答卡属于重要布局时才加 `fill` 底板，否则直接排布 |
| `summary` | `summary` | 30–40px | 页面底部或总结区 | 用强调色或 `bold` 突出，与正文形成层级差 |
| `bigNumber` | `bigNumber` | 64–112px | 页面视觉焦点位置 | 大字号居中，配 `unit` 后缀；通常独占一行 |

示例——探究型页面的问答布局：

```json
{
  "kind": "text",
  "source": "question",
  "role": "question",
  "box": {"x": 60, "y": 180, "w": 1160, "h": 80},
  "style": {
    "fontSize": 32,
    "color": "#14213D",
    "bold": true,
    "fill": "#E8EEF4",
    "fillOpacity": 90,
    "padding": [16, 12, 16, 12],
    "rounded": true,
    "radius": 0.06
  }
},
{
  "kind": "text",
  "source": "answer",
  "role": "answer",
  "box": {"x": 60, "y": 270, "w": 1160, "h": 100},
  "style": {
    "fontSize": 24,
    "color": "#3A4A60",
    "lineSpacing": 1.5
  }
}
```

`question` 和 `answer` 通常成对出现。`summary` 适合放在总结页的底部，用一句话提炼全页核心结论。`bigNumber` 适合数据驱动型页面（如统计、年份、数量对比），独占视觉焦点。

文字样式还可包含 `font`、`bold`、`align`、`verticalAlign`、`lineSpacing`、`accentColor`。直接文字省略 `fill` 即为透明，不需要迁移。只有内容分组确实需要设计容器时才使用下面的组合：

```json
"style": {
  "fontSize": 30,
  "color": "#17324D",
  "fill": "#D6E8E8",
  "fillOpacity": 92,
  "padding": [18, 14, 18, 14],
  "rounded": true,
  "radius": 0.08,
  "line": "#5F8588"
}
```

使用 `fill` 时必须同时显式提供 `fillOpacity` 和正数 `padding`。`fillOpacity` 范围为 `0–100`；`padding` 可为一个正数，或按 `[left, top, right, bottom]` 提供四个正数；`rounded` 必须为布尔值；`radius` 必须在 `(0, 0.5]`；`line` 必须为 `#RRGGBB`。容器颜色、描边和文字色应取自本页已有色彩，留出合理内边距，避免通用近黑矩形和同页重复卡片墙。**`fill` 容器只服务于特定重要内容或重要布局，不是页面默认样式**；同页容器数量控制在必要范围，普通正文、引导与要点一律直接排布。

### 文字对比度

**目标**：标题（`title`）与主要正文（`lead`/`body`/`items`/`question`/`answer`/`summary`）的文字色必须与所在区域的实际背景色调形成高对比度，目标 ≥ 4.5:1（WCAG AA 普通文本），硬底线 3:1（低于即报错）。中等亮度背景不得凭直觉选色。

**先算后写，禁止凭直觉落色**：AI 在把任何文字色写进 spec 前，必须先以该文字所在区域的**实测背景色**运行文字配色工具完成对比度预检，再把达标颜色写入 spec；校验器只在事后兜底，不承担选色职责。

```powershell
python scripts/courseware/design/text_contrast.py --bg #A87F45            # 推荐深/浅两组达标文字色
python scripts/courseware/design/text_contrast.py --bg #A87F45 --fg #2A1500  # 校验组合；<4.5 退出码 2
python scripts/courseware/design/text_contrast.py --bg #EDDBB1 --bg #7A5F3A  # 批量选色
```

“实测背景色”按以下顺序确定：

1. **文字有 `fill`（容器）**：以 `fill` 与底层基色按 `fillOpacity` 混合后的颜色为背景。`fillOpacity ≥ 85` 时容器色占主导，可直接据此选文字色。
2. **文字落在 `scrim` 上**：以 `scrim.color` 与底层基色按 `scrim.opacity` 混合后的颜色为背景。`opacity ≥ 60` 时遮罩色占主导。
3. **文字直接排在背景上**：纯色背景取 `background.color`；图片背景取文字所在 `textSafeRegion` 的 `bgTone`。

**图片背景必须声明实测 `bgTone`**：每个 `textSafeRegion` 必须显式提供一个 `bgTone` 字段（`#RRGGBB`），代表该安全区域的平均主色调。`bgTone` 必须来自出图后的真实画面——支持读图时按回读画面取该区域平均色调，不支持读图时用像素分析（亮度/边缘网格）估计后标注来源。**未声明 `bgTone` 时校验器无法计算对比度，直接排布在其上的文字会报错**；无法实测时改用 `fill` 容器或 `scrim` 垫底再排文字。

支持把 `bgTone` 声明为 `"auto"`：校验器会用 PIL 按 16:9 `cover` 裁切后自动实测该区域的平均色并回填（须已安装 `requirements.txt` 中的 Pillow，未安装或图片不可读时提取失败会报错，提示人工实测或改用垫底方案）。适合背景色调均匀、不想逐区域人工取色的场景；色调分布不均的区域仍建议人工实测，避免平均色失真。

```json
"textSafeRegions": [
  {
    "label": "上方金色天空",
    "box": {"x": 0, "y": 0, "w": 1280, "h": 200},
    "bgTone": "#D4A848"
  }
]
```

按背景亮度分档的选色基准（亮度为 WCAG 相对亮度 0–1）：

| 背景亮度 | 典型场景 | 首选文字色 | 预期对比度 |
|---|---|---|---|
| 极浅（>0.6） | 雪景、白纸、浅米纸面 | 深墨/深褐（`#1A1A2E`、`#2A1500`、`#2E4B4F`） | ≥ 7:1 |
| 浅（0.4–0.6） | 亮天空、暖黄纸面 | 深色系（`#2A2116`、`#3A2A14`、`#14302E`） | ≥ 5:1 |
| 中等（0.15–0.4） | 金色晚霞、暖褐、灰蓝 | **必须用工具计算**，深浅都可能达标 | ≥ 4.5:1 |
| 深（0.05–0.15） | 深青山水、暗色 scrim | 浅色系（`#FFFFFF`、`#F4F0E4`、`#F0F4F8`） | ≥ 5:1 |
| 极深（<0.05） | 近黑遮罩、夜景 | 白或近白（`#FFFFFF`） | ≥ 12:1 |

修复优先级：文字色与背景对比度不足时，**先用工具重选文字色**；仍不足再在文字区域添加 `scrim` 或 `fill` 容器，用遮罩/容器色作为新的有效背景，并把新背景色代入工具校验。

## 视觉差异门槛

- 不声明 `composition`，也不根据学科、年级或课型选择 layout 候选；结构类型按 [references/page_structure_guide.md](page_structure_guide.md) 匹配，但只作为组织逻辑起点，不决定最终几何。
- 普通页背景按「背景图生成与复用」一节从背景池中按主题匹配复用，复用上限按留白方向分档：中间留白最多 6 页、侧边（左/右）留白最多 2 页、底部留白最多 4 页；相邻页可以复用同一背景图（中间留白背景尤佳），但版面轮廓相似度仍须 < 82%，复用多页时各页前景布局、文字排版与视觉重心必须明显差异，并优先通过更换配图制造差异。
- 相邻教学页不得使用同一结构类型（成组练习/检测页除外，但轮廓与排版必须明显不同）；实际占位轮廓相似度达到 82% 时必须重做。
- 六页及以上课件至少形成四种实际版面轮廓；这是结果检查，不是要求从四种模板中轮换。
- 封面、关键结论、比较、推导、练习和总结是否出现、出现几页、以什么顺序出现，完全由内容与用户要求决定。
- 原生工具页的前景图层不得进入工具安全区；课堂活动页不得放背景或装饰。

## 生成与校验

正式生成：

```powershell
python scripts/courseware/build_v2.py --spec pages.json --require-images
```

项目只接受逐页 `visualPlan` 计划，不提供旧 spec、固定布局或候选构图回退。

预检使用与渲染器一致的中英文估宽，按声明字号、显式换行、`lineSpacing` 和四侧 `padding` 返回预计行数、所需高度与可用高度；图片背景同时检查文字安全区和主体交叠。失败信息会指出页面、内容槽或 scrim、主体标签、交叠比例或尺寸差额，并在写出 ENBX 前停止。校验失败必须扩大文本框、精简文案、重新出图、拆页或修正图片资源，不能自动缩号，也不能让渲染器自动换候选构图。dry-run ENBX 只包含前景，图片和纯色背景都会标记为等待 MCP 原生设置；最终仍需在希沃客户端应用背景后核对颜色、可读性、裁切、遮挡和原生组件落位，不得只凭 JSON 或基础 ENBX 通过就宣称视觉质量合格。
