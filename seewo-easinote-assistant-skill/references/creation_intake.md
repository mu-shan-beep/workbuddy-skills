# 新建课件的信息与内容规划

仅在新建课件时读取。连接、排障、同步、调整已有课件和独立本地 ENBX 操作不得加载本文件。

## 四阶段建课流程总览

新建课件按四个检查点推进，每个检查点都**先确认后前进、可编辑、可回溯**：

| 阶段 | 检查点产出 | 确认方式 |
|---|---|---|
| ① 基本信息 | 课题、学段、课堂目的、页数区间、图片方案、硬约束摘要 | 询问卡片确认 |
| ② 教学目标 | 按新课标对齐思考写出的目标条目（含素养指向与检测方式） | 询问卡片确认 |
| ③ 大纲设计 | 原生元素选型 + 环节大纲 + 详细设计网格 | 询问卡片确认 |
| ④ 分段生成 | 按环节分段充实的 pages.json → 校验 → 生成 | 生成后回读汇报 |

**回滚规则**：用户在任何阶段要求修改已完成检查点的内容时，回到该检查点修改并重新确认；后续受影响的检查点（如改目标影响大纲、改大纲影响生成）一并重做，不受影响的部分保留。已生成的课件需要局部修改时，只重写受影响页的内容与视觉计划后重新生成，不重做全册。

每个检查点未确认前，不进入下一阶段：不生成图片、不写出正式 `pages.json`、不运行 `build_v2.py`，也不修改希沃客户端。宿主没有询问卡片能力时才降级为文本询问，并明确说明能力降级。

## 阶段①：基本信息

优先从用户消息和素材中提取课题、学段、学生基础、课堂目的、课时、硬约束、必须覆盖的知识点、事实来源和可用图片。已经明确的信息不重复询问。只有缺项会实质改变结果且不能可靠推断时才询问，例如：

- 课题或必须忠实处理的教材、课文、数据和答案；
- 学段、年级或学生已有基础（学段同时决定课堂活动密度与工具选型，见 `subject_tool_guide.md` 的「学段与课堂活动密度」）；
- 本次用于新授、复习、练习、展示还是其他明确目的；
- 课件页数区间（用户未明确时必须询问，选项与规则见「页数确认与结构页」）；
- 必须使用的人物、作品、实验、地点、校内素材或品牌要求；
- 图片方案：图片由用户提供、允许 AI 生成，还是明确采用无图方案。结果写入 spec 根级 `imageStrategy`（`generated` 生成 / `provided` 用户提供 / `none` 无外部图片）。选 `none` 时须同时声明 `visualPlanning.backgroundImageMinRatio: 0`，并按 `visual_planning.md` 的「无图方案」重新设计纯色页面；选 `provided` 时先确认素材清单。

不要把模型常识、常见教材版本或上一份课件当成已确认事实。具体人物、年份、数据和教材结论应来自用户素材或可靠来源；仍不确定时标记待核实。

信息齐备后，向用户展示基本信息摘要（课题/学段/目的/页数区间/图片方案/硬约束），用询问卡片确认进入下一阶段。摘要按「对话内呈现规范」以卡片呈现，不用表格。

课题名确认后写入 spec 根级 `title`——它是落稿文件名与客户端课件名；缺失时 `build_v2.py` 会按课题或首页标题自动派生并告警（见 `visual_planning.md`「根级契约」）。

## 阶段②：教学目标（新课标对齐）

先读取 [references/curriculum_standards.md](curriculum_standards.md) 完成对齐思考（定位核心素养、对标学段要求、行为动词、教学评一致、真实情境），再产出教学目标条目。

向用户展示的目标条目至少包含：目标陈述（行为动词 + 内容 + 可判断产出）、素养指向、对应的检测方式（哪个环节/哪种检测页承载）。条目用**宫格卡片**呈现（每目标一卡），禁止表格，卡片规范见「对话内呈现规范」。展示后用询问卡片确认；用户增删改目标后，须按对齐思考清单重查一致性再确认。

目标条目确认后写入 spec 根级 `teachingObjectives`（字符串数组），供阶段③逐环节回看。

## 阶段③：大纲设计

确认目标后：

1. 先按 `subject_tool_guide.md` 完成原生元素选型（含「思维导图自动研判」与「学段与课堂活动密度」）；
2. 按学科读取最佳实践大纲模板作为**组织逻辑起点**——语文/数学/英语读 `subject_outlines/` 对应文件，其他学科读 `subject_outlines/general_outlines.md`；模板不是固定页序，须按课题内容与已确认目标逐环节改造；
3. 逐环节回看：每个环节服务于至少一条教学目标，每条目标至少对应一个承载环节 + 一个检测环节；无目标支撑的环节删除或改造；
4. 组织成详细设计网格向用户展示（见「详细设计确认」），用询问卡片确认。

### 详细设计确认

把内容组织成真实教学环节，向用户展示一次完整的**宫格卡片网格**（呈现规范见「对话内呈现规范」，**禁止用表格**）。每张卡代表一个教学环节或连续页面组，不与单页机械绑定，卡片内至少包含：

- 环节序号、预计页码或页数，以及已知时长；封面页、目录页、章节页须单独标注 role 与页位，注明不计入总页数；
- 教学问题或目标（对应阶段②的目标条目）；
- 讲授内容及其证据、素材；
- 学生任务；
- 预期产出及评价标准；
- 拟使用的希沃原生元素或课堂活动；
- 每页拟匹配的**页面结构类型**（按 `page_structure_guide.md` 的速查表；相邻环节不重复同结构）；
- 拟使用的配图（页面教学插图）与图注方向。

卡片数量由教学内容决定：1–3 格单行排列，4 格使用 2×2，5–6 格使用 2×3，7 格及以上按三列连续增加行。不得为了凑满九格拆分、合并或补空教学环节。窄屏或宿主限制下可响应式改为一列或两列，但必须保持同一个连续总览、原有顺序和全部字段。

网格只用于对话确认；目录页、章节页等结构页只有在用户确认的设计方案中包含时才创建。网格总览须显示用户确认的页数区间和有效内容页合计（如「区间 5-10 页 · 当前内容 8 页 + 结构 2 页」），用户可在确认时调整区间。

面向用户只展示教学决策，不展示坐标、字号、内部 ID、`visualPlan` 字段或渲染术语。确认视图不是固定课型、固定页序或视觉模板，最终视觉几何仍由 AI 根据已确认内容自主完成。

## 对话内呈现规范（全部检查点通用）

检查点确认视图——基本信息摘要、教学目标、大纲设计网格——是面向用户的教学决策视图，一律用**宫格卡片**呈现，**禁止使用任何形式的表格**（含管道 Markdown 表格、HTML `<table>`、制表符对齐文本）。具体要求：

- **优先可视化卡片**：宿主提供内联可视化组件（如 WorkBuddy 的 show_widget）时，用它渲染 HTML/SVG 宫格卡片。卡片遵循宿主主题：浅色主题用浅底深字、深色主题用深底浅字，文字对比度达标；用底色、圆角、图标、色块区分维度（环节角色、素养指向、活动/工具类型、结构页 role），不用表格线框。
- **降级 Markdown 卡片**：宿主不支持可视化组件时，降级为 Markdown 卡片（引用块 + 分隔线 + 表情符号标题模拟卡片），保持相同字段与顺序，并在文本中说明已降级。
- **字段只增不减**：改卡片不删减字段；卡片内用「标签 + 内容」分层排布（如素养指向做成色块标签、检测方式放卡底），长文本不截断。
- **色彩语义**：可用颜色区分维度（素养一维一色、课堂活动一色、结构页一色），颜色取自宿主主题色。

### 内容结果

大纲确认后，AI 在页数区间内自主决定具体页数、教学顺序、页面角色和表达方式，不强制“封面、目录、目标、讲解、练习、总结”等序列。每页围绕一个清晰教学问题组织信息，按课题需要提供：

- 学生应理解或完成什么；
- 核心问题、结论、解释、证据、例子、对比或推导；
- 学生的观察、思考、练习或互动动作；
- 可以判断的产出、答案依据或成功标准；
- 与前后页面的逻辑关系。

这些是自适应语义检查，不是固定栏目。可以合并、省略不适用项或增加课题特有内容，不得为了完整感加入空泛套话。

## 阶段④：分段生成

大纲确认后进入制作，同一对话中不再逐页询问：

1. 按教学环节**分段**充实 `pages.json`：逐段写出该环节各页的内容字段与 `visualPlan`，段内自检（内容槽绑定、密度、结构类型不与相邻页重复）后再写下一段；全部段落完成后再整体校验；
2. 按图片方案生成或核对图片（见「图片」），回读确认后写入 `imageLayout`；
3. 运行 `inspect_visual_blocks.py` 与 `build_v2.py`（命令见 SKILL.md），按回读结果汇报。

局部返修只重写受影响页：修改某一环节时保留其他环节的既有内容与视觉计划，不因局部修改重做全册。

## 内容密度与信息分层

每页内容必须形成多层信息结构，不能只有一句结论或一段背景。校验器对普通页按 `teachingIntent` 分档检查内容字数和信息层数，未达标会报错或警告。

### 内容字段与语义角色

每页可使用以下内容字段，校验器会统计所有字段字数计入密度：

| 字段 | 语义角色 | 适用场景 | 示例 |
|---|---|---|---|
| `lead` | 引导语、核心问题或任务说明 | 每页首选 | "上阕由远及近铺展北国雪景，请观察诗人如何由实景展开联想。" |
| `body` | 核心解释、背景或推导 | 知识讲解页 | "上阕先总写北国雪景，再分写山原，由实景生发想象，境界由实入虚、逐层推开。" |
| `items` | 结构化要点列表（数组） | 作业、线索、对比项 | ["必做：背诵默写全词", "选做：写 150 字写景短文"] |
| `question` | 驱动性问题 | 适合探究型页面 | "「山舞银蛇，原驰蜡象」用了什么修辞？为何让山和原「舞」「驰」？" |
| `answer` | 参考答案或思路要点 | 配合 question | "比喻+拟人，化静为动，赋予雪景生命力与竞争意志。" |
| `summary` | 本页一句话结论提炼 | 适合总结型页面 | "上阕总写→分写→想象，由远及近、动静结合。" |

### 信息分层要求

authored_canvas 页至少使用上述字段中的 **3 种**，形成多层信息结构。推荐模式：

- **讲解型**：`lead`（引导） + `body`（讲解） + `items`（要点或任务）
- **探究型**：`question`（驱动问题） + `answer`（参考答案） + `body`（背景补充）
- **总结型**：`lead`（主线） + `body`（总结） + `summary`（一句话结论） + `items`（作业）

只用 `lead` + `body` 两层的页面会被校验器警告信息分层不足。

### 内容密度阈值

校验器按 `teachingIntent` 分档执行硬下限和建议下限（字数含所有内容字段）：

| teachingIntent | 硬下限 | 建议下限 | 典型场景 |
|---|---|---|---|
| moment | 80 | 120 | 导入、情境创设 |
| evidence | 100 | 150 | 知识讲解、证据呈现 |
| sequence | 120 | 180 | 流程梳理、时间线 |
| compare | 120 | 180 | 对比分析、表格补充 |
| practice | 100 | 150 | 练习、检测 |
| summary | 80 | 120 | 总结、作业布置 |

内容不足硬下限时报错并阻止生成；不足建议下限时警告。解决方式是补充解释、证据、例子、辨析或成功标准，不能靠缩字号或加空话凑字数。

## 页数确认与结构页

### 页数区间确认

页数区间必须由用户确认，AI 不得自行决定课件规模。用户在消息中已明确页数或区间时直接采用，不再询问；否则必须通过询问卡片让用户选择：

| 选项 | 区间 | 适用场景 |
|---|---|---|
| 5-10 页（默认） | 5–10 | 常规单课时新授课 |
| 10-15 页 | 10–15 | 知识点较多或需要更多脚手架 |
| 15-20 页 | 15–20 | 多知识块、多环节的综合课 |
| 20-30 页 | 20–30 | 长文精读、整章复习等多课时内容 |

- 默认选项为 5-10 页，排在首位并向用户标注推荐。
- 用户选择某一档位后，区间约束贯穿设计与生成全程；详细设计网格中须显示当前区间与有效内容页合计。
- 用户跳过或未回应时不擅自扩大规模，按默认 5-10 继续，并在详细设计网格中再次显示当前区间供复核。

确认结果写入 spec 根级字段，校验器按此检查有效内容页数量，超出区间报错：

```json
"pagePlan": {"range": [5, 10]}
```

### 结构页不计入总页数

封面页、目录页、章节页属于结构页，不计入页数区间，通过 `page.role` 显式声明：

| role | 页面 | 内容要求 |
|---|---|---|
| `cover` | 封面页 | 课题、学段等身份信息，通常仅标题与副标题 |
| `toc` | 目录页 | 教学环节导航 |
| `section` | 章节页 | 环节分隔，可承载过渡引导语 |

- 结构页仍须有 `title` 并满足视觉契约（背景、构图、对比度），但豁免内容密度与信息分层检查；
- 内容页省略 `role` 字段；
- 结构页不得滥用：15 页以下的课件通常不需要目录页和章节页；
- 是否包含结构页、各包含几页，在详细设计网格中单独标注并向用户展示，未获确认不自动添加。

## 图片

图片方案由阶段①确认（`imageStrategy`）：

- `provided`（用户提供）：先检查内容、清晰度、方向和可裁切空间，并按最终 `cover` 画面识别主次主体与文字安全区，再决定页面作用；
- `generated`（AI 生成）：先确定画幅、主体方向、主体占比、文字安全区和禁止出现文字的区域，再规划**背景池**（2–4 张同源主题背景图覆盖各教学阶段，风格与色调全册一致，**大部分池项为主体置边缘、中心安静的中间留白图**，侧边留白图至多 1 张），最后为每页按主题匹配分配、内容页优先复用中间留白池项；只有池中没有可匹配的背景时才为该页新生成一张并加入池中。这些要求必须进入图片提示词；
- `none`（无外部图片）：以色彩、留白、字体层级和必要图形完成设计，不保留空图位；背景一律纯色，详见 `visual_planning.md` 的「无图方案」。

通用规则：

- 背景图按需复用而非每页独立生成：复用上限按留白方向分档——中间留白（主体置边缘、中心安静）最多 6 页、建议多复用；侧边（左/右）留白最多 2 页、尽量少用少复用；底部留白最多 4 页。相邻页可以复用同一背景图，但版面轮廓仍须明显不同，并优先通过更换配图与布局制造差异。背景池规划与复用决策详见 `visual_planning.md` 的“背景图生成与复用”一节。
- 出图后由 AI 视觉回读最终图片，按 1280×720 `cover` 后的可见画面确认实际主体框和文字安全区。主体漂移进入文字区时，重新生成图片或调整文字几何，不得直接沿用生成前假设。
- 图片没有可识别主体时也要完成回读，并在最终视觉计划中显式声明无主体；不能用空主体数组逃避检查。
- 背景图和内容图必须服务当前课题；纯装饰图不能用于凑图片覆盖率。
- 除背景池外，按需为页面规划**配图**（页面内教学插图）：配图是可选增强而非每页标配，只有当本页主题需要图来说明、描述、介绍或美化时才配；纯文字梳理页、强调阅读的文本页、课堂活动页保持无配图。配图必须结合本页内容生成插入、与全册视觉世界同源；中间留白背景的内容页可多结合插图形成图文组合（见 `visual_planning.md` 的「中间留白页的图文组合」）。有配图需求的页面每页 1–2 张；配图带一句 10–80 字的图注 `caption`。配图决策与校验见 `visual_planning.md` 的「页面配图」一节。
- 正式背景图会先按 16:9 `cover` 物理裁切，再通过 MCP `set_slide_background_image` 设置为页面自身背景；背景路径必须由希沃客户端所在主机读取，禁止用全画布图片元素置底模拟。
- 缺少不可替代的专有图片时继续与用户交互，不擅自换成无关图片或占位图。

## AI 自主决定范围

大纲确认后，AI 自主决定视觉概念、背景策略、结构类型、构图、配图和课堂节奏，不再要求用户逐页确认，也不向用户展示内部字段和坐标。页面结构类型按 `page_structure_guide.md` 逐页匹配作为组织逻辑起点，具体几何仍由 AI 根据已确认内容自主完成。

## 学科工具组合最佳实践

每份课件不应只使用 2-3 种原生工具。以下组合基于学生学习动作设计，不是固定模板——实际选型仍按课题需要逐页判断，选型流程与硬约束见 `subject_tool_guide.md`。

### 语文

| 课型 | 推荐工具组合 | 选型理由 |
|---|---|---|
| 古诗词/文言文新授 | poem + mindmap + table + hanzi + judge | 诵读感知→结构梳理→对比分析→生僻字认读→理解检测 |
| 古诗词（含多音字） | poem + pinyin + mindmap + table + judge | 增加拼音正音页，解决多音字误读 |
| 现代文阅读 | mindmap + table + choice + judge | 结构梳理→手法对比→理解选择→主旨判断 |
| 作文指导 | mindmap + table + match | 写作思路→素材整理→范文配对 |

古诗词课特别建议：课文中出现的生僻字或多音字应单独设 `hanzi` 页认读，不要只在正文中标注读音。如「饮湖上初晴后雨」中「潋滟、空蒙」等字、「相(xiāng/xiàng)」等多音字，都是 `hanzi` 组件的真实学习场景。

### 数学

| 课型 | 推荐工具组合 | 选型理由 |
|---|---|---|
| 概念新授（含函数） | plot + mindmap + table + choice | 函数探究→概念关系→数据记录→选择检测 |
| 几何性质课 | mindmap + table + judge | 性质梳理→判定条件→判断检测 |
| 习题讲评 | table + choice + mindmap | 错题对比→易错点检测→解题思路 |

数学课的 `plot` 仅在教学内容涉及可绘函数时使用，不得强行用于非函数场景。

### 英语

| 课型 | 推荐工具组合 | 选型理由 |
|---|---|---|
| 词汇新授 | wordcard + ruled + match + classify | 单词学习→书写练习→配对巩固→分类检测 |
| 阅读理解 | mindmap + table + choice | 文章结构→信息对比→理解选择 |
| 语法专题 | mindmap + table + judge | 语法结构→用法对比→判断检测 |

英语词汇课的 `wordcard` 每页 1-3 个词，超过时拆页，不截断。

### 选型注意事项

- 组合中的工具数量是建议值，不是硬性要求。课题简单时 4 种即可，课题复杂时可到 5-6 种。
- 每个工具必须对应真实的学生学习动作，不得为了凑工具数而插入无关组件。
- `hanzi` 和 `pinyin` 在语文课中常被遗漏——检查课文中是否有生僻字、多音字或易错音，有则优先安排认读页。
- 课堂活动（choice/judge/match/classify）通常放在教学末尾做检测，但也可在中段插入形成性评价。

## 结构扩展

### 页数与环节密度

具体页数在用户确认的区间内由 AI 自主决定。当教学内容复杂、知识点多或学生需要更多脚手架时，优先在区间内增加页数而非压缩每页信息密度；内容确实无法放入当前区间时，向用户说明理由并请其确认调整区间，不得擅自超出，也不得靠压缩密度强行塞入。以下情况建议增加页数：

- 课题涉及多个独立知识块（如一篇长文的上下阕分析、一个定理的多个推论）；
- 学生需要前置概念铺垫才能理解核心内容；
- 环节之间存在较大的认知跳跃，需要过渡承上启下；
- 课文中有生僻字、多音字或关键术语需要专门认读。

不要为了"精简"而把多个不相关的知识点挤在一页，也不要为了凑页数而拆分本应一页讲清的内容。

### 知识铺垫页

当核心内容需要前置概念支撑时，可在正式讲解前插入知识铺垫页。铺垫页使用 `authored_canvas` 布局，内容聚焦一个前置概念：

- 古诗词课的作者背景或时代背景（但不得写成干瘪时间线）；
- 数学课的定理前提或公式回顾；
- 英语课的核心词汇预习。

铺垫页同样需要满足信息分层要求（至少 3 层内容字段）。

### 过渡页

当两个教学环节之间存在较大跳跃时，可插入过渡页。过渡页不是空泛的"接下来我们学习……"，而应：

- 用一句话或一个核心问题承接上一环节的结论；
- 用一个引导语或情境引出下一环节的问题；
- 视觉上与前后页保持同一视觉世界但形成节奏变化。

过渡页的 `teachingIntent` 可设为 `moment`。
