# 希沃原生组件契约

新建课件时必须读取。先判断学生动作，再选择工具；不得按学科名机械插入，也不得把组件当装饰。

机器可读的类型、参数、数量限制、交互安全区和客户端坐标修正规则以 `scripts/courseware/subject_tools.py` 为唯一真值。本文件只解释 AI 如何作决策，不复制坐标。

## 何时使用

| 学生需要完成的动作 | 原生元素及能力 | 不适用 |
|---|---|---|
| 听读整首古诗、查看原文及内置学习信息 | `poem`：古诗词学习组件 | 单句炼字、现代文 |
| 认读汉字，观察拼音、部件、笔顺、笔画或组词 | `hanzi`：汉字卡 | 段落写作、只展示一句普通文本 |
| 拼读音节、练习声调、正音或辨析易错音 | `pinyin`：拼音卡及发音 | 高年段常规词汇展示 |
| 学习 1-3 个核心英语词的音形义 | `wordcard`：英语单词卡 | 语法讲解、长句阅读 |
| 练习英文字母或单词规范书写 | `ruled`：英语四线三格 | 中文田字格 |
| 操作具体函数图像并观察性质 | `plot`：函数图像 | 无自变量算式、静态公式结论 |
| 自动研判内容结构：知识复习、概念层级、推理步骤、对比总结、结构化信息 | `mindmap`：思维导图 | 无层级关系的平铺列举、仅为视觉装饰 |
| 记录、填写或比较结构化数据 | `table`：表格 | 能用一句话清楚表达的内容 |
| 作答单选题并获得课堂反馈 | `choice`：选择活动 | 仅陈述知识点 |
| 判断陈述正误并获得课堂反馈 | `judge`：判断活动 | 需要开放论证的问题 |
| 建立术语、图片或内容之间的一一对应 | `match`：配对活动 | 不存在明确配对关系 |
| 将对象按明确标准归入类别 | `classify`：分类活动 | 分类标准尚未建立 |

## 选型顺序

1. 先从课题和素材中提取学生动作，不从想画出的版式反推组件。
2. 动作与上表能力直接匹配时，默认优先使用原生元素，再围绕组件设计页面和相邻内容。
3. 不得用普通 `text`、`shape`、`image` 或自绘卡片复刻上表已有能力，也不得把截图当成交互组件。
4. 只有组件无法忠实承载当前内容、教学动作，或用户明确要求静态呈现时，才使用普通页面；在内部规划中说明不使用组件的具体原因。
5. 一页最多一个主要原生元素。存在多个匹配动作时，根据当前教学重点选择主动作或调整页面组织，不预设固定页序。

学科工具组合参考表在 [references/creation_intake.md](creation_intake.md) 的「学科工具组合最佳实践」一节（与建课流程同文件，避免重复加载）。

## 课堂活动页规则（唯一权威定义）

课堂活动 `choice / judge / match / classify` 独占空白页：**活动页不得声明 `visualPlan`（含 background、scrims、elements 任何部分）、不得放背景、正文、装饰、配图或其他组件**，页面保持空白由活动组件独占。`imageStrategy=none` 等图片方案不改变此规则。其他文档涉及活动页时一律引用本节，不另行展开。

## 思维导图自动研判

选型时先自动分析课程内容本身，判断是否具有适合用思维导图呈现的结构，不因“某个课型常见”而机械插入。以下情况优先使用 `mindmap`：

| 内容特征 | 判断线索 | 教学价值 |
|---|---|---|
| 知识复习课 | 需重建整章/整单元知识网络，串联分散概念 | 一页呈现知识全貌，暴露结构关系与缺漏 |
| 概念关系复杂 | 概念间存在父子、包含、派生或多级分类关系 | 层级展开比文字描述更直观 |
| 逻辑推理步骤 | 推导、论证、解题路径有明确先后步骤与分支 | 步骤可视化，便于复述、检查与纠错 |
| 对比总结 | 多个对象按相同维度对比后归纳结论 | 框架化对比，结论落点清晰 |
| 结构化信息 | 内容本身有天然层级（体系、分类、要素构成） | 忠实呈现原有结构，便于记忆与迁移 |

同时明确排除：

- 内容只是平铺列举、彼此无层级关系——用 `items` 列表或 `table` 更合适；
- 一个表格或一句话就能讲清的关系——思维导图会放大信息量；
- 只为了“页面看起来丰富”或凑工具数量——思维导图是教学内容载体，不是装饰。

研判结论写入页面规划：使用 `mindmap` 时说明被梳理内容的核心层级关系；不使用时要能指出替代工具或结构。一份课件中思维导图页数以内容结构决定，通常 1–2 页，不因页数区间而刻意增减。

## 数据契约

新 spec 使用以下类型和教学意图：

```json
{"type":"poem","teachingIntent":"whole-poem-reading","data":{"title":"静夜思","author":"李白","lines":["床前明月光，","疑是地上霜。"]}}
{"type":"hanzi","teachingIntent":"character-formation","data":{"characters":"静思"}}
{"type":"pinyin","teachingIntent":"pronunciation","data":{"pinyin":"jìng yè sī"}}
{"type":"wordcard","teachingIntent":"vocabulary-acquisition","data":{"words":["moon","light"]}}
{"type":"ruled","teachingIntent":"english-handwriting","data":{"content":"Moon moon"}}
{"type":"plot","teachingIntent":"function-inquiry","data":{"expression":"2x+1","observations":["读取与坐标轴的交点","描述增减性"]}}
{"type":"mindmap","teachingIntent":"structure-mapping","data":{"markdown":"# 观沧海\n## 临海\n- 东临碣石\n- 以观沧海"}}
```

**mindmap 数据层级规范（防层级塌陷，必须遵守）**：

- `markdown` 用 `#` 标题层级表达父子关系（`#` 根节点 → `##` 一级分支 → `###` 二级分支），最末级叶子节点用无缩进的 `- 列表项` 写在对应标题下方，由渲染器自动按最近标题补缩进；
- 禁止把叶子节点写成与 `#` 标题同级、无任何层级信息的多行平铺（例如根级直接堆 `- a` `- b`），否则客户端只渲染出根节点与第一个分支，其余节点丢失；
- 也可以全部使用带缩进的 `-` 列表风格（`- 根` / `  - 分支` / `    - 叶子`），缩进必须正确且统一为 2 空格一级；
- 节点文案不超过 4 字为宜（校验器对超 4 字节点告警），详细解释放进页面 `lead`/`items` 文字说明。

`function` 仅为旧输入兼容别名，新输入统一使用 `plot`。

硬约束：

- `poem` 必须提供完整 `lines`，保证本地诗词库未收录或标题、作者模糊命中多首时可按 spec 全文显式兜底，不要求 AI 改标题反复重跑。古诗词原生组件自带完整视觉界面，页面的 `visualPlan` 必须省略 `background`，不得生成背景图、纯色背景块、scrim 或其他背景装饰。
- `hanzi` 每页支持 1–20 字。1–7 字调用一次 `add_hanzi_card_element`；8–20 字均匀拆成两组并调用两次，每组不超过 10 字，再按客户端实际回读尺寸上下排成两行。不得把一次调用理解为客户端会自动换成两行，也不得依赖 `height` 写回缩放组件。
- `pinyin` 应带声调；高年级仅用于多音字或易错音。
- `wordcard` 每页 1-3 个当前任务真正需要学习的词，超过时拆页，不截断。
- `ruled.content` 必须包含英文，不能冒充语文书写组件。
- `plot.expression` 必须含自变量 `x`，并提供 2-3 条与当前函数相关的观察任务。
- `mindmap` 页必须把 `visualPlan.background` 声明为图片背景，并与本课视觉世界和谐同源，不得退化为纯色底；优先复用本课背景池中安全区（约 y 234–660）安静低细节的池项，安全区内的画面保持安静低细节以保证节点可读。除标题外至少提供 `lead` 任务引导，建议补充 1–3 条 `items` 结构说明使页面内容翔实。节点文案建议不超过 4 字，详细解释交给页面文字说明。
- 所有页面的文字色与显示区域的背景色调必须有足够亮度对比度（WCAG ≥ 3:1）。图片背景的 `textSafeRegion` 可声明 `bgTone`（支持 `bgTone:"auto"` 自动实测）供校验器计算对比度。对比度不足时更换文字色或添加 `scrim`/`fill` 容器。详见 [references/visual_planning.md](visual_planning.md) 的"文字对比度"一节。

## 页面规划

工具页的标题或引导语应描述学生动作和可判断产出，不写“本页使用某工具”。组件承担主要交互焦点，普通图层不得进入 `tool_interaction_slot`，也不重复绘制同一批内容。

安全区是客户端组件边界，不是视觉模板。除 `poem` 外，安全区之外的背景、标题、说明和视觉关系仍由 AI 根据当前课题设计。`poem` 使用客户端默认页面底色，由古诗词原生组件独占画面，不另加背景。

`mindmap` 页是组件与教学内容的复合体，视觉要求高于普通工具页：背景图必须与本课主题和全册视觉世界和谐一致（同一场景的延展视角或氛围呼应，保持色彩连续性），组件安全区内画面安静低细节；除标题外必须提供任务引导（`lead`），建议补充 1–3 条结构说明（`items`），使页面内容翔实可读。详细视觉契约见 [references/visual_planning.md](visual_planning.md) 的“思维导图工具页”一节。

课堂活动 `choice / judge / match / classify` 的页面规则见上方「课堂活动页规则」。

## 学段与课堂活动密度

课堂活动（choice/judge/match/classify）按学段控制数量，不是每份课件都必须有。学段以 spec 根级 `grade` 为准：

- **小学低段（1-2 年级）**：课堂活动是游戏化学习的主要载体，可多用（match/classify/judge/choice），但每页仍须对应真实学习动作，不与讲授内容脱节。
- **小学中高段（3-6 年级）**：适度使用，课堂从游戏化向结构化工具过渡，保留必要的检测环节即可。
- **初中及以上（高年级）**：以讲授、梳理、对比类原生工具（poem/hanzi/mindmap/table/plot）为主，课堂活动只保留必要的检测环节——通常不超过 1-2 个，尽可能相邻页展示，甚至可为 0 个，不能为了凑活动数量插入游戏化环节。

高年级课件尽量不使用课堂活动，除非是「讲授、梳理、对比」无法达成的目标（即时全员反馈、易错点快速甄别、术语配对巩固等），否则用普通练习页替代。校验器会统计活动页数量与内容页占比，对高年级活动偏多的课件给出警告。

## 客户端确认

组件调用成功后必须：

1. 回读元素类型，确认组件落在预期页和 shell；
2. 按 `subject_tools.py` 归一化客户端报告的坐标；
3. 确认组件位于安全区内，没有压住标题、说明或其他教学信息；
4. 对异步尺寸组件等待稳定后再次回读，不能用假定宽高完成布局；汉字卡等待展开后按目标行列等比调整宽高，再次回读确认；
5. 失败时在同步前停止，修正数据或布局后重试。

客户端内部字号、资源库命中和异步尺寸属于外部能力限制。不能通过缩小页面、丢词、丢正文、替换图片或伪造成功来绕过。
