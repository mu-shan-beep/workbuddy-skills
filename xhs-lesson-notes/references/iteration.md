# 小红书文案持续迭代与多对标融合机制

## 十一、持续迭代与融合机制（用户提供新对标帖 / 多篇文案时）

本技能不是一次性沉淀，而是**累积型**：用户会不断丢新的对标帖、爆款文案过来，目标是把它们拆解后融进本技能，越用越准、越用越贴合「我们自己的产品调性」。

### 归档位置（硬规则）

**双落点：飞书表（结构化字段）＋ IMA 知识库（全文副本）；本地不留。**

| 落点 | 存什么 | 用途 |
|---|---|---|
| 飞书表「小红书爆款笔记与对标博主记录表」（子表：爆款笔记／对标博主） | 标题、链接、博主、数据快照、标题公式、封面形式、钩子、正文结构、标签、评论需求、爆点归因、可复用点、二次利用动作、复用状态、来源、合规自检 | 结构化、可比对、可统计，**唯一权威记录** |
| IMA 知识库「小红书学习笔记」 | 同名 .md 文字稿（正文原文＋逐页文字＋拆解要点） | 全文语义检索，以后可直接问 ima |
| 本地 | **不留** | 拆解中间产物不入库；**成品文案同样不落盘**，只在对话代码块交付（见第 5 步）。唯一例外是确需留存的配图原图，放该课题 `assets/` |

**三条注意**

1. **本地不留副本**：不在工作区建「文字稿 .md + assets 原图」目录（既删起来麻烦，又容易和对外交付的成品混淆）。确需留原图时，放该课题目录的 `assets/`，按素材命名规范走。
2. **IMA 只进不出**：官方 ima-mcp 工具集只有增/查，openapi 实测无任何 delete 端点（只有 move/rename）。存之前先确认这份内容值得长期留存；入错了只能「同名替换清内容」＋ 客户端手动删占位空壳。
3. **不重复拆解**：写新笔记前先查飞书表（结构化维度）与 IMA（全文检索维度），避免同一篇被拆解、入库两次。

**IMA 入库操作（3 步）**

1. `create_media`（同名 .md，`content_type=text/markdown`）→ 取 presigned_url
2. COS PUT 上传（`Content-Type` / `Content-Length` 必须与申请时完全一致）
3. `add_knowledge` 带 `duplicate_name_strategy: DUPLICATE_NAME_STRATEGY_REPLACE`（同名时**替换而非新增**，库内条目总数不变）

**回读校验**：`get_knowledge_list` 比对条目总数与 `file_size`；`search_knowledge` 确认正文可检索。

**批量入库**：一个文件放多个博主／多篇笔记时，**按主题合并成一份 md**（如「对标博主拆解-墨雨与化境可视化.md」），不要拆成几十个小文件——IMA 条目数越少越好检索。

新对标入双落点后，再决定要不要固化进本技能（按下面 4 步动作）。

### 数据采集：抓笔记互动数的可用通道（实测）

小红书笔记的点赞/收藏/评论/分享数**不在主页 SSR 里**，必须逐篇抓。按可用性排序：

| 通道 | 能否拿到互动数 | 说明 |
|---|---|---|
| **移动端 UA ＋ `/discovery/item/{id}` ＋ `xsec_token` ＋ `xsec_source=pc_user`** | ✅ **可用，首选** | 一次请求拿到 `likedCount` / `collectedCount` / `commentCount` / `shareCount` / `time` / `desc` / `tagList` / `type` |
| 移动端 UA ＋ `/explore/{id}` | ❌ | 返回的是搜索/发现页数据，无笔记详情 |
| 桌面端 UA ＋ 任意路径 | ❌ | 笔记详情一律不渲染（37KB 空壳） |
| 不带 token | ❌ | 返回 404/空 |
| 主页 SSR（`/user/profile/{userId}`） | ⚠️ 仅账号级 | 可拿 `fans` / `follows` / `likeAndCollect` / `redId` / `desc` / `tags` / `collectionList`（收藏夹＝产品矩阵）/ `tabs`（有 `buyer` 说明开了选品）；**笔记列表 `userNotes` 为空** |

**取 token 的路径**（按顺序）：
1. 短链 `xhslink.cn/o/xxx` → 302 到 `discovery/item/{id}?xsec_token=...`（分享 token，最稳）
2. 主页 SSR 里 `profile.userInfo.redId` 无用；**笔记 token 要从浏览器 DOM 拿**——`/user/profile/{userId}` 页面每个笔记卡片的 `<a href>` 里带 `?xsec_token=xxx&xsec_source=pc_user`
3. 用 `dom_cua_get_visible_dom` 读主页 DOM，一次能拿到 20–30 条笔记的 id＋token

**可复用抓取脚本模板**：
```bash
MUA="Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1"
curl -sL -A "$MUA" -H "Referer: https://www.xiaohongshu.com/" \
  "https://www.xiaohongshu.com/discovery/item/${nid}?xsec_token=${tok}&xsec_source=pc_user" -o out.html
```
- **串行 + 每次 sleep 0.8–1.2s**，并发会被限流返回空
- 失败重试 2–3 次（间隔 3s），限流是暂时的
- `desc` 字段里的 `\n` 是 JSON 转义，解析时先 `.replace('\\u002F','/')` 再 `unicode_escape` 解码
- `time` 是**毫秒时间戳**，除以 1000 再格式化
- `type` 区分图文（`topic`）/ 视频（`video`）
- 首页笔记数被折叠，DOM 里拿到的链接是**当前已渲染的部分**，不是全部

### 采集：账号级 vs 笔记级分工

| 想要 | 从哪拿 |
|---|---|
| 粉丝/关注/赞藏总数/简介/标签/收藏夹/是否有选品 | 主页 SSR 一次搞定 |
| 单篇互动数与发布时间 | 逐篇抓（上面的通道） |
| 平均点赞/收藏/评论 | 抓样本（20–30 篇足够）后自算，填进「对标博主」表的 I/J/K 列 |
| 商品成交数 | **取不到**（商品页是 APP 端），只能靠用户截图 |

### 归档：博主级 vs 笔记级的分工

- **单篇笔记** → 飞书「爆款笔记」子表（30 列结构化）＋ IMA 全文
- **博主主页** → 飞书「对标博主」子表（28 列档案：粉丝/笔记数/平均赞藏评/爆款数/更新频率/人设/内容主线/封面风格/标题套路/SEO/商业化形式/可借鉴/需规避/跟踪状态）
- **同一位博主的代表作** → 挑互动最高的 2–3 篇进「爆款笔记」，其余清单进 IMA 的 md
- 一个博主一份 md（**合并写，不拆多文件**）

### 触发

- 用户说「分析拆解这篇」「照这个格式写」「把这篇融进去」「后期还有文案你帮我拆解」等
- 用户直接贴一篇新文案（无论是否同课题、同体裁、同长度）

### 单个新对标的标准动作（4 步）

1. **拆解（必做，先出）**
   用「四、对标拆解六块法」逐块填表：原文要点 / 在文中的作用 / 可复用点。缺块也要写明缺口与代价。结尾给一句「本帖与现有骨架的差异点」，让用户一眼看到新东西在哪。

2. **出改良稿（先出效果，等确认）**
   把新对标里有效的结构、句式、节奏，套到用户当前课题上，产出一版可直接发的文案。
   ⚠️ 这一步只动「当前任务」，**不碰 skill 文件**。

3. **列「拟固化条目」（临时清单，不写文件）**
   明确告诉用户：准备把哪些新发现写进 skill，例如：
   - 骨架公式要不要加新块（如新增「避坑提醒」「互动钩子」「封面引导」）
   - 语言规范「禁止」要不要加新条目（如某类新出现的夸张话术）
   - 体量数据要不要调整（如对标普遍更短/更长）
   - examples.md 要不要新增一篇示例、归入哪类
   列出后**停一下，等用户确认**。

4. **确认后固化**
   用户说「可以 / 固化 / 写进去」后，才编辑 `SKILL.md` 与 `references/examples.md`。未确认前，所有新发现只停留在当前对话。

### 多篇对标融合

- **多篇同体裁**：取「结构并集」，在 `examples.md` 各存一篇并标注「类型 A / 类型 B」；骨架公式只保留最大公约数，差异点写进「常见坑」或单列「变体说明」。
- **多篇跨体裁**（如既有备课笔记、又有卖货种草、又有晒单反馈）：**分独立 few-shot 类别**，不混进同一骨架；跨体裁的只在示例区并列，绝不污染核心骨架与语言规范。
- **商品说明型对标**（清单 + 总述 + 原创声明）：作为**变体 A** 挂在主骨架之后，不替换主骨架；只吸收其标题格式、清单写法、总述四句、原创声明，痛点与取舍仍留在主骨架里。
- **商品详情页型对标**（方括号清单 + 痛点归因 + ■落点 + 双注 + 发货方式）：作为**变体 E** 独立成类，**不并入变体 A**——它无标题无标签、带交易条款，与笔记体量不可互换；只把它「每条落点带可核对细节」的写法反哺主骨架的痛点段密度。
- **同课题多版**：保留「定稿版」为基准示例，其余版本作为变体附录，避免主骨架被临时试错带偏。

### 红线（与全局技能迭代规则一致）

- 改 skill 一律「先出效果 → 等确认 → 再固化」，不得边改边写进技能。
- 未确认前，任何新发现的版式/语言偏好只停留在当前对话，不落盘。
- 用户已确认定稿的教案 / PPT / 学习单等教学内容，绝不因文案需要而改动。
- **涉及教案／设计思路的文案，出稿前必须对照真实教学设计自检、零虚构**：商品详情页（变体 E）每条 ■ 落点、备课笔记的脉络与想法、任何写到的环节／数字／课文原句／写法，都要能在本课教学设计中找到依据，不得凭空想象、不得为凑卖点编造教案里没有的环节或说法；原词照实写（如「人类作品与自然和谐相融」不可漏成「自然相融」）。自检通过再交付，未自检不出稿。
- **归档走双落点**：对标拆解进飞书表 + IMA 知识库全文副本，本地不留文件（见第十一节「归档位置」）。

### 每次融合后建议自检

- [ ] 新示例是否与现有示例「同调性、不同课题」，不会互相打架
- [ ] 骨架公式改动后，旧示例仍能套用（向后兼容）
- [ ] 语言规范「禁止」清单是否变长但不冗余（同类合并，不堆叠）
- [ ] 体量数据是否为真实测量值，而非估算
