# 规则总账（Rule Index）

> **本文件是这套规则的唯一清单。** 规则的数量就该等于这张表的行数——不在表里的不算规则，在表里出现两次的就是重复。
> 判断技能有没有膨胀，不看 SKILL.md 有多少行，看**规则有没有在总账之外被重述**。

## 一、维护约定（七条）

1. **单一权威源**：一条规则只在 SKILL.md 的一个位置写完整表述（下表「唯一位置」列），别处只给操作指令和出处。同一条规则在两个地方各写一套，就是缺陷。
2. **新增须伴合并**：加一条新规则前，先查下表有没有管同一件事的旧规则——有就**改写那一条**，不另起一段。加进总账必须同时进 A/B/C 分级。
3. **不写永久禁令**：风格类只写「X 适用于 Y 情况」。唯一例外是平台红线与 21 条样本 0 次出现的负面共性。
4. **数字必须带 N**：写进规则的字数、条数、标签数，依据列必须标样本量；N < 8 只作参考值，不作判定失败依据。
5. **依据随规则走**：论证写一次就够，写在下表「依据」列或该规则定义处的括号里。**不写「上一版怎样、这次怎么改」**——那是变更记录的事。
6. **变更进 changelog**：改了什么、为什么改，记 [rule-changelog.md](rule-changelog.md)，不占手册正文。
7. **规则必须自跑到底**：一条规则如果能对某一课成立、对另一课就要回头问用户，它就不是规则，是备注。凡出现「请用户核实某具体成分」，按 A-18 改成降级写法或待核标记。

## 二、规则总账

**级别**：A＝硬约束（不可让）｜B＝形态选择（必选，不指定用哪个）｜C＝形态内自由（由本课教案推导）
**强度**：P＝平台规则／F＝教案事实｜S＝有数据样本（标 N）｜O＝单账号观察或跨账号一致（不作强度依据）｜X＝无样本，待验证

## 四、规则冲突怎么裁

1. **平台合规 > 转化**：红色题材与售卖意图冲突时，转化让位（A-12）。
2. **事实 > 形式**：教学内容、实授经历和交付承诺分别核对各自的事实依据。
3. **形态之间不判优劣**：M1 与 M6 首屏不同，不是谁对谁错，按声明各写各的（B-04）。
4. **用户一手观察 > 跨账号不可比数据 > 单账号无数据样本**。
5. **两条都成立且冲突时**：按形态分配，各写各的适用条件，不写「不做 X」。
