# 事实台账（模板）

> 规则总账记的是「规则」，事实台账记的是「事实」。
> 规则回答"该怎么做"，事实回答"这件事到底是什么"。
> **矛盾几乎都出在事实上——同一件事被几个文件说了几种样子。**

## 为什么需要

按文件读，每个文件内部都通顺；把同一事实的几处原文并排读，矛盾才现形。

台账的作用：**改任何一条规则之前，先查它在哪几处出现过，改的时候一处不漏。**

## 字段

| 字段 | 说明 |
|---|---|
| 编号 | `F-01` 起 |
| 事实 | 一句话，能判真假。写"课件以可画链接交付"，不写"课件交付要规范" |
| 权威源与证据类型 | 产出方交付规程、实际成品及权限、平台明文、用户约定或原始样本。若是本技能自身的编辑约定，指向唯一规定处并说明性质 |
| 复述位置 | 列主规则、模板、自检、示例、引用方，写文件与小节 |
| 搜索别名 | 能找到该事实的不同说法，包括旧称与反向措辞。审查时沿引用补齐搜索未命中处 |
| 不一致后果 | 错了会出什么事。写具体后果，写"影响转化"这种不算 |
| 最近核对 | 日期 |

## 示例（填法参考）

| 编号 | 事实 | 权威源 | 投影位置 | 不一致后果 | 最近核对 |
|---|---|---|---|---|---|
| F-01 | 课件默认交付形态是「可画设计链接」，仅明确要求时才交 `.pptx` | 产出技能 `交付规程` 节 | SKILL 4.4 模板、4.5 变体 E、examples、pitfalls、rule-index | 文案承诺「可编辑 PPT」而买家拿到链接，改不动 → 纠纷 | 2026-11-16 |
| F-02 | 无真实交付文件时不写发货文案 | 交易履约常识 | SKILL 2.3、fulfillment 第 0 步、rule-selfcheck | 买家付款后领不到货 | — |
| F-03 | 第一人称课堂叙述只能来自实授记录 | 用户实授 | account-matrix、pitfalls | 编造学生行为，同行一问就露 | — |

## 建台账的步骤

1. **先列事实，不列规则。** 问自己：这个技能里，哪些话是在陈述"某件事是什么"？承诺、数字、格式、机制、边界都算。
2. **每条找一个权威源。** 找不到权威源的，说明这条事实本身没依据——那才是最大的问题，先解决它。
3. **核对复述位置。** 用 `scan.py --fact <事实名> --same <别名1,别名2>` 收集候选后沿引用补齐，打开证据和各处原文并排读。
4. **只收会被复述的事实。** 只在一处出现的事实用不着进台账。

## 用台账改规则

改一条规则前：

```
1. 在台账里找到对应的 F-xx
2. 看投影位置有哪几处
3. 逐处改，不只改"主规则"
4. 回读上游和各处修订；缺前置条件就用具体输入验算
5. 只更新实际核过的事实日期，未核处写清缺口
```

**第 3 步最容易漏。** 「主规则」通常是最显眼的那一处，而模型最先照抄的往往是**示例**——示例不改，等于一边立规矩一边留范本。

## 什么时候更新

- 新增一条承诺或数字 → 加一行
- 改了权威源（比如交付形态变了）→ 全投影位置都要动，台账记日期
- 发现某条事实有两处说法不同 → 先修，再回填台账

## 不需要进台账的

- 只出现一次的操作指令
- 纯格式约定（标题层级、表格样式）
- 语气与文风偏好
